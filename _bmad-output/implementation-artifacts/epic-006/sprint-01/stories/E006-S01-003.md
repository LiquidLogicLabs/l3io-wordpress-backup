# E006-S01-003: Know what is public and what is not


**Implements:** FR-24


As a DevOps engineer,
I want to know which names I can rely on,
So that a patch release does not break my pipeline.

**Acceptance Criteria:**

**Given** the package
**When** a caller inspects it
**Then** the public surface is enumerable via `__all__` and documented
**And** internal modules are identifiable as internal by layer, regardless of underscore convention
**And** the distribution ships no `__init__.py` at `l3io/` or `l3io/wp/`, asserted in the source tree, the built wheel and an installed tree alongside a sibling on a different `sys.path` entry (AD-27)

## Business acceptance criteria

### Outcome

A DevOps engineer can list exactly which names they may rely on: `l3io.wp.backup.__all__` (`__version__`) together with `l3io.wp.backup.api.__all__`. Each name has a docstring and an entry in `docs/api.md`. Everything else is internal, identified by the layer directory it lives in (`domain/`, `ports/`, `core/`, `adapters/`, `cli/`), whether or not its name has an underscore. A patch release can therefore change an internal module without breaking a pipeline, and a change to a listed name is a §10 version event.

The AD-27 namespace invariants already asserted for the package also hold for everything `api/` adds:

- no `__init__.py` at `l3io/` or `l3io/wp/`;
- every directory below `l3io/wp/backup/` is a regular package.

These are checked in the source tree, in the built wheel and sdist, and in two distributions on two `sys.path` entries.

A reviewer can check it by running `python -c "import l3io.wp.backup.api as a; print(a.__all__)"` and comparing the output with `docs/api.md`. The contract tests fail on any drift between the two.

### Non-goals

- **A stability promise.** Before v1.0, the Python API is explicitly unstable (AD-22 amended: first release v0.0.1; §10). This story declares the surface so that the promise *can* begin at v1.0. It does not start it.
- **Re-exporting the API from the package root.** `l3io.wp.backup/__init__.py` predates the epic ownership table and is owned by no epic. It stays `__all__ = ["__version__"]`, and `l3io.wp.backup.api` is the import path for everything else. A lean root also keeps `from l3io.wp import backup` (the `verify-install` probe) free of `cli/` imports.
- **A generated API reference.** That means Sphinx, pdoc or mkdocstrings. Docstrings plus one hand-written page, checked in both directions, are the documentation for v0.
- **A deprecation mechanism.** `warnings.warn` shims are §10's from v1.0 onward.
- **The three-way namespace check against the real `l3io-wordpress-config` and `l3io-wordpress-database`.** It runs in the last package's release pipeline (AD-27). This repository keeps its stub-sibling check.
- **Re-checking AD-27 shapes that `tests/contracts/test_namespace_layout.py` and `tests/contracts/test_namespace_coexistence.py` already assert.** Those are extended, not duplicated.

## Technical acceptance criteria

### Interface contracts

**Files.** Files added or changed:

- `src/l3io/wp/backup/api/__init__.py`, whose docstring states the public-surface rule;
- `docs/api.md`, new;
- the tests below.

**Sibling conventions.**

- Every package `__init__.py` under `l3io/wp/backup/` declares `__all__`. Today these are `adapters/__init__.py`, `api/__init__.py` and the root.
- Layer `__init__` files carry a docstring naming their layer's rule.
- Public names carry docstrings.
- `docs/` holds `adr/` and `handoff/` today, and `docs/api.md` is the first reference page.
- *(E006 arch gate, 2026-11-06, C2: two of the bullets above are stale.)*
  - All seven package `__init__.py` files already declare `__all__`: the root, `adapters/`, `api/`, `cli/`, `core/`, `domain/` and `ports/`. The test walks them and lists none.
  - `docs/` also holds `logging.md` and `restore.md`, and E004-S01-001 adds `exclusions.md`. `docs/api.md` is the first page about the Python API, and it links to `docs/logging.md` for `configure_logging` and the record schema rather than repeating them.

**The rule.**

- A name is public if and only if it appears in `l3io.wp.backup.__all__` or `l3io.wp.backup.api.__all__`.
- A re-exported class's defining module path, for example `l3io.wp.backup.domain.site`, is not part of the contract: callers import it from `api`.
- Every module whose dotted path contains `.domain`, `.ports`, `.core`, `.adapters` or `.cli` is internal, by layer (Consistency Conventions: "everything else is internal regardless of underscore").
- `api/` modules other than `api/__init__.py` (`api/operations.py`, `api/errors.py`) are implementation and internal. Their public names are the ones `api/__init__.py` re-exports.
- The CLI's own contract (§8: command names, options, exit codes, log schema) is separate and frozen by AD-22. It is not part of this surface.

**Scope from the source of truth.**

- The internal layer set is derived from the `layers` list of the `"AD-1 — layers run inward only"` contract in `pyproject.toml`'s `[tool.importlinter]`, read with `tomllib`. Every layer except `api` is internal.
- The public set is `__all__` at run time.
- No test holds a hand-written list of either. A new layer added to the import-linter contract is classified automatically, internal unless it is `api`.
- *(E006 arch gate, 2026-11-06, C3.)* The built `layers` list holds siblings as one entry: `"l3io.wp.backup.cli : l3io.wp.backup.api"` (`pyproject.toml`, contract `"AD-1 — layers run inward only"`). The parser splits each entry on `:` and strips it, which yields six layers. The test asserts that `cli` and `api` both appear, so an entry read whole cannot leave `api` unclassified.

**`__all__` integrity.**

- Every name in each `__all__` resolves with `getattr`.
- There are no duplicates.
- Every public callable and class has a non-empty `__doc__`.
- `api/__all__` contains no name whose object is defined under `cli/` other than through an explicit re-export recorded in E006-S01-001. Those are `BackupResult`, `RestoreOutcome`, `RunContext` and `configure_logging`, and they are listed in `docs/api.md` with that note.
  - *(E006 arch gate, 2026-11-06, C1: the four-name list is replaced.)* It conflicts with the sibling stories:
    - E006-S01-002 re-exports every `BackupError` subclass, and four are defined in `cli/restore.py`: `DatabaseNotRestoredError` (`:344`), `NonEmptyTargetRefusal` (`:483`), `ArchiveIdentityUnconfirmedError` (`:527`) and `ExistingDatabaseUserError` (`:574`);
    - E006-S01-001 re-exports `RelocationFlags` (`cli/restore.py:653`).

    A hand-kept list would also drift, against global rule 4. The rule becomes:
    - a `BackupError` subclass may come from any layer, because E006-S01-002's walk governs that set;
    - any other name in `api.__all__` whose `__module__` is under `l3io.wp.backup.cli` must have, under its `docs/api.md` heading, the line `Defined in the CLI layer; import it from l3io.wp.backup.api.`

    The test derives the set from `__module__`, so it lists nothing, and a planted case without the line fails *(orchestrator decision, 2026-11-06, under global rule 4; the owner may overrule)*.

**`docs/api.md`.**

- One `###` heading per public name, in the form `` ### `name` ``.
- For classes: the constructor signature and documented fields. For callables: parameters, return and the exceptions raised.
- A preface states the internal-by-layer rule and the pre-1.0 instability (§10).
- *(E006 arch gate, 2026-11-06.)* The preface also states four things the sibling stories leave to this page:
  - **Logging (ADR-0018, E006-S01-002, E006-S01-004).** A host that configures logging itself gets no `redact_event`. A host that wants trace ids in its records adds `add_trace_ids` to its chain, or calls the re-exported `configure_logging(..., trace_processors=(add_trace_ids,))`.
  - **Joining a Run (E006-S01-001, C5).** `context=` is for a caller already inside a Run. v0 offers no public way to open one, so a library caller normally omits it.
  - **The environment (E006-S01-001, A8).** It lists the variables a library call may read from the host's environment.
  - **What the Run reports (E006-S01-002, B4).** `run_finished.error` and a span's `error.type` name the original exception's type, even when the caller receives `UnexpectedError`.

**AD-27 applied to `api/`.**

- No `__init__.py` at `l3io/` or `l3io/wp/`, in the source tree, the wheel and the sdist. This already exists and is unchanged.
- Every directory under `src/l3io/wp/backup/` that contains a `.py` file also contains `__init__.py`. There is no implicit namespace package below the distribution root, so `mypy --strict`'s module resolution and the wheel's file list agree. This is new and walked, not listed.
- `mypy` keeps `namespace_packages`, `explicit_package_bases` and `mypy_path = "src"`. A test asserts those three keys and their values in `pyproject.toml`, because `mypy --strict` advises adding exactly the `__init__.py` that breaks the siblings (AD-27).

### Error and edge case handling

- **A name in `__all__` that does not resolve** (renamed, or removed by an epic) fails `test_public_surface` and names the missing attribute.
- **A public name added without a doc heading, or a doc heading with no public name,** fails the bidirectional check and names the name and the direction.
- **A new subdirectory under `api/` (or any layer) without `__init__.py`** fails the regular-package walk.
- **A planted `__init__.py` at `l3io/wp/`** is caught by the existing two-`sys.path`-entry coexistence test, which `test_the_check_would_catch_the_violation` already proves. This story extends that test's sibling import to `l3io.wp.backup.api` as well as `l3io.wp.backup`, so the shadow is asserted against the public module a caller actually imports.
- **A circular import between `cli/` and `api/`.** The layers contract permits `cli` → `api` (non-independent siblings), but `cli` must never import `api`: the library root would become a CLI dependency and the cycle would break a cold `import l3io.wp.backup.api`. An AST check fails if any module under `cli/` imports `l3io.wp.backup.api`.
- **A layer listed in the import-linter contract that has no directory, or a directory with no layer.** The derived-scope test fails, so the classification can never silently skip a directory.

### Security considerations

- **No public name may expose a credential-bearing internal.** `api/__all__` re-exports no adapter instance, no `SecretRegistry` and no `ResolvedCredentials`. A test fails if any public class has an annotated field named `password`, `passphrase`, `identity` or `identities` whose `__repr__` is not overridden. It reuses E002-S01-006's walked `__repr__` check, with scope narrowed to the public set.
- **The public surface is the attack surface a host links against.** Keeping `adapters/redaction.py`, `cli/passphrase.py` and the adapter set internal means a host cannot bypass the AD-26 chain or the registry by importing them as API. It also gets no compatibility promise if it tries.

### Testability approach

The new contract tests extend the existing files under `tests/contracts/` where those already own the shape. They reuse the session-scoped `built_distributions` fixture in `tests/contracts/conftest.py`, so the wheel and sdist are built in process once.

- **`tests/contracts/test_public_surface.py`** (new)
  - `__all__` integrity for the root and `api`.
  - The derived internal-layer set, read from `pyproject.toml`'s layers contract. The test asserts it parsed at least `domain`, `core`, `ports`, `adapters` and `cli`, so a parse that returns nothing cannot pass.
  - Every walked module under `src/l3io/wp/backup/` is classified as root, public `api/__init__`, api-implementation or internal-by-layer. None is unclassified.
  - Docstrings are present.
  - The `cli` → `api` import ban, with a planted-violation case: a temporary `cli/planted.py` importing `api` must fail the AST check.
- **`tests/contracts/test_api_docs.py`** (new). The bidirectional check between `docs/api.md` headings, parsed by heading regex over lines beginning `### `, and the public set. Each direction has a planted case: a fake extra name, and a fake extra heading.
- **`tests/contracts/test_namespace_layout.py`** (extended)
  - Every directory containing `.py` under `src/l3io/wp/backup/` has `__init__.py`. This is walked, and the test asserts it visited `api/`.
  - The same check against the wheel's member list.
  - The mypy namespace keys assertion.
- **`tests/contracts/test_namespace_coexistence.py`** (extended). The subprocess imports `l3io.wp.backup.api` and reads `l3io.wp.backup.api.__all__` alongside the stub sibling, in the two-`sys.path`-entry shape AD-27 makes mandatory. The existing planted-marker test keeps proving the check fires.
- **CI.** `mypy --strict` and `lint-imports` already run. No new job is added.

### Existing-library check

- `__all__` is Python's own export declaration.
- `tomllib` (stdlib, 3.11+) reads `pyproject.toml`.
- `ast` and `pkgutil.walk_packages` walk the tree.
- `zipfile` and `tarfile` read the built distributions, as the existing tests already do.
- hatchling's in-process `build_wheel`/`build_sdist` are already in the `test` group.
- `import-linter` 2.x already enforces the layer contract. This story reads its configuration rather than restating it.
- A documentation generator (pdoc, mkdocstrings, Sphinx autodoc) was considered and not taken for v0. The surface is small. A docstring check plus one page checked in both directions catches drift without adding a build-time dependency and a docs build to CI. Revisit when the surface is promised stable at v1.0.
