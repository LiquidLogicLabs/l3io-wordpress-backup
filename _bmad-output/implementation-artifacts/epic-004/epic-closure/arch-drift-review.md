## Checked with no drift

- AD-1 layering: `core/exclusions.py` imports `domain/` and `pathspec` only; the three import-linter contracts (I/O forbidden list, pure layers never face outward, layers) cover it. `pathspec`'s tree-walking helpers, which import-linter cannot see, are caught by `test_exclusions_pure.py`, whose forbidden set is derived from `pathspec` itself. `adapters/exclusions.py` holds the logging; `core/` logs nothing.
- AD-1 mechanism: `LoggedExclusionPolicy` holds an `ExclusionSet` (composition), no subclassing.
- AD-4: no `dry_run`/`what_if` in any added src line across the three commits.
- AD-6 ownership: `INNER_MANIFEST_MEMBER`, `inner_manifest_bytes` and `check_inner_manifest` live in `domain/archive_format.py`; `adapters/tar.py`, `cli/verify.py` and `adapters/restore_runner.py` import them. Both check sites call the one comparison. The comparison is parsed-field, not byte, as the amendment requires; an unauthenticated outer key present on one side yields the mapping path, never the key (so no attacker text reaches the error).
- ADR-0024 amendment: inner Manifest written last, skipped by extraction and `read_member`, refused under any other name or with a different position; mismatch is `PayloadDamagedError(field=...)`, exit 8, before the Safety Snapshot; unencrypted Archives unchanged; the rollback limit is stated in `docs/restore.md`, `verify --help` and the README usage block.
- Single passphrase chain: `test_single_passphrase_chain.py` derives its scope (`rglob` over the package, scope assertion, planted violation at depth) and holds `L3IO_WP_BACKUP_PASSPHRASE` to `cli/passphrase.py`. `verify --authenticate` and restore build the cipher through `build_payload_cipher`, which registers the passphrase for redaction before `check()`.
- No direct crypto: `adapters/crypto.py` reaches `age` only through `l3io.wp.database.encryption`, importing it inside the function (AD-8); errors map to package types (AD-14).
- Docs vs mechanism: `docs/exclusions.md` is held equal to `DEFAULT_EXCLUSIONS` by `test_exclusions_documented.py`; CLI flags not yet bound are labelled "not available in this build" in the generated usage block (no overstatement). `wp-config.php` protection is checked against `PROTECTED_PATHS` read from the constant, with a nested-path plant (`test_wp_config_never_excluded.py`).
- v0 compatibility (AD-23, FR-10): fixture selection is one derived rule (`tests/archive_fixtures.py::archive_files`, directory listing, sidecars named by suffix); the owner guard covers the v0 names; the generator is reproducible and held by `test_v0_fixtures_reproducible.py`; provenance and the "no operator secret" check are committed. No `src/` change, consistent with "E002's v0 code met every case".
- Encryption FR-4 ACs as amended: stock `age -d` interop (`test_age_interop.py`, CI pins age 1.3.2 by published sha256); no key material in the Manifest (`test_manifest_no_key_material.py`); a committed-key guard; wrong passphrase and damaged payload are distinct named errors; `FakeAge` removed (BL-E004-042 intent met).
