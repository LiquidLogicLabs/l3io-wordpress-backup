## New findings

MAJOR: [Python overlay, locked reproducible install · Core rule 2 (test a constraint) · CI] Under the AG-3 resolution, the family index becomes a credentialed dependency of every CI job, and nothing reconciles that with the repository's stated constraint. pyproject.toml L67–70/L108 keeps `l3io-wordpress-database` off the index because `/simple/` returns 401 (confirmed today, also for `l3io-age-passphrase`) and "a PR runner clones it with no token". E004-S01-003 L93 nonetheless sources the binder from that index for the dev lock. The static, contracts and test jobs run `uv sync --locked --all-extras --dev` (ci.yml L60, L87, L228) without `UV_INDEX_FAMILY_USERNAME`/`PASSWORD`, so all three fail once the story lands. f17170c's step (ci.yml L338–360) already depends on `secrets.GITEA_TOKEN`, which is empty for fork `pull_request` runs (`on: pull_request`, L17), so that step is red for any external PR today. Remediation (owner decision): either make the binder's family-index package anonymously readable, or give every `uv sync` step the two env vars and decide, and record in ADR-0014, what a no-secret PR run does (an explicit skip with a notice, never a silent pass). Name the affected steps in E004-S01-003 L94.

MINOR: [spec-conflict · PRD FR-3] prd.md L128 (FR-3 consequence 1) still requires "per-member checksums and a Dump checksum", and the glossary at L83 says the same. ADR-0024 withdraws both, and its follow-ups amend only FR-4. FR-3 consequence 4 (a declared Dump that is missing fails Verification) is now checked only against the Manifest's own index: E002-S01-003 L61 says "the inner tar is not opened", and no reader compares the inner tar with the index. A writer defect or a crafted Archive therefore surfaces at `LOAD_DUMP`, after `SNAPSHOT`/`CLEAN`. Remediation: amend FR-3 with an ADR-0024 backlink. Either have restore `VERIFY` stream the plain payload's tar headers and compare them with the index (stdlib `tarfile`, no new code path), or record the gap in ADR-0024.

MINOR: [spec text · AD-6] The amendment note in ARCHITECTURE-SPINE.md is attached to rule 3 (L106), but the rule header (L101) and rule 2 (L104) still say the Manifest carries "which members are encrypted and the checksums". Remediation: amend L101/L104 in place, or widen the note to name rules 1–3.

MINOR: [Core §3 design by contract] `ArchiveView.config_path` now has two meanings (E002-S01-003 L58): a member path for v0 and a `ConfigLocation` value for v1. Every consumer must branch on whether a `config`-role member exists: E003-S01-001 L100, E003-S02-006 L68, E007-S01-002 L81. E007-S01-002's AC L27 ("a v0 archive yields `config_path` of `None`") now contradicts it, reconciled only by a note (L29). Remediation: split out `config_member: str | None` (the original remediation), so `config_path` keeps one meaning.

MINOR: [stale signature] E004-S01-002 L60, "Consumed interfaces … unchanged", cites `extract_archive(source, destination, view, *, roles, exclude=frozenset())`. E002-S01-003 L65 now also takes `payload: Path | None = None`. Remediation: re-cite it from E002-S01-003.

MINOR: [leftover per-member naming] E004-S01-003 keeps per-member names for a single-payload design: `EncryptedMemberCorruptError` with a `member` field (L85–86) and the log event `member_decryption_failed` (L144). L185 asserts "`database.sql` intact", but that is v0's name, and v1's inner Dump is the `dump/…` member (ADR-0024 corrected 2026-10-30). Remediation: say "the `dump`-role member" at L185. Either rename to payload terms or record that the names are kept on purpose.

MINOR: [contract gap · NFR-7] On the no-config path (E003-S02-006 L68), the payload is decrypted to `ctx.workspace/"payload.tar.gz"`, and `VERIFY` "later decrypts to the same path again". `decrypt_payload` (E002-S01-003 L66) promises "a new `0600` file" but does not say whether an existing destination is overwritten or refused. The whole payload is also decrypted twice against NFR-7's budget. Remediation: state overwrite semantics, or have `VERIFY` skip the decrypt when the root already produced the file in this Run.

MINOR: [AD-22 compatibility · UX] Restore now resolves the passphrase on every call (E003-S02-006 L57; E006-S01-001; E008-S01-001), before the Archive's view is known. With a TTY and no `L3IO_WP_BACKUP_PASSPHRASE`, every interactive restore prompts, including plain v1 and v0 Archives, where 0.2.21 never prompted. No story states this as intended behaviour. Remediation: state it as the AD-26 Snapshot behaviour, or build the cipher after the probe so the prompt appears only when `view.encrypted` or a Snapshot will be taken.

MINOR: [Core §9 logging · Core §3] `LoggedExclusionPolicy` is "frozen" yet holds a once-flag (E004-S01-001 L58). An instance reused across Runs in a library process therefore logs `exclusions_applied` only once. Library callers that pass an `ExclusionSet` directly get no exclusion events, and E006-S01-001 L132 still says the default becomes `ExclusionSet.default()`, while E008-S01-001 now makes it `LoggedExclusionPolicy(ExclusionSet.default())`. Remediation: wrap per Run inside Epic 2's consumer (`TarArchiveWriter.write`), or have E006 wrap caller-supplied sets. Correct E006-S01-001 L132.

MINOR: [cross-epic ordering] E005-S01-002 L122/L212: the tool-docs tripwire "fails once `adapters/crypto` exists" until the backend requirements are enumerated. E004 and E005 are phase-2 peers. If E005 lands first, E004-S01-003 turns E005's CI check red, and neither story nor the plan says who adds `age`/`age-plugin-batchpass` to `KNOWN_TOOLS` and the generator. This is the AG-11(a) pattern again. Remediation: have E004-S01-003 name that edit, or record the order in the plan.

MINOR: [Core rule 3, prose overstating coverage] The f17170c step comment (ci.yml L340–347) says the extras install "from the family index alone". `uv --index` adds an index in front of PyPI; it does not replace it. The contract test (test_workflow_invariants.py L247–279) checks only for three substrings in a step found by the literal `${wheel}[`. Remediation: say "family index first, PyPI for the rest", or add `--default-index` handling if "alone" is intended.

MINOR: [stale text, from 3002428 in range] E002-S02-009 L97 still says `test_config_writer.py` runs "against the pinned v0.1.1" after the bump to `l3io-wordpress-config` v0.1.2.
