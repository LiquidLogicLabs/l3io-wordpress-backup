## Findings

### F1. MEDIUM: the released-fixture secret guard is nearly vacuous, and the "public test values" claim is not enforced (security, kind: claim)

- **Location:** `tests/adapters/test_v0_fixtures.py` L682-684 (`SENTINEL_PREFIXES`) and
  `test_the_released_fixture_carries_no_operator_secret` (L825-835).
- **Problem:**
  - The test looks for `sentinel-pw-`, `sentinel-pw2-`, `sentinel-pw3-` and `sentinel-pp-` in
    the released `database.sql`.
  - Those prefixes are minted per run with `uuid4` by `credential_sentinel`
    (`tests/conftest.py` L65, L70, L226-227). The released fixture is produced once, by hand,
    outside that fixture, so no sentinel can ever appear in it. The assertion cannot fail.
  - The real leak risk is the owner running 0.2.21 against a non-CI database or a real
    `wp-config.php`. That leak would sit in `wp-root/wp-config.php` and in the Dump's data,
    and the test checks neither for it.
  - The story's security AC states the credentials are "the existing public test values".
    Nothing enforces that, which is a rule-3 gap.
  - The prefixes are also copied by hand from `conftest.py` rather than imported from it
    (rule 4).
- **Suggested fix:**
  - Assert that the released fixture's `wp-root/wp-config.php` is byte-identical to
    `tests/data/wp-config.php`. If 0.2.21 rewrote it, assert instead that its `DB_PASSWORD`
    and `DB_USER` equal the values parsed from that file.
  - Export the sentinel prefixes from `tests/conftest.py` as one constant, and import that
    constant instead of copying it.

### F2. MEDIUM: the parametrised v0 extraction test excuses any link the extractor skips (test precision)

- **Location:** `tests/adapters/test_tar_probe.py` L97-99 of the diff
  (`test_extract_reads_a_v0_archive_itself`).
- **Problem:**
  - `expected` is built as the Archive's members minus `result.skipped_links`. So whatever the
    extractor chooses to skip is removed from the expectation.
  - Scenario: a regression makes `extract_archive` skip the in-tree link
    `latest.php -> index.php` in `synthetic-all-symlink.tar.gz`. It would land in
    `skipped_links`, be dropped from `expected`, and the test would stay green.
  - This replaced a test with no symlink case, so nothing was lost. But the new extraction
    proof for symlink fixtures is weaker than it looks.
- **Suggested fix:** assert the skipped set itself. It should be `{"link"}` for
  `symlink-escape.tar.gz` and empty for every other passing fixture. Derive that from the
  member's `linkname` resolving outside `wp-root`, not from a hand list.

### F3. LOW: the escape-extraction test has a dead assertion, and its docstring overclaims for `escape-absolute` (kind: claim)

- **Location:** `tests/contracts/test_extraction.py`, `test_a_committed_escaping_v0_fixture_is_refused`
  (diff L354-364), and the module docstring (diff L295-298).
- **Problem:**
  - `assert not (tmp_path / "out" / "escape").exists()` checks the wrong path. The dotdot
    member is `wp-root/../escape\n\x1b[31mred`, so a write would create
    `out/escape\n\x1b[31mred`, never `out/escape`. That line can never fail. The before/after
    snapshot is what actually covers this case.
  - For `escape-absolute` (`wp-root//etc/x`), the write target is `/etc/x`, outside
    `tmp_path`. The snapshot cannot see it. Only the `ExtractionRefusedError` raise protects
    that case.
  - The docstring says "refused with nothing written outside the test's directory". For the
    absolute case that is not what the test observes.
- **Suggested fix:**
  - Compute the would-be path from the member name, e.g. `destination / member_relative(...)`
    resolved, and assert it does not exist.
  - Reword the docstring: the absolute case is proved by the refusal raised before any write,
    not by observation.

### F4. LOW: the selection-rule test plants sidecars from the constant it is testing (guard scope, rule 4)

- **Location:** `tests/adapters/test_v0_fixtures.py`, `test_the_selection_rule` (diff L701-708).
- **Problem:**
  - The planted sidecars are `x{suffix}` for each `suffix in SIDECAR_SUFFIXES`.
  - If `.passphrase.txt` were removed from `SIDECAR_SUFFIXES`, the test would plant one sidecar
    fewer and still pass. E004-S01-003's `encrypted-passphrase.passphrase.txt` would then be
    opened as a tar. So the test proves the rule but not its reach.
- **Suggested fix:** plant the real sidecar names as literals,
  `released-0.2.21-all.provenance.json` and `encrypted-passphrase.passphrase.txt`, and assert
  that neither is selected.

### F5. LOW: an Archive in any `v0/` subdirectory other than `malformed/` escapes every guard (guard scope)

- **Location:** `tests/adapters/test_v0_fixtures.py` (`PASSING`/`FAILING`),
  `tests/contracts/test_v0_fixtures_reproducible.py::_committed`, and
  `tests/integration/test_verify_cli.py` (`V0_PASSING`/`V0_MALFORMED`).
- **Problem:**
  - Every walker hard-codes two directories: `v0/` and `v0/malformed/`. `archive_files`
    deliberately skips subdirectories.
  - So `v0/escapes/x.tar.gz` (or a misspelled `v0/malfromed/`) would be committed with no
    table entry, no reproducibility check, no CLI check and no supported-formats check, and
    the suite would stay green.
- **Suggested fix:** add one scope assertion: the subdirectories of `v0/`, excluding
  `__pycache__`, equal `{"malformed"}`.

### F6. LOW: the old CLI v0 test's directory-less shape is no longer exercised end to end (kind: deletion, confidence: medium)

- **Location:** `tests/integration/test_verify_cli.py`, `test_a_v0_archive_passes_structural_only`
  (diff L563-578).
- **Problem:**
  - The removed in-test Archive was a gzipped v0 holding only `wp-root/index.php`: no
    `wp-root` directory member, no `database.sql`, no `wp-config.php`.
  - Every committed passing fixture carries the `wp-root` directory member, because it was
    written through `tarfile.add`. So the CLI no longer verifies a directory-less v0 Archive.
  - It is still covered at the classifier level (`tests/unit/domain/test_classifier.py` L139)
    and by the base Archive of `test_a_crafted_v0_archive_fails` (failing path only).
  - 0.2.21 always wrote the directory member, so the risk is low. No other assertion was
    dropped:
    - the new CLI test adds `"VERIFIED" not in out`;
    - the `test_tar_probe` extraction test is stronger than the name-only check it replaced;
    - `_v0` is still used by `test_a_v0_archive_passes_as_structural_only`.
- **Suggested fix:** none required. If wanted, keep one directory-less, files-only case in
  `test_tar_probe.py::test_a_v0_archive_passes_as_structural_only` (adapter level) rather than
  adding a fourth in-test builder.
