# Code review — E004-S01-003 "Encrypt an archive at rest, passphrase only"

Inputs: the diff, the story (Files in scope, the re-check notes, the technical ACs) and ADR-0024's
2026-11-06 amendment. The three known deviations were checked against their justifications and
are not raised again, except where the code does not match its own justification (H-1).

## Findings

### H-1 — high — test-quality — the encrypted RSS leg cannot detect whole-Archive buffering

`tests/contracts/test_streaming.py:514-522`

**What is wrong.** Deviation 2 is justified by "the bound still limits growth with Archive
size". The code does not deliver that. The allowance is the **max** of the three KDF probes
(about 512 MiB, set by decrypt/check). It is added to both legs: `bound = RSS_BOUND_BYTES + kdf`,
about 536 MiB. The fixture is `SITE_FILE_BYTES + DUMP_BYTES` = 256 MiB (`floor = 10 *
RSS_BOUND_BYTES` = 240 MiB). So on the encrypted leg, a change that buffers the **whole**
payload passes the test, because its growth (about 256 MiB) is under the bound. Examples:
`reader.read()` before `encrypt`, a `BytesIO` of the decrypted payload, or `read_inner_manifest`
reading the tar into memory. The backup leg is the loosest case. It only encrypts (about
270 MiB measured), yet it gets the decrypt allowance too. For the encrypted path this is a
false green on AD-21/AG-13, the failure mode the test exists to catch.

**Fix.** Make the allowance and the fixture match, so that size-dependent growth is still bounded:
- give each leg its own allowance: the backup leg uses `max(kdf-check, kdf-encrypt)`, and the
  restore leg uses `kdf-decrypt`;
- **and** do one of the following:
  - (a) measure the encrypted leg at two Archive sizes (e.g. `floor` and `2 * floor`) and assert
    that `growth(large) - growth(small) < RSS_BOUND_BYTES`, which states the deviation's claim
    directly;
  - (b) grow the encrypted fixture until `SITE_FILE_BYTES + DUMP_BYTES > 2 * (RSS_BOUND_BYTES +
    kdf)`, and assert that inequality in the test so it cannot drift.

Option (a) costs no extra disk beyond one more run, and it keeps the plain leg unchanged.

### M-1 — medium — claim — two observability ACs are neither implemented nor superseded

`src/l3io/wp/backup/adapters/crypto.py:151` (decrypt), `src/l3io/wp/backup/adapters/crypto.py:185`
(factory). Story, Observability requirements, lines 234 and 236.

**What is wrong.** The story still requires:
- one INFO `encryption_configured` per Run (`scheme="age"`, `mode="passphrase"`);
- an ERROR `member_decryption_failed` with `member` and `reason` (`wrong_passphrase` / `corrupt`)
  on a decrypt failure.

F-20 superseded only the `WRITE_ARCHIVE` line (line 237). The other two stand. Neither event is
emitted anywhere in `src/`: `grep -rn "encryption_configured\|member_decryption_failed" src`
finds nothing. The decrypt failure shows up only as the phase record's exit code, with no
`reason` that tells `wrong_passphrase` from `corrupt`. The architect review of 2026-10-28
(MINOR, AD-10) already noted that the factory runs before `open_run`, so an
`encryption_configured` emitted there would carry no `run_id`.

**Fix.** Do one of the following:
- Emit them inside the Run. Set `reason="wrong_passphrase"` / `"corrupt"` on the open `VERIFY`
  record where `PassphraseRejectedError` / `PayloadDamagedError` cross `decrypt_payload`'s callers
  (`restore_runner._verify`, `cli/verify._authenticate`), or log `payload_decryption_failed` there.
  Emit `encryption_configured` from the phase that runs `ENCRYPT` / `VERIFY`'s decrypt, after the
  Run opens.
- Or record in the story, as a re-check note with the owner's decision, that both events are
  dropped or renamed (the payload is the only member, so the `member` field is meaningless).
  Then add a test that asserts whatever survives.

### M-2 — medium — test-coverage — the swapped-payload attack is claimed but never tested

`docs/restore.md:211`; `tests/unit/cli/test_verify_authenticate.py` (inner-Manifest section);
story line 253 (BL-E002-115 "Tests: the swapped-payload and Manifest-edit attacks … fail
`--authenticate`").

**What is wrong.** `docs/restore.md` now says that "a payload swapped in from another Archive"
is refused with `PayloadDamagedError`. BL-E002-115's close-out text names that attack as a
required test. The tests cover outer-Manifest edits, inner-Manifest layout and rollback, but no
test forges Archive A's Manifest around Archive B's payload, encrypted under the same passphrase,
with size and sha256 recomputed. The mechanism should catch it (`created_at`, `source` or
`members` differ), but the claim in the docs is untested.

**Fix.** Add the case to `tests/unit/cli/test_verify_authenticate.py`:
- seal a second Archive under the same passphrase from a different Site, or with a different
  `created_at`;
- run `forge_archive(sealed, out, lambda _: other_payload_bytes)`;
- assert that keyless verify passes, and that `drive_verify(authenticate=True)` raises
  `PayloadDamagedError` with a non-`None` `field` and `reason == "inner_manifest_mismatch"` on the
  `VERIFY` record.

Optionally add the same forgery through the restore harness in `test_restore_runner.py`.

### L-1 — low — security — an attacker-chosen `source` key is copied into the error message and log

`src/l3io/wp/backup/domain/archive_format.py:623`

**What is wrong.** `_first_difference` walks `Manifest.source`, a free-form
`Mapping[str, SourceValue]`, over the sorted union of keys. When a key exists on one side only, it
returns `source.<key>`. The outer Manifest is unauthenticated, so someone without the passphrase
can add a key of any text, including newlines or terminal escape sequences. That text then
reaches `PayloadDamagedError`'s message on stderr and the `VERIFY` record's `field`. It is not a
payload value and not the passphrase, so the ADR's "never a value from the payload" holds. It is
still untrusted text printed verbatim.

**Fix.** When a mapping key is present on only one side, or is not in a known key set, return the
mapping's own path (`"source"`) instead of `source.<key>`. Or emit the key through `repr()` / a
safe-character filter. Add a case to `test_the_first_difference_is_a_path_never_a_value` that plants
`"\x1b[2J"` as an outer-only source key.

### L-3 — low — test-quality — the no-`bytes` signature check misses `bytes | None` and `Optional[bytes]`

`tests/adapters/test_crypto.py:237`

**What is wrong.** The check is `"bytes]" not in str(hint).replace("IO[bytes]", "")` plus
`hint is not bytes`. That passes `bytes | None` (str `"bytes | None"`) and `bytearray`. A public
callable that took or returned an optional whole buffer would not be caught. There is no planted
case proving what the check reaches.

**Fix.** Walk the hint structurally. Recurse through `typing.get_args` / `types.UnionType`, and
fail on any leaf that is `bytes`, `bytearray` or `memoryview`, except as the argument of
`typing.IO`. Add a planted function annotated `-> bytes | None` and assert that the walk reports
it.

### L-4 — low — test-quality — the process-call guard ignores keyword arguments and absolute paths, and its docstring does not say so

`tests/contracts/test_no_direct_crypto.py:67-68` (module docstring lines 8-13)

**What is wrong.** Only `node.args` is inspected, and only the exact constants `age` /
`age-plugin-batchpass` match. So these are not caught:
- `subprocess.run(args=["age", "-d"])`;
- `subprocess.Popen(["/usr/local/bin/age", …])`;
- `os.execv("/usr/bin/age", […])`.

The docstring's "Not covered" list names only runtime-assembled names and variables. That
overstates the guard's reach (global rule 3).

**Fix.** Also inspect `node.keywords` values. Match a constant whose `PurePosixPath(value).name`
is in `AGE_PROGRAMS`. Plant both forms in `test_planted_crypto_is_found_however_deep_and_however_spelled`.
Or list both as blind spots in the docstring.

### L-5 — low — test-quality — vacuous and partial assertions in the encrypted end-to-end tests

`tests/integration/test_encrypted_backup.py:70-80`, `:111`, `:255`

**What is wrong.**
- `test_encryption_requested_with_no_passphrase_is_refused_first` asserts that
  `not target.exists()` for a path that nothing could ever write: `drive_backup` is never called.
  The assertion cannot fail.
- `test_the_right_passphrase_restores_the_tree` runs `RestoreMode.FILES` only, while the
  re-check (story line 317) requires "the tree and `database.sql` intact".
- The inspector checks that the row sentinel is *in* the decrypted Dump. The AC (line 310)
  requires the `dump`-role member to *equal* its source.

**Fix.**
- Drop the `target` assertion, or make it meaningful: wrap the root sequence
  `require_passphrase` → `drive_backup` in one helper, and assert that the target is absent after
  the refusal.
- Run the right-passphrase restore in a mode that loads the Dump (the harness's `ALL` / `DB`
  mode), and assert that the loaded `DUMP` bytes reached the database double.
- In the inspector, compare the extracted Dump against a dump taken independently, or at least
  against its size and sha256 in the Manifest index.

### L-6 — low — test-quality — tests patch database's private `_passphrase`, and `_drive_age` can hang

`tests/adapters/test_crypto.py:182`; `tests/adapters/test_age_interop.py:106`

**What is wrong.**
- `_hide_the_binder` monkeypatches `l3io.wp.database._passphrase.binder_available`, the private
  seam that BL-E004-042 retired `FakeAge` for using. A rename in database fails loudly, so this is
  not a false green, but the coupling is back.
- In `_drive_age`, when the deadline passes with the child still running, `os.waitpid(pid, 0)`
  blocks forever, so a hung `age` stalls the CI job until its global timeout instead of failing
  the test.

**Fix.**
- Hide the binder through the import system only: the `builtins.__import__` patch already there,
  plus `sys.modules["l3io_age_passphrase"] = None`. Or ask database to export a public
  backend-availability query and use that.
- In `_drive_age`, after the loop, `os.kill(pid, signal.SIGKILL)` if `os.waitpid(pid, os.WNOHANG)`
  reports the child still running, then `pytest.fail` with the captured output.
