# Close-out owner decisions (Shawn, 2026-11-07)

Each is implemented after all are collected, then the item is resolved with the commit.

1. **BL-E002-098 (root restore extraction race): (c) now, (a) after release.** A restore running as root is refused (usage error, exit 2) unless the operator passes an explicit flag (e.g. `--allow-root`); with the flag it proceeds and logs a WARNING naming the race. File a post-release item: extract to a private staging dir and move entries in with `openat`/`renameat` (new ADR). Interacts with O4 (a): WP-CLI's root warning still applies once the flag is given.
2. **BL-E002-063 (credentials sent to the site's DB_HOST): (a).** A backup refuses a non-local `DB_HOST` (anything but localhost/127.0.0.1/::1/a socket) before any connection unless the operator confirms it with an explicit flag naming the host (mirroring restore's `--archive-database`). Provider-agnostic: no credential source (AWS or any other) changes this rule.
3. **BL-E002-064 (Archive written inside the Site Root): (a).** A backup whose target resolves inside the Site Root is refused (exit 2) before any effect unless the operator passes an explicit allow flag. This is a deliberate behaviour change from v0.2.21's default (running from the docroot); it is a named release-note entry (AD-22 change), and the refusal text names the flag and suggests a target outside the Site Root.
4. **BL-E002-065 + BL-E003-086 (plaintext residue after a hard kill): (a) + (b).** Each Run sweeps the current OS user's stale `l3io-wp-backup-*` workspaces under `$TMPDIR` and stray `.partial` files of its own target older than 24 h (never a live Run's: age cutoff plus the Site Lock), logging what it removed by path; SIGHUP and SIGQUIT are handled like SIGTERM (cleanup, then exit).
5. **BL-E006-010 (database library spans record raw exception text): (a).** Ask the database agent to record only the error type on its spans (no message, no stack trace), release it, then raise backup's floor and add a test that a planted secret in a database error never reaches an exported span.
6. **BL-E004-055 (database's `age` CLI backend inherits the full environment): (a).** Bundled with #5 into one database release: `age` is started with a minimal explicit environment and an absolute path; then raise backup's floor and add a test that the child's environment carries no `L3IO_WP_BACKUP_*` value.
7. **BL-E008-014 (restored site PHP runs unconfined in the relocation `wp` child): (a).** Accept for v1 and document it in `docs/restore.md` (what runs, as whom, and that an encrypted Archive authenticates it); a URL-rewriting restore of an unencrypted Archive logs a WARNING saying so. File a post-v1 item for optional confinement.
8. **BL-E004-063 (wp-config.php exclusion protection case-sensitive): (a).** The protected-path match is case-insensitive, consistent with BL-E002-067.
9. **BL-E002-069 / 074 / 103 (exit codes): (a).** (1) An extraction refusal after CLEAN exits 8 (VERIFICATION_FAILED class), never 3; the message says the Site was changed and names the snapshot. (2) An encrypted Archive with no passphrase exits 4, as `domain/exit_codes.py` defines. (3) A nonexistent `--wp-dir`/`--archive` exits 2 (USAGE). Each is a named release-note entry; the exit-code table test asserts all three.
10. **BL-E002-103 UX-5 (JSON-only failures on a non-TTY): (b).** Keep stderr strict JSON lines off a terminal; document in README/`docs/` that `--log-format text` gives human-readable output for cron mail.
11. **BL-E002-109 (phase names in two spellings): (a).** Restore phases are logged upper-case with underscores (`LOAD_DUMP`, `REWRITE_CONFIG`, …) like backup's; the Run Journal's on-disk format is unchanged (it maps). Docs and tests updated; a contract test asserts every logged `phase` value is upper case.
12. **BL-E006-019 (log keys collide with a host's): (a).** The Run binds `l3io_run_id` and `l3io_dry_run` (not `run_id`/`dry_run`) in structlog contextvars; docs (logging schema, `docs/api.md`) and tests updated; a test asserts no un-prefixed key is bound.
13. **BL-E002-072 / BL-E002-106 (payload-presence branching vs AD-23): (a).** Amend AD-23: payload presence is a layout fact, permitted outside `domain/archive_format.py`; only version comparisons (`format_version`, version literals) are confined there. Widen `test_version_branching` to catch those, with planted violations.
