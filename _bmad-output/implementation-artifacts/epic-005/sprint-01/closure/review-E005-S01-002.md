# Code review — E005-S01-002 (Fail before starting when a required tool is missing)

Reviewed against the story's technical acceptance criteria (the later "superseded by"
text wins). The story's tests plus `tests/contracts/test_no_mysql_client.py` run green
(58 passed). Medium findings 1 and 2 were reproduced with a short script against the
built module. Finding 3 was confirmed from the installed metadata.

## The six declared deviations

All six match their justifications:

1. `probe(argv, cwd, extra_env)`. `extra_env` comes only from the fixed
   `ToolInfo.probe_env` data. The spy test asserts the env keys exactly:
   `{PATH, HOME, LC_ALL}` for `age`, plus `WP_CLI_CONFIG_PATH` for `wp`.
2. `Diagnosis.database_clients` is a typed `DatabaseClientsStatus`. It runs nothing,
   and it carries `blockers`/`warnings` when a `Readiness` is given.
3. `_ProbeFailedError(BackupError)` is private. It never leaves `_status`.
4. There is no `RootPreflight`, and `require_tools` is untouched.
5. The refusal test asserts `tool`, `needed_for` and `found="1.2.0"`. The built
   `PreflightFailedError` does not render the minimum.
6. `ready` follows the stated rule. Absent tools are ignored. `error`, an unsupported
   platform, an unwritable or existing target, and `database.ready is False` all make
   it false. `StorageTarget.path` is the Archive file (`cli/backup.py:542`
   `ArchiveExistsError`), so "exists ⇒ not ready" is correct.

The architecture rules hold. `adapters/preflight.py` imports `domain/`, `ports/`, the
stdlib, `packaging` and `structlog` only. It has no `dry_run`/`what_if`, no
`l3io.wp.database` type and no MySQL client literal. Version parsing uses
`packaging.version.Version`. `Requires-Dist` parsing uses
`packaging.requirements.Requirement`. No hand-rolled equivalent was found.

## Findings

### M1 — medium — probe output that is not valid UTF-8 crashes `check()` and `diagnose()` (error/edge handling)

- **Where.** `src/l3io/wp/backup/adapters/preflight.py:183-191` (`_version_output`).
  `subprocess.run(..., text=True)` decodes strictly with the parent's locale encoding.
  The `except` clauses catch only `TimeoutExpired` and `OSError`.
- **What goes wrong.** A probed binary that writes a non-UTF-8 byte (a PHP warning
  from `wp` in Latin-1, or a wrong binary named `age`) raises `UnicodeDecodeError` out
  of `BinaryPreflight.check`.
  - The Run then fails with an unhandled non-`BackupError` instead of `ToolStatus.error`
    → `PreflightFailedError` (exit 7).
  - `diagnose()` raises instead of reporting.
  - Reproduced with a fake `age` printing `age v1.3.0 \377\376`. Both `check` and
    `diagnose` raised `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff`.
- **The contract it breaks.** The story says probe output is untrusted and a failed
  probe is data, not an exception.
- **Fix.** Pass `errors="replace"` (and `encoding="utf-8"`) to `subprocess.run`, or
  decode bytes yourself with `errors="replace"`. Add a default-probe test with a script
  that emits `\377`.

### M2 — medium — `diagnose()` raises `PermissionError` for a Storage Target under an untraversable directory (error/edge handling, `kind: claim`)

- **Where.** `src/l3io/wp/backup/adapters/preflight.py:469-473` (`_target_status`).
  On Python 3.11/3.12, `Path.is_dir()` and `Path.exists()` re-raise `EACCES`. They
  ignore only `ENOENT`/`ENOTDIR`/`EBADF`/`ELOOP`.
- **What goes wrong.** With a target `/srv/locked/sub/a.tar.gz`, where `locked` is mode
  000 and the user is not root, `diagnose(...)` raised
  `PermissionError: [Errno 13] Permission denied: '.../locked/sub'` (reproduced on the
  project's Python 3.11.15).
- **The claim it contradicts.** The story says: "A Storage Target whose parent directory
  is missing or not writable is reported, not raised."
- **Fix.** Wrap the probes and treat an `OSError` as `exists=False, writable=False`, or
  use `os.path.exists`/`os.path.isdir`, which return `False` on `EACCES`. Add a test with
  a mode-000 parent, skipped when the user is root.

### M3 — medium — an extra that requires another distribution's extra is reported installed when that extra's packages are missing (error/edge handling, observability)

- **Where.** `src/l3io/wp/backup/adapters/preflight.py:452-466` (`_extra_status`).
- **What goes wrong.** Only `importlib.metadata.version(requirement.name)` is checked.
  `requirement.extras` is ignored.
  - The `aws` extra is `l3io-wordpress-database[aws]>=0.3.2,<0.4; extra == 'aws'`
    (installed metadata).
  - So `aws` reports `installed=True` whenever the `database` extra is installed, even
    with `boto3` and the rest of `l3io-wordpress-database[aws]` absent.
  - The diagnostic then tells the operator an extra is present when importing it would
    raise `MissingExtraError`. That is the fourth AC's extra-versus-binary signal,
    reported wrongly.
- **Fix.** When `requirement.extras` is non-empty, resolve each nested extra the same
  way:
  - read `importlib.metadata.requires(requirement.name)`;
  - keep the entries whose marker evaluates for `{"extra": e}`;
  - check them with `specifier.contains`.

  Recurse with a visited set. Add a test that monkeypatches `version` to raise
  `PackageNotFoundError` for `boto3`, and asserts `aws.installed is False`.

### L1 — low — `diagnose()` logs every absent known tool at ERROR (observability)

- **Where.** `src/l3io/wp/backup/adapters/preflight.py:505-514` with `:301-327`.
- **What goes wrong.** `diagnose` checks every `KNOWN_TOOLS` entry with
  `minimum_version=None`. `preflight_failure` returns `found="absent"` for an absent tool
  whatever the minimum, so `_log_checked` emits `preflight_checked outcome=missing` at
  ERROR.
  - On a host without `age`/`wp`, `wpbackup2 doctor` (E008) will log 2–3 ERROR records
    while reporting `ready=True`. Deviation 6 says nothing is required there.
- **Fix.** Pick one:
  - let `diagnose` call a `check` variant (or pass a flag) that logs absent-but-not-required
    tools at DEBUG/INFO;
  - or have `_log_checked` treat `minimum_version is None and not present` as INFO when
    called from `diagnose`.

  Either way, add a `capture_logs` assertion to the diagnose test.

### L2 — low — the module docstring overstates its import set (`kind: claim`)

- **Where.** `src/l3io/wp/backup/adapters/preflight.py:3-4`.
- **What goes wrong.** The docstring says the module "imports `domain/`, `ports/`, the
  stdlib and `packaging` only". Line 52 imports `structlog`, which the observability AC
  requires. The story's "imports only the stdlib and `packaging`" (Sibling conventions)
  is contradicted the same way.
- **Fix.** Say "the stdlib, `structlog` and `packaging`".

### L3 — low — the relocation tripwire passes with no recorded scope assertion while `RESTORE_EXTENSION` is `None` (guard can pass vacuously, `kind: claim`)

- **Where.** `tests/contracts/test_tool_requirements_documented.py`,
  `test_relocation_requirements_are_registered` (diff line ~818).
- **What goes wrong.** `relocation_violations` returns `[]` when the factory is `None`,
  and the test asserts `== []`. The test therefore reports green over an empty set.
  - The story says "While `RESTORE_EXTENSION` is `None` the case passes, **and its scope
    assertion records why**". Only the docstring records it.
  - The planted-extension case does prove that the wire trips.
- **Fix.** Branch explicitly.
  - When `restore_cli.RESTORE_EXTENSION is None`, assert that and call
    `pytest.skip("no relocation in this build: RESTORE_EXTENSION is None (E007-S01-004 sets it)")`,
    or `xfail(strict=False)` with that reason, so the vacuous pass is visible in the
    report.
  - Otherwise, assert that the extension's `required_tools()` is non-empty before
    comparing.

### L4 — low — `_extra_status` counts a core dependency with an environment-only marker under every extra (latent)

- **Where.** `src/l3io/wp/backup/adapters/preflight.py:455-458`.
- **What goes wrong.** `marker.evaluate({"extra": name})` is also `True` for a non-extra
  requirement whose marker names only environment variables, for example
  `tomli; python_version < "3.12"`. Such a core dependency would be attributed to every
  extra.
  - No core dependency carries a marker today, so this is latent.
- **Fix.** Keep a requirement only when its marker evaluates true for the extra **and**
  false for `{"extra": ""}`. That is the standard way to isolate extra-gated
  requirements.
