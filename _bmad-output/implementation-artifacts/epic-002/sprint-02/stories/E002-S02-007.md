# E002-S02-007: Rehearse any destructive operation


**Implements:** FR-19


As an operator,
I want to see what a backup would do before it does it,
So that I can check the plan against a production site safely.

**Acceptance Criteria:**

**Given** a backup run as a Dry Run
**When** it runs
**Then** credential resolution, preflight and planning all execute for real
**And** the actions it would take are reported in order
**And** the Site and the Storage Target are unchanged afterwards — the `ArchiveStore` command adapter is a no-op
**And** the plan is equal across the real and the no-op adapter sets
**And** no `if dry_run:` conditional exists anywhere outside a composition root — a Dry Run binds real queries and no-op commands (AD-4)

*(The restore half of FR-19 — "what a restore would do" — is Epic 3's, AG-29.)*

## Business acceptance criteria

### Outcome

`wpbackup2 --whatIf backup --wp-dir <Site Root>` (and the library equivalent, `BackupRequest(dry_run=True)`) resolves credentials, runs preflight and database dump readiness, runs every query the plan depends on for real, and reports, in order, the actions a real backup would take — then exits with the code the real backup would have had at that point, leaving the Site, the database and the Storage Target byte-identical. It does not dump the database, read or hash Site Root file contents, encrypt, write, stage, verify or publish an Archive (ADR-0019). A Dry Run that would be refused by a query reports the refusal exactly as the real Run would. This works because a Dry Run binds the real query adapters and no-op command adapters; no `dry_run` conditional exists outside a composition root. A reviewer can tell it happened by diffing the Storage Target directory and the database checksum before and after, and comparing the reported plan with a real Run's plan against the same site.

### Non-goals

## Technical acceptance criteria

### Interface contracts

- **Every port splits into a query half and a command half (AD-4, AG-12).** Convention for `ports/`: each capability is two `typing.Protocol` classes named `<Capability>Query` and `<Capability>Command`. A query never changes the Site, the database or a Storage Target; a command may. Protocols that are neither carry a one-line justification on the **single-role allowance** in `ports/__init__.py`'s docstring: `ArchiveProbe`, `Clock` (queries), `Preflight` (query), `PayloadCipher` (transform, ADR-0024), `ExclusionPolicy` (pure query), `Tracer` and `RunSpan` (observation). E002-S02-008 adds `SiteLock`. This story makes the convention a test (below).
- **The archive-writer command port (ADR-0019).** `ports/archive.py::ArchiveWriterCommand(Protocol)`: `write(out: IO[bytes], *, site_root: Path | None, dump: Path | None, config: Path, exclusion: ExclusionPolicy, cipher: PayloadCipher | None, manifest_builder: Callable[[tuple[ManifestMember, ...], tuple[ExcludedEntry, ...]], Manifest]) -> Manifest` (`site_root=None` for a `database` scope, `dump=None` for `files`). Collection, encryption and the write happen behind it. `adapters/tar.py::TarArchiveWriter` is the real implementation and calls E002-S01-010's `collect_site_root` and `write_archive` unchanged, emitting the `COLLECT_SITE_ROOT`, `ENCRYPT` (encrypted path) and `WRITE_ARCHIVE` phase records. E002-S01-010's `execute_backup_plan` gains `writer: ArchiveWriterCommand` and **stops calling `collect_site_root` and `write_archive` directly**, so a Dry Run has no unguarded effect to reach.
- **What each backup step is bound to.** `DUMP` → `DatabaseCommand.dump_to`; collection, `ENCRYPT` and `WRITE_ARCHIVE` → `ArchiveWriterCommand.write`; `VERIFY` and `PUBLISH` → inside `ArchiveStoreCommand`'s `StagedArchive.publish()` (E002-S01-010). The existing-final-name check is `ArchiveStoreQuery.exists`, a query, so it runs for real.
- **No-op command adapters, `adapters/noop.py`.** One per `*Command` Protocol, named per the Consistency Conventions. Each satisfies its Protocol (mypy, and `isinstance` against `@runtime_checkable` Protocols), performs no effect, records the call into an `ActionLog`, emits `phase_completed` with `outcome="skipped_dry_run"` and `bytes=0`, and returns a value of the declared type that lets the plan continue: `NoopDatabase.dump_to` → `DumpResult(bytes=0, duration_ms=0.0)`, writing nothing; `NoopArchiveWriter.write` → the `Manifest` built from an empty index, reading no Site Root file and writing nothing to `out`; `NoopArchiveStore.stage` → a `StagedArchive` whose stream is an `os.devnull` writer and whose `publish()`/`discard()` do nothing, `publish()` returning `False` (not performed; the real one returns `True`) *(Gate AG-5, 2026-10-28; ADR-0022)* — no verifier is called (AD-21 holds; nothing accumulates in memory).
- **`AdapterSet` (E002-S01-004) gains `archive_writer: ArchiveWriterCommand`**; `real_adapters(...)` binds `TarArchiveWriter()`. **`cli/adapter_sets.py::dry_run_adapters(real: AdapterSet) -> AdapterSet`** — the only other constructor — returns a set that reuses the **same** query instances and the same `tracer` as `real` and substitutes only the command halves (`archive_store_command`, `database_command`, `archive_writer`) with their no-ops. E002-S02-012 extends it for the fields it adds.
- **Selection, only at the composition root.** `BackupRequest` (E002-S01-004) gains `dry_run: bool = False`; `drive_backup`, when it opened the Run, binds `dry_run_adapters(real_adapters(...))` when `request.dry_run` and `real_adapters(...)` otherwise. `open_run` gains `dry_run: bool = False`, bound as a context variable and passed to `tracer.run_span(dry_run=...)`. A joined Run inherits the outer root's selection (ADR-0016). `dry_run` / `what_if` appear only in `cli/` and `api/` — the existing CI step "AD-4 no dry-run conditionals" greps for this and stays as is.
- **Preflight (AD-13, AG-20).** `domain/preflight.py` (pure): frozen `ToolRequirement(name: str, minimum_version: tuple[int, ...] | None, needed_for: str, install_hint: str | None = None)` — `install_hint` is the last field and its only default — and frozen `ToolStatus(name: str, present: bool, version: tuple[int, ...] | None, path: str | None, error: str | None = None)`, `error` set when the tool was found but probing it failed (e.g. `"exit 127"`). They are in `domain/` because `core/backup.py` names `ToolRequirement` and the import-linter contract forbids `core/` → `ports/`. `ports/preflight.py::Preflight(Protocol)`: `check(requirements: Sequence[ToolRequirement]) -> Sequence[ToolStatus]`, a query. `BackupPlan` (E002-S01-010) gains `required_tools: tuple[ToolRequirement, ...]`, derived from its steps. The composition root runs preflight for every requirement **before the first command adapter is called**, in both a real Run and a Dry Run; a missing, too-old or unusable tool raises E002-S01-001's `PreflightFailedError` with `found` = `"absent"`, the version found, or `"unusable (<error>)"`, and `install_hint` passed through — never folded into `needed_for`. For E002 the `DUMP` requirement is satisfied by `DatabaseQuery.check_dump` (database's `check_dump` at v0.2.0, so the client-tool check stays database's): a `Readiness` blocker `UNREACHABLE` raises `DatabaseUnreachableError`, any other blocker raises `PreflightFailedError` naming the finding codes. Until Epic 5 supplies `adapters/preflight`, the root binds a `Preflight` that consults only `check_dump` for the dump step. *(Decided 2026-10-28.)* `build_backup_plan` gains the keyword `extra_tools: tuple[ToolRequirement, ...] = ()` and `BackupRequest` gains `extra_tools` (default `()`); `BackupPlan.required_tools` is the plan's own requirements followed by `extra_tools`, de-duplicated by `name` (the stricter minimum wins). This is how a requirement the plan cannot derive from its own inputs — the passphrase backend, when the cipher is in passphrase mode — reaches preflight: through the plan, never through a side channel into the preflight adapter. E008-S01-001 fills it from the cipher.
- **The plan is data, and is what a Dry Run reports.** *(Decided 2026-10-27.)* The active exclusion set is part of the plan: `build_backup_plan` (E002-S01-010) gains keyword-required `exclusion_source: str` and `exclusion_patterns: tuple[str, ...]`, with no default, and `BackupPlan` carries both. The root fills them from `request.exclusion.source`/`.patterns` (E002-S01-001's `ExclusionPolicy`), the same policy object it passes to `ArchiveWriterCommand.write(..., exclusion=)`, so a real Run and a Dry Run plan the same set. `cli/backup.py` renders the `BackupPlan` in order on stdout — e.g. `1. resolve credentials from wp-config:<path>`, `2. check dump readiness (DatabaseQuery.check_dump)`, `3. dump <db_name> from <host>:<port>`, `4. collect Site Root <path> (excluding <k> patterns, <source>: <pattern>, <pattern>, …)`, `5. write Archive`, `6. verify`, `7. publish to file:<path>` — and logs each as `planned_action` (with `exclusion_source` and `exclusion_patterns` on the collection line). The Dry Run lists the patterns, never the paths they would exclude: under ADR-0019 it reads no Site Root content and `NoopArchiveWriter` calls no policy. A `database`-scope plan has no collect step, and its plan still carries the set (the Manifest records it with an empty `excluded` list, E004-S01-001). No line names a MySQL client binary (ADR-0015). A real Run executes the same `BackupPlan` value.
- **CLI.** `--whatIf` (dest `what_if`, top-level, as v0.2.21) is wired to `BackupRequest.dry_run`; `--what-if` is added as an alias of the same action (triage E-7). Restore's use of it is Epic 3's.

### Error and edge case handling

- A Dry Run against a site whose credentials fail, whose database is unreachable, or whose `check_dump` verdict blocks: exits with the same `ExitCode` the real Run would, after reporting the actions planned up to that point; it does **not** report "would back up".
- A Dry Run whose Storage Target final name already exists: `ArchiveExistsError`, exactly as the real Run (the check is a query).
- A Dry Run with an unsupported Storage Target scheme: refused at parsing, identical to the real Run.
- `--mode files` Dry Run: no credential resolution and no database preflight, matching the real `files` plan (E002-S01-002).
- Workspace: a Dry Run still creates and removes the Run workspace (Run machinery, not a Site or Storage Target write); no-op commands write nothing into it.
- A command port added later without a no-op twin: `dry_run_adapters` cannot fill the field — caught by mypy and by `test_port_split.py`.
- A preflight tool found but unusable: `found: unusable (<error>)`, distinct from `found: absent` and `found: <version>`; the `install:` line is last.

- `run_started` carries `dry_run: true|false`, bound once at the root as a context variable so every record in the Run carries it.

### Security considerations

- A Dry Run resolves real credentials (FR-19 requires it); they are registered with the Run's `SecretRegistry` and redacted as in a real Run. E002-S01-006's `credential_sentinel` is run once in Dry Run mode, covering the `planned_action` rendering.
- A Dry Run against production must be provably non-destructive: no command adapter can be reached except through the `AdapterSet`, and the executor calls no writer, dump or store function directly; the tests below assert it.

## Completion notes

Spec tree not opened; every contract came from the ACs and the sprint-01 code.

### Deviations from the ACs (followed the code, or filled a gap)

1. **`ArchiveWriterCommand.write` gains `workspace: Path`.** `write_archive` stages the payload in the Run workspace, and the AC's signature had no way to reach it. Passing it per call keeps `real_adapters` binding `TarArchiveWriter()` with no arguments, as the AC says. The port also exports `ManifestBuilder`, an alias for the AC's `Callable[[tuple[ManifestMember, ...], tuple[ExcludedEntry, ...]], Manifest]`.
2. **Tracer.** The AC says `tracer.run_span(dry_run=...)`. The sprint-01 `Tracer.run_span` takes an opaque `attributes` mapping that already carried `"l3io.dry_run": False`, so `open_run(dry_run=...)` now sets that attribute instead. The tracer port is unchanged, and AD-4 still holds: only `cli/` names the Dry Run.
3. **Allowance list widened.** Sprint 01 had four more Protocols under `ports/` that are neither query nor command: `PhaseSpan`, `Redactor` (observation, `ports/tracing.py`) and `StagedArchive` (the value `ArchiveStoreCommand.stage` returns). They are on the single-role allowance in `ports/__init__.py` with a reason each, beside the AC's seven.
4. **Credential blockers from `check_dump`.** The AC maps `UNREACHABLE` to `DatabaseUnreachableError` and every other blocker to `PreflightFailedError`. `authentication_failed`/`credentials_unobtainable` blockers raise `CredentialsError` instead, which is what the real dump raises. This keeps "a Dry Run with wrong credentials exits `CREDENTIALS` like the real Run". The mapping is the new public `adapters.database.blocked_dump_error`, and `WpDatabase._refusal` now uses it too. Other blockers become `found: unusable (check_dump: <codes>)`.
5. **Preflight binding.** `Preflight` is not an `AdapterSet` field, because the AC lists only `archive_writer` as new. `backup(...)` gains `preflight: Preflight | None = None` and `extra_tools=()`. `None` binds `cli.preflight.DumpReadinessPreflight` over `ctx.adapters.database_query`, and `drive_backup` passes one carrying the resolved credential-source label. For a requirement other than the dump, `DumpReadinessPreflight` checks presence only, with `shutil.which`. Version probing is Epic 5's. A version that was not probed passes a minimum; only a known-older version fails it.
6. **Plan rendering and stdout.** The plan is rendered by `cli/backup.py::plan_actions`, and every action is logged as `planned_action` *before* preflight, in both modes. A refused Run has therefore reported its plan up to that point in the log. stdout carries the numbered plan only when nothing was published (`result.performed is False`, i.e. a Dry Run). A real Run still prints only the Archive path, so the sprint-01 stdout contract holds. `BackupResult` gains `plan` and `actions`.
7. **DUMP requirement name.** `core.backup.DUMP_REQUIREMENT = ToolRequirement("database-dump", None, "the database dump (DUMP)")`. ADR-0015 forbids naming a client binary, and the AC gives no name.
8. **`phase()` outcome.** `PhaseRecord.skip()` and `SKIPPED_OUTCOME = "skipped_dry_run"` were added to `adapters/phase.py`. `NoopDatabase.dump_to` *joins* the executor's open `DUMP` phase (`join_phase`), so one record per step is kept. `docs/logging.md` documents the new outcome, the `dry_run` record field and `planned_action`.
9. **Import cycle.** `adapters/phase.py` now imports `NoopTracer` lazily inside `_tracer()`, because `adapters/noop.py`'s command no-ops use `phase`.
10. **`--whatIf`.** sprint 01 had not registered it. It is now a top-level `store_true` flag (`dest="what_if"`) with `--what-if` as an alias. The README CLI block was regenerated. `test_flag_map.py` needed no change: it covers the restore subparser only.
11. **`cli/exit.py` unchanged.** `PreflightFailedError.exit_code` is already `NOT_READY` and `exit_code_for` reads the class attribute. `test_preflight_failed.py` asserts the routing.
12. **The `*Command` Protocols** (`DatabaseCommand`, `ArchiveStoreCommand`, `ArchiveWriterCommand`) are now `@runtime_checkable`, so the no-ops are asserted with `isinstance`.
13. **AD-21 reach.** `noop.py` defines `stage`, so the streaming tripwire covers it. It is in `RSS_COVERED`, and the RSS test gains a `backup-noop` leg over the same 256 MiB fixture. `TarArchiveWriter` was added to the pinned `tar.py` surface.
