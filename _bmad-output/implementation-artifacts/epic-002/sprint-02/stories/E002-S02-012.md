# E002-S02-012: Declare the restore and Run Journal ports


**Implements:** AD-4, AD-18 (the journal and staging seams), AD-29; FR-7, FR-9, FR-12 (the ports their operations go through)

*(Split from E002-S02-007 on 2026-10-27, arch gate findings AG-42 and AG-41. E002-S02-007 keeps the port-split mechanism and the backup Dry Run; E002-S02-009 implements the real adapters behind these ports.)*


As a restore implementer in Epics 3 and 7,
I want every port restore reaches the Site, the database, `wp-config.php` and the Run Journal through to exist with its no-op twin,
So that restore is built without editing an Epic 2 module and a restore Dry Run changes nothing.

**Acceptance Criteria:**

**Given** the restore halves of the database port and the `SiteFiles`, `Config`, `SearchReplace` and Run Journal ports
**When** a composition root builds the real or the dry-run adapter set
**Then** each port is a `*Query`/`*Command` pair (or a command-only port with its reason stated) taking and returning domain values only, with no database or config type crossing into `core/`
**And** every `*Command` has a no-op twin in `adapters/noop.py` that performs no effect and records `skipped_dry_run`, and `dry_run_adapters` binds it while reusing the real queries
**And** `load_dump` has no `replace`, credential or decryption parameter, so loading over a non-empty database cannot be expressed through the port (AD-18.3)
**And** every restore-half database method answers existence only through the administrator, refusing with `AdminCredentialsRequiredError` before any connection when none is bound (AD-29)
**And** a port whose real implementation has not landed is bound to a placeholder that raises a named error, never a silent no-op in a real Run

## Business acceptance criteria

### Outcome

Epic 3 (E003-S01-001, E003-S01-002, E003-S02-004, E003-S02-005) and Epic 7 (E007-S01-003) write restore against ports that already exist: they import `RunJournalQuery`, `RunJournalCommand`, `JournalHeader`, `JournalRecord`, `NoopRunJournal`, the database restore halves, `SiteFiles*`, `Config*` and `SearchReplaceCommand`, and define none of them; `tests/contracts/test_port_split.py` sees every one. A reviewer can tell it happened by importing each name from `ports/` and `adapters/noop.py`, building `dry_run_adapters(real_adapters(...))`, and finding every command field bound to a no-op and every query shared with the real set.

## Technical acceptance criteria

### Interface contracts

Ports take and return domain values only, so no `l3io.wp.database` or `l3io.wp.config` type crosses into `core/` (AD-1, AD-14). Credential sources (WordPress, and administrator when given) are bound into an adapter at construction; no port method takes a credential.

- **`domain/database.py` additions (E002-S01-001 created it).** Frozen `DatabaseTargetState(database_exists: bool, table_count: int, is_wordpress: bool, schema_version: str | None, user_exists: bool | None)` — the administrator-observed facts of database's `Survey` (AD-29), copied field by field; frozen `EnsureOutcome(created_database: bool, created_user: bool, password_set: bool, granted: bool, warnings: tuple[str, ...], performed: bool)`; frozen `LoadResult(bytes: int, duration_ms: float, performed: bool)`. `performed` is `True` from a real adapter and `False` from a no-op twin, so a check that follows the effect takes its result and reports "would check" in a Dry Run instead of re-reading the world *(Gate AG-5, 2026-10-28; ADR-0022)*.
- **`ports/database.py` — the restore halves (AD-4, AD-29).** `DatabaseQuery` gains `survey_target(location: DatabaseLocation, *, table_prefix: str, wordpress_user: str | None) -> DatabaseTargetState`, `check_ensure(location) -> Readiness`, `check_load(location, *, source: Path | None) -> Readiness`, `check_revoke(location, *, user: str, confirm: str) -> Readiness`, `check_drop_database(location, *, confirm: str) -> Readiness`. `DatabaseCommand` gains `ensure_database(location) -> EnsureOutcome`, `load_dump(location: DatabaseLocation, source: IO[bytes] | Path) -> LoadResult`, `revoke_grants(location, *, user: str, confirm: str) -> bool`, `drop_database(location, *, confirm: str) -> bool`. Every method except `load_dump` (and the backup half's `dump_to`/`check_dump`) uses the bound administrator source and raises `AdminCredentialsRequiredError` when none is bound.
- **The `load_dump` contract, reconciled with Epic 3 (AG-41).** Epic 2's signature is the contract: **`load_dump(location: DatabaseLocation, source: IO[bytes] | Path) -> LoadResult`**. The target database is `location.name` (Epic 3 passes `location.with_name(<staging or load name>)`, never a `Connection`); the WordPress account is the source bound into the adapter at construction (`AdapterSet.restore_database_command`); there is no `replace` (the adapter calls database's `load` with `replace=None`, so a non-empty target is refused by database — ADR-0015 amendment); and there is no decryption parameter — `source` is the plain Dump, which travels plain inside the payload and is extracted into the Run workspace (E003-S02-005), so the adapter passes no decryption argument to `load` *(ADR-0024)*. The same holds for the other restore-half calls Epic 3 makes: `ensure_database(location)`, `survey_target(location, table_prefix=..., wordpress_user=...)`, `drop_database(location, confirm=...)` — no `Connection`, no credential argument.
- **`ports/site_files.py`.** `SiteFilesQuery`: `is_empty(site_root: Path) -> bool`; `entry_count(site_root: Path) -> int` (top-level entries, for the FR-7 refusal's `detail`); `file_exists(path: Path) -> bool` (PHP `file_exists` semantics, following symlinks — for Epic 7's `ConfigFacts` and Epic 3's in-root `wp-config.php` question). `SiteFilesCommand`: `clean(site_root: Path, *, keep: frozenset[PurePosixPath]) -> int` (entries removed; `keep` is required — Site-Root-relative paths the caller decides survive; the Site Root itself is never removed); `extract(source: StorageTarget, destination: Path, view: ArchiveView, *, roles: frozenset[MemberRole], exclude: frozenset[PurePosixPath] = frozenset(), payload: Path | None = None) -> ExtractResult` (`payload`, the decrypted payload for an encrypted Archive, ADR-0024), whose real implementation delegates to E002-S01-003's `extract_archive` unchanged (the single AD-11 extraction function).
- **`ports/config.py` (AD-18.2/18.4).** `ConfigQuery.read_constants(config_file: Path, keys: Sequence[str]) -> Mapping[str, str | int | bool | None]` — for reading the **restore target's** config (E003-S02-005's `prior_constants`), not for building a Site Descriptor, which stays `adapters/database.py`'s (AD-3); `ConfigCommand.set_constants(config_file: Path, values: Mapping[str, str | int | bool]) -> ConfigWriteResult(changed: tuple[str, ...], performed: bool)` (`performed` as for `LoadResult`, ADR-0022); `ConfigCommand.save_copy(config_file: Path, destination: Path) -> ConfigWriteResult` (copies the file, mode `0600`, fsynced) and `ConfigCommand.replace_file(config_file: Path, source: Path, *, keep: Mapping[str, str | int | bool | None]) -> ConfigWriteResult` (`keep` applied to `source`'s text in memory with `l3io.wp.config.WpConfigString.set` before anything is written; temp file in `config_file`'s directory, fsync, `os.replace`, keeping mode and owner and refusing rather than change the owner) — the two file effects of E003-S01-001's `--overwrite-wp-config` arm, implemented by E002-S02-009 *(Gate AG-16, 2026-10-28; ADR-0023)*.
- **`domain/search_replace.py` and `ports/search_replace.py` (FR-12; E007-S01-003).** Frozen `UrlRelocation(site_url: str | None, home_url: str | None)`, `StoredUrls(siteurl: str, home: str)`, `Replacement(old: str, new: str)`, `SearchReplaceReport(pairs: tuple[Replacement, ...], replacements: int | None, tables: tuple[str, ...] | None, remaining: int | None, merged: bool)`. `SearchReplaceCommand(Protocol)`: `relocate_content(site_root: Path, urls: UrlRelocation) -> SearchReplaceReport`. It is **command-only**, and its docstring says why: every WP-CLI read depends on a loaded Dump and a rewritten config, both produced by commands, so a "real query" in a Dry Run would read the target's *current* database and report differently from the real Run (AD-4). It takes `UrlRelocation`, not Epic 7's `Relocation`; Epic 7 projects onto it.
- **The Run Journal ports (AD-18.1; E003-S02-005).** `domain/journal.py` (pure; E002 owns `domain/`): frozen `JournalHeader(run_id: str, started_at: str, site_root: PurePosixPath, restore_mode: RestoreMode, archive: str, snapshot_path: str | None, live_database_before: str, staging_database: str | None, wp_config_path: str, load_database: str, cutover_keys: tuple[str, ...], cutover_targets: Mapping[str, str], prior_constants: Mapping[str, str | None], phase_undo: Mapping[RestorePhase, str], saved_config: str | None)` — `__post_init__` rejects any key outside `{"DB_NAME", "DB_HOST", "DB_USER"}` in `cutover_targets` and `prior_constants`, so `DB_PASSWORD` cannot be journaled; `phase_undo` is Epic 7's per-phase undo text copied from `RestoreRelocation.undo` and `saved_config` the path of the config copy `--overwrite-wp-config` saves, so a later Run derives the undo from the record alone; frozen `JournalEntry(event: Literal["phase_started", "step_completed", "phase_completed"], phase: RestorePhase, at: str, target: str | None, step: str | None)` — no stored undo; `step` is the named step of a `step_completed` entry, and the undo is derived when the journal is read (E003-S02-005's `undo_for`, ADR-0020) *(Gate AG-1, 2026-10-28)*; frozen `JournalRecord(header: JournalHeader, entries: tuple[JournalEntry, ...])`. `ports/journal.py`: `RunJournalQuery.incomplete(site_root: PurePosixPath) -> JournalRecord | None`; `RunJournalCommand`: `begin_run(header: JournalHeader) -> None`, `phase_started(phase: RestorePhase, target: str) -> None` *(Gate AG-1, 2026-10-28)*, `step_completed(phase: RestorePhase, step: str) -> None`, `phase_completed(phase: RestorePhase) -> None`, `finish_run() -> None`, `resolve(run_id: str, resolved_by: str) -> None` (acknowledges an incomplete journal; E003-S02-005 owns the layout, ADR-0021) *(Gate AG-8, 2026-10-28)*. `RestoreMode`/`RestorePhase` are E002-S02-011's. The durable write sequence and file layout are `adapters/journal.py`'s (Epic 3).
- **No-op twins, in `adapters/noop.py`.** `NoopDatabase` gains `ensure_database` → `EnsureOutcome(False, False, False, False, warnings=("skipped_dry_run",), performed=False)`, `load_dump` → `LoadResult(0, 0.0, performed=False)` without reading `source`, `revoke_grants`/`drop_database` → `False`, and carries the same administrator-binding check as the real adapter; `NoopSiteFiles` (`clean` → `0`, `extract` → `ExtractResult(0, 0, skipped_links=())`, both recording `exclude`/`keep`); `NoopConfigWriter` (`set_constants`, `save_copy` and `replace_file` → `ConfigWriteResult(changed=(), performed=False)`); `NoopSearchReplace` → `SearchReplaceReport(pairs=<planned pairs with old unresolved>, replacements=None, tables=None, remaining=None, merged=False)`; `NoopRunJournal` (every `RunJournalCommand` method, `resolve` included, records and writes nothing, so a Dry Run resolves nothing — ADR-0021). Each records into the `ActionLog` and emits `outcome="skipped_dry_run"`.
- **`AdapterSet` (E002-S01-004) gains** `restore_database_query: DatabaseQuery`, `restore_database_command: DatabaseCommand`, `site_files_query: SiteFilesQuery`, `site_files_command: SiteFilesCommand`, `config_query: ConfigQuery`, `config_command: ConfigCommand`, `search_replace: SearchReplaceCommand`, `journal_query: RunJournalQuery`, `journal_command: RunJournalCommand`.
- **`real_adapters(...)` gains** `admin_source: CredentialSource | None = None`, `restore_wordpress_source: CredentialSource | None = None`, `search_replace: SearchReplaceCommand | None = None`, `journal: tuple[RunJournalQuery, RunJournalCommand] | None = None` (sources built by E002-S01-006's `cli/credentials.py`, never by the root). `restore_database_*` are the **same instances** as `database_*` unless `restore_wordpress_source` is given (a relocated WordPress account, E003-S02-006), in which case they are a second database adapter bound to that source and the same administrator source; the Safety Snapshot keeps using `database_*`. A port whose real implementation has not landed is bound to a placeholder in `cli/adapter_sets.py` that raises `UnboundAdapterError(BackupError)` (added to `domain/errors.py`; exit `FAILED`; a programming error, because no plan reaches it unless the feature was supplied): the restore-half database methods (`WpDatabase` gains them as raising stubs), `site_files_*` and `config_*` until **E002-S02-009** replaces them with the real adapters; `search_replace` until Epic 7 supplies one (E003-S02-006 passes it); `journal` until Epic 3 passes `adapters/journal.py`'s pair. **`dry_run_adapters(...)`** additionally substitutes `NoopDatabase` for `restore_database_command`, `NoopSiteFiles`, `NoopConfigWriter`, `NoopSearchReplace` and `NoopRunJournal`, and reuses every query.

### Error and edge case handling

- A restore-half database method on an adapter bound without administrator credentials: `AdminCredentialsRequiredError` naming `--admin-username`/`--admin-password`, raised before any connection — in the real and the no-op set alike, so a Dry Run refuses where the real Run would.
- `SiteFilesCommand.clean` given a `keep` path that is absolute or contains `..`, or `extract` given such an `exclude` entry: `ValueError` (a programming error), nothing removed or written.
- A placeholder-bound port called in a real Run: `UnboundAdapterError` naming the port and the story or epic that supplies it.
- `JournalHeader` constructed with `DB_PASSWORD` (or any other key) in `cutover_targets` or `prior_constants`: `ValueError` at construction.
- A command port added later without a no-op twin: `dry_run_adapters` cannot fill the field — caught by mypy and by E002-S02-007's `test_port_split.py`.

### Observability requirements

- Every no-op twin emits `phase_completed` with `outcome="skipped_dry_run"` and `bytes=0`, and records its call (with `keep`, `exclude`, the keys of `values` — never the values — and the journal event) into the `ActionLog`, so a restore Dry Run's log shows each skipped effect.
- `UnboundAdapterError` is logged by the boundary like any `BackupError`; the port and supplier names are fields.

### Security considerations

- No port method takes a credential, and `load_dump` cannot express "load over a non-empty database" (AD-18.3, ADR-0015).
- `JournalHeader` cannot hold `DB_PASSWORD`; the journal records keys and non-secret targets only.
- `ConfigCommand.set_constants` may receive a `DB_PASSWORD` value (relocation); the real adapter registers it with the Run's `SecretRegistry` (E002-S02-009) and the no-op records keys only.
- `AdapterSet.__repr__` (E002-S01-004) stays free of credential contents with the new fields.
