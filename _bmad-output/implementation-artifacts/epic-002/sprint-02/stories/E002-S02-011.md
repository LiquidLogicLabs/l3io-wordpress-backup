# E002-S02-011: Register the restore vocabulary and flags


**Implements:** FR-6 (the Restore Mode vocabulary), AD-5, AD-17, AD-22, AD-25; FR-27 (the `doctor` subcommand's registration)

*(Split from E002-S01-005 on 2026-10-27, arch gate finding AG-42. E002-S01-005 keeps the exit-code table and the CLI exit path.)*


As an operator,
I want every restore, encryption, exclusion and credential flag to mean one fixed thing from the first release,
So that no later change can quietly widen what `--cleanfirst` or `--force` destroys.

**Acceptance Criteria:**

**Given** the restore subcommand's mode-selecting flags `--mode`, `--cleanfirst`, `--drop-database` and `--force`
**When** any of their 24 combinations is resolved
**Then** it maps, through one literal table, to exactly one `(RestoreMode, OverrideSet)` or to a rejection that exits `USAGE` naming the combination that would express a real Mode
**And** `all-clean` is reachable only with both `--cleanfirst` and `--drop-database`, and `--force` only waives FR-7's non-empty-target refusal for the parts the Mode restores — it selects no Mode and authorises no removal
**And** `RestoreMode`, `RestorePhase`, `OverrideSet` and `SnapshotPolicy` are defined once, in `domain/restore.py`, and no parameter annotated with one of them carries a default
**And** all nineteen v0.2.21 spellings are accepted on the subcommands they lived on, and every new flag is registered with help text and classified where it is defined
**And** a flag or subcommand whose feature has not landed exits `USAGE` naming the feature and the story that delivers it, and is never silently ignored
**And** no flag added here takes a passphrase or password value

## Business acceptance criteria

### Outcome

The whole outward CLI vocabulary for restore exists and is frozen before Epics 3, 4, 5 and 7 build behind it: an operator running `wpbackup2 restore --mode db --cleanfirst` gets a usage error that says to use `--drop-database`; `--force` alone never turns into "delete everything" (the v0.2.21 defect B-3 is gone); `wpbackup2 doctor`, the encryption flags, `--exclude` and `--db-credentials-aws-*` are accepted and explain which release delivers them; and every v0.2.21 flag still parses. Epics 3 and 7 import `RestoreMode`, `RestorePhase`, `OverrideSet`, `SnapshotPolicy` and `resolve_flags` and define none of them. A reviewer can tell it happened by running each of the 24 combinations and reading the table, and by running the CLI-surface conformance test against the legacy parser.

- A `--what-if` alias on restore, or any new spelling of a frozen flag.

## Technical acceptance criteria

### Interface contracts

- **`domain/restore.py` (new, pure) — the restore vocabulary every epic consumes and none redefines (AD-5, AD-17, AD-25).**
  - `class RestoreMode(StrEnum)`: `FILES = "files"`, `FILES_CLEAN = "files-clean"`, `DATABASE = "database"`, `DATABASE_CLEAN = "database-clean"`, `ALL = "all"`, `ALL_CLEAN = "all-clean"` — FR-6's names verbatim. Four pure functions read FR-6's table through one `match` over every member ending in `assert_never`: `restores_files(mode)`, `restores_database(mode)`, `clears_site_root(mode)` (true for `files-clean`, `all-clean`) and `removes_database(mode)` (true for `database-clean`, `all-clean` only — the database losing the cutover is dropped only in `*-clean` modes, decision 6 of 2026-10-20).
  - `class RestorePhase(Enum)` in AD-17's order: `PREFLIGHT, VERIFY, SNAPSHOT, CLEAN, EXTRACT, REWRITE_CONFIG, LOAD_DUMP, SEARCH_REPLACE`; `RESTORE_PHASE_ORDER: Final = tuple(RestorePhase)`; `is_subsequence(phases) -> bool`. The docstring carries AD-17's amendment in substance: `REWRITE_CONFIG` writes no `DB_*` key; the cutover of `DB_NAME` (with relocation, also `DB_HOST`/`DB_USER`/`DB_PASSWORD`) is the **last journaled step of `LOAD_DUMP`**, after the load is checked. Epic 3's phase-sequence test asserts it; this module states it.
  - `class Override(StrEnum)`: `NONEMPTY_FILES = "nonempty-files"`, `NONEMPTY_DATABASE = "nonempty-database"`; frozen `OverrideSet(waived: frozenset[Override])` with `waives(part: Literal["files", "database"]) -> bool` and `OverrideSet.none()`. `OverrideSet` is a distinct type from `RestoreMode` and cannot name a Mode or authorise a removal.
  - `class SnapshotPolicy(StrEnum)`: `TAKE = "take"`, `SKIP = "skip"` — closed (E003-S02-003).
  - `tools/check_mode_defaults.py`'s guarded set gains `RestoreMode`, `SnapshotPolicy` and `OverrideSet`.
- **The AD-25 table (decided 2026-10-20) in `domain/flag_map.py`.** The restore subparser's mode-selecting flags are `--mode {files,db,all}` (frozen), `--cleanfirst` (frozen), `--force` (frozen) and **`--drop-database`** (new, `store_true`). Meanings, which the table encodes and nothing else re-derives: `--mode` chooses the parts restored (`db` → database through E002-S01-002's `CLI_MODE_TO_SCOPE`; no second spelling table); `--cleanfirst` authorises **clearing the Site Root** and nothing else; `--drop-database` authorises **removing the database that loses the cutover** and nothing else — two separate authorisations (FR-6, §7.1); `--force` yields `OverrideSet` waiving FR-7's refusal for exactly the parts the Mode restores (`NONEMPTY_FILES` iff `restores_files`, `NONEMPTY_DATABASE` iff `restores_database`). Rows (`force` doubles each, adding the waivers): `files` → `FILES`; `files --cleanfirst` → `FILES_CLEAN`; `db` → `DATABASE`; `db --drop-database` → `DATABASE_CLEAN`; `all` → `ALL`; `all --cleanfirst --drop-database` → `ALL_CLEAN`. Every other combination — `files --drop-database`, `db --cleanfirst`, `all --cleanfirst` alone, `all --drop-database` alone, both on `files`/`db` — maps to `FlagRejection(reason: str, use_instead: str)` (e.g. `db --cleanfirst` → "`--cleanfirst` clears the Site Root, which `--mode db` does not restore; to remove the previous database use `--drop-database`"). `COVERED_FLAGS = frozenset({"mode", "cleanfirst", "drop_database", "force"})`; `FLAG_MAP: Final[Mapping[FlagCombination, tuple[RestoreMode, OverrideSet] | FlagRejection]]` is a **literal** of all 24 entries, not a comprehension, so each row is reviewable against FR-6; `resolve_flags(combination) -> tuple[RestoreMode, OverrideSet]` indexes it with no `.get` default and raises `FlagCombinationRejectedError(UsageError)` (added to `domain/errors.py`) for a rejection; `authorizing_combination(mode, part) -> FlagCombination` is the inverse lookup E003-S01-002 uses to name the waiving flag (derived from the table, never typed into a message). Behaviour change from v0.2.21, named in the release notes: `--force` no longer maps to `ALLCLEAN` (B-3); `--cleanfirst` no longer removes the database.
- **Classification at the flag, not in a list (AD-25 enforcement).** The restore subparser puts its mode-selecting flags in an argument group titled `restore mode` and every other `store_true`/`choices` action in `restore options`. `tests/contracts/test_flag_map.py`'s derivation is narrowed to the `restore mode` group, and a new assertion fails if any such action belongs to neither group.
- **Flags registered here** (AD-22 permits additions; each with help text, documented by E002-S01-005's `tools/gen_cli_docs.py`):
  - Frozen v0.2.21 restore flags on the restore subparser: `--mode`, `--cleanfirst`, `--force`, `--admin-username`, `--admin-password`, `--admin-credentials-aws-secret-id`, `--admin-credentials-aws-region`, `--new-site-url`, `--new-site-home-url`, `--new-db-host`, `--new-db-name`, `--new-db-user`, `--new-db-password`, and `--only-appointed-in-asg`. `--admin-password` and `--new-db-password` say in their help that the value is visible in the process list and (for the administrator) name `L3IO_WP_BACKUP_ADMIN_PASSWORD`.
  - Restore (`restore options`): `--drop-database` (above); `--no-safety-snapshot` → `SnapshotPolicy.SKIP`, else `TAKE` (the explicit opt-out, AD-26 as decided 2026-10-20); `--snapshot-dir PATH`; `--resolve-interrupted-run RUN_ID` (requires the interrupted Run's ID, so no blanket flag resolves a journal nobody read — E003-S02-005); `--wp-config PATH` (E002-S01-010 registered it on `backup`).
  - Encryption: repeatable `--recipient AGE_RECIPIENT` and `--recipients-file PATH` on `backup` and `restore`; repeatable `--identity-file PATH` on `restore` and `verify`; `--encrypt-with-passphrase` (`store_true`; the secret comes only through E002-S01-006's `resolve_passphrase`).
  - Backup exclusions: repeatable `--exclude PATTERN`, `--no-default-excludes`, `--list-default-excludes` (prints the default set and exits `OK` without a Run, once Epic 4 provides the set).
  - Credentials: `--db-credentials-aws-secret-id ID` / `--db-credentials-aws-region REGION` on `backup` and `restore` (FR-14, mirroring the frozen `--admin-credentials-aws-*` pair), translated by E002-S01-006's `cli/credentials.wordpress_spec(...)`; the region without the secret id is a usage error at parse time.
  - **`doctor` subcommand (FR-27):** `wpbackup2 doctor [--wp-dir DIR] [--archive TARGET] [--json]`, dispatched from `cli/__init__.py::main` to `cli/doctor.py::run_doctor(args) -> int`. Epic 8 (E008-S01-001) makes it render E005-S01-002's `Diagnosis` (human text on a TTY, JSON otherwise or with `--json`) and return `OK` when ready, else `NOT_READY`.
- **Accepted-and-explained, declared once.** `cli/parser.py::NOT_YET_IMPLEMENTED: Final[Mapping[str, str]]` maps each flag `dest` or subcommand whose behaviour has not landed to the story that delivers it: the restore subcommand and its flags → E003-S01-006; `--new-*` and restore's `--wp-config` → Epic 7; encryption flags → E004-S01-003; exclusion flags → E004-S01-001; `--db-credentials-aws-*` and `doctor` → E008-S01-001; `--only-appointed-in-asg` → "removed with `chesney`" (never implemented). Using one exits `USAGE` naming the feature and the story. The story that binds a feature removes its entries.

### Error and edge case handling

- A rejected flag combination (e.g. `restore --mode db --cleanfirst`): exit `USAGE`, nothing read beyond argument parsing, message from the table entry naming the combination that would express a real Mode.
- A flag or subcommand in `NOT_YET_IMPLEMENTED`: exit `USAGE` naming the feature and the delivering story; never silently ignored.
- `--only-appointed-in-asg`: exit `USAGE` with a message naming the removal of `chesney`, not argparse's "unrecognized arguments".
- `--db-credentials-aws-region` without `--db-credentials-aws-secret-id`, or a lone `--admin-username`/`--admin-password`: usage error.
- `--list-default-excludes` combined with Run-requiring arguments (once bound): prints and exits `OK` without opening a Run or reading the Site Root.

### Observability requirements

- Usage errors are reported on stderr before any Run opens, so they carry no `run_id` and emit no `run_started`; the message is the table entry's or the `NOT_YET_IMPLEMENTED` entry's text.
- Epic 3's restore root logs the resolved `restore_mode` and the waived overrides as values; this story provides them and logs nothing itself.

### Security considerations

- No flag registered here takes a passphrase or password value; the two frozen password flags are a named, docstring-justified allowance, and their help text states the process-list exposure and the environment alternative.
- Destruction needs two distinct, specific authorisations (`--cleanfirst` for files, `--drop-database` for the database); `--force` waives only a refusal (§7.1). The table is a literal so each row can be reviewed against FR-6.

### Testability approach

- `tests/unit/domain/test_restore_vocabulary.py`: FR-6's four columns per `RestoreMode`, parametrised from the enum, checked against a table transcribed from the PRD in the test's docstring; `RestorePhase` order equals AD-17's; `is_subsequence` rejects a reordering.
- `tests/unit/domain/test_flag_table.py` plus the extended `tests/contracts/test_flag_map.py`: every `RestoreMode` is reached by exactly one `force=False` combination (scope from the enum); `ALL_CLEAN` only with both `cleanfirst` and `drop_database`; no single flag turns a non-clean Mode into one where both `clears_site_root` and `removes_database` hold; `force` never changes a row's Mode; every `FlagRejection` names a flag; planted-violation cases — a `store_true` added to `restore mode` without a table entry fails, one added outside both groups fails.
- `tools/check_mode_defaults.py`'s planted-violation test gains a defaulted parameter of each of `RestoreMode`, `SnapshotPolicy` and `OverrideSet`.
- **Frozen CLI surface conformance (AG-10)** — `tests/contracts/test_cli_surface.py`: the parser accepts all nineteen v0.2.21 spellings (`--version`, `--log-level`, `--whatIf`, `--wp-dir`, `--mode`, `--archive`, `--cleanfirst`, `--admin-username`, `--admin-password`, `--admin-credentials-aws-secret-id`, `--admin-credentials-aws-region`, `--only-appointed-in-asg`, `--new-site-url`, `--new-site-home-url`, `--new-db-host`, `--new-db-name`, `--new-db-user`, `--new-db-password`, `--force`) on the subcommands they lived on; the expected list is taken **from the legacy parser** (`wpbackup2/__main__.py`, kept on disk) by AST, and the test fails if that file is deleted without a committed snapshot replacing it. It also asserts the additions exist where stated (`--wp-config` on backup and restore, `--db-credentials-aws-*` on both, `doctor` with its three options, the encryption and exclusion flags), that `backup`, `restore` and `verify` exist, and that the `wpbackup2` console script reaches `main`. Decided 2026-10-20 (Shawn): the `python -m wpbackup2` case is `xfail(strict=True, reason=...)` naming AD-22's open legacy-tree item (the legacy `wpbackup2/` tree occupies the module name on disk but is excluded from the wheel), so it fails the moment module invocation works without the marker being removed.
- `tests/contracts/test_not_yet_implemented.py`: one case per entry of `NOT_YET_IMPLEMENTED`, derived from the mapping and checked against the parser's actions (an entry naming no real action fails), asserting exit `USAGE` and the story in the message.
- `tests/contracts/test_no_secret_valued_flags.py`: every parser action whose `dest` contains `passphrase` is `store_true`, and no action's `dest` contains `password` except the two frozen flags on the named allowance (each checked to exist) — scope from the parser.
