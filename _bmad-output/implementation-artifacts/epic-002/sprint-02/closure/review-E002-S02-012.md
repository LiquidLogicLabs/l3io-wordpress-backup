# Code review — E002-S02-012

## Summary

The ports, value types, no-op twins, placeholders and `AdapterSet`/`real_adapters`/`dry_run_adapters`
extensions match the interface contract. AD-4 holds: no new `dry_run`/`what_if` name sits outside
`cli/`/`api/`. AD-1 holds: `domain/` and `ports/` import no I/O, and no port method takes a credential.
`load_dump` has no `replace`, credential or decryption parameter. Every command result carries `performed`,
and the no-op twins return `False`. The AD-29 administrator check runs before the stub or no-op body, in
both the real set and the no-op set. No maintained-library equivalent was hand-rolled.

**Recorded deviations, not defects:**
- `adapters/journal.py` and `adapters/staging.py` were not created. The story's non-goals assign them to Epic 3.
- `ConfigWriteResult`/`ConstantValue` were placed in a new `domain/config.py`, which is not in Files in scope. The placement is consistent with AD-1.
- `cli/credentials.py` is untouched. No restore driver exists yet to pass `admin_source`.

`UnboundAdapterError` exposes `port`/`supplier` as attributes, and the boundary (`cli/exit.py`) logs the
message containing both. This review accepts that as meeting "the port and supplier names are fields".

## Findings

### F1 — MEDIUM — kind: claim — `JournalHeader` can be made to hold `DB_PASSWORD` after construction

- **Location:** `src/l3io/wp/backup/domain/journal.py:78-81` (`__post_init__` copies into plain `dict`)
- **Claim contradicted:** "`JournalHeader` cannot hold `DB_PASSWORD`; the journal records keys and
  non-secret targets only." (Security considerations). Also: "`__post_init__` rejects any key outside
  {DB_NAME, DB_HOST, DB_USER} … so `DB_PASSWORD` cannot be journaled."
- **Description:** The key check runs only at construction, and the mappings are then stored as mutable
  `dict`s on a "frozen" dataclass. Running the following reproduces it:
  `h.prior_constants['DB_PASSWORD'] = 's3cret'` succeeds, and `dict(h.prior_constants)` then
  returns `{'DB_PASSWORD': 's3cret'}`. Epic 3's `adapters/journal.py` would serialise that
  header as given. Side effect: `hash(header)` raises `TypeError: unhashable type: 'dict'`, even
  though the class is declared `frozen=True`. `JournalRecord` inherits the same problem.
- **Suggested fix:** Store the three mappings as read-only views, `types.MappingProxyType(dict(...))`
  (stdlib), or as a sorted `tuple` of pairs. Then add a test that mutating the mappings after
  construction raises. `dataclasses.asdict` deep-copies values that are not dicts, and a
  `mappingproxy` cannot be deep-copied. So either keep the asdict round-trip by giving the
  header its own `to_dict`, or make the test convert the proxies explicitly. Alternatively,
  narrow the claim in the docstring to "at construction" and have the journal adapter
  re-validate before it writes. Of the two, the read-only mappings are preferred.

### F2 — MEDIUM — kind: testability — the new scope guards plant no violation against their own scope, and the placeholder scope is a name convention

- **Location:** `tests/unit/cli/test_adapter_sets.py:2245-2254`
  (`test_the_placeholder_table_is_every_unbound_field`), `:2257-2265`, `:2285-2309`;
  `tests/unit/adapters/test_noop_restore.py:1982-1994` (`test_every_restore_twin_has_a_case`)
- **Description:**
  1. `test_the_placeholder_table_is_every_unbound_field` finds placeholders by
     `type(...).__name__.startswith("Unbound")`. That is a hand-kept naming convention, not the
     source of truth. A placeholder class named otherwise, such as `_PendingConfig`, escapes it.
     The `WpDatabase` restore stubs, which are also placeholders under the story's AC, are
     outside its set entirely.
  2. Only one method per placeholder is called (for example `site_files_query.is_empty`, but not
     `entry_count`/`file_exists`; `config_command.set_constants`, but not
     `save_copy`/`replace_file`; `journal_command.finish_run`, but none of the other five).
     For `WpDatabase`, `check_ensure`, `check_load`, `check_revoke`, `check_drop_database`,
     `revoke_grants` and `drop_database` are never exercised past the admin check. A wrong
     `port` string or supplier on any of those methods, or a stub that returns instead of
     raising, would pass. The AC asks that "each placeholder-bound port raises
     `UnboundAdapterError` naming its supplier".
  3. Neither scope test has a planted case that attacks its scope. Per project rule, every guard
     test must plant a violation that attacks its scope.
- **Suggested fix:** Derive the placeholder set from the source of truth. Either give the
  placeholders a shared marker (a base class or an `_unbound_supplier` attribute) and select by
  that, or select every field of `real_adapters()` whose methods raise `UnboundAdapterError`.
  Call every Protocol method of every placeholder (enumerate them from the Protocol, the same
  way `test_port_split` does), including the nine `WpDatabase` restore methods with an
  administrator bound. Add one planted case for each test: a placeholder class that does not
  use the marker, and a twin class with no `CASES` entry. Each must make its test fail.

### F3 — LOW — kind: testability — `test_no_load_replace` package half passes vacuously and misses generic Protocols

- **Location:** `tests/contracts/test_no_load_replace.py:1718-1721`, `:1612-1617` (`_is_protocol`)
- **Description:** `test_no_database_load_call_passes_replace` discards `total`. No database `load`
  call exists until E002-S02-009, so the test currently checks zero calls. Nothing will flag it
  if S02-009's call uses a spelling the walker misses, for example
  `importlib.import_module`, or a module alias bound by assignment. `_is_protocol` also only
  recognises `Protocol` and `x.Protocol` bases, so a generic `class X(Protocol[T])` port
  (`ast.Subscript`) is skipped silently.
- **Suggested fix:** Record that `total == 0` is expected until S02-009, and assert `total >= 1`
  once it lands. A simple way is to xfail `total >= 1` with `strict=True` referencing
  E002-S02-009, so the guard flips red when the call appears and the assertion has to be
  tightened. Also accept `ast.Subscript` bases whose `.value` is `Protocol`, and add that case
  to the planted module.

### F4 — LOW — kind: interface-contract — `administrator_bound` is an untyped, attribute-name contract

- **Location:** `src/l3io/wp/backup/cli/adapter_sets.py:784-791` (`_administrator_bound`);
  `src/l3io/wp/backup/adapters/database.py:106-109`
- **Description:** `dry_run_adapters` reads `getattr(command, "administrator_bound", False)`. No
  Protocol declares that attribute, so mypy cannot catch it if E002-S02-009's real adapter
  renames or drops it. The no-op would then refuse every administrator method in a Dry Run
  while the real Run proceeds. That fails closed, but it contradicts "a Dry Run refuses where
  the real Run would".
- **Suggested fix:** Declare `administrator_bound: bool` as a read-only property on
  `DatabaseQuery` or `DatabaseCommand`, or on a small dedicated Protocol, and read it directly.
  Alternatively, add a test that `WpDatabase` exposes the attribute the root reads, referencing
  the constant name.

### F5 — LOW — kind: maintainability — module-wide lint suppression in a composition root

- **Location:** `src/l3io/wp/backup/cli/adapter_sets.py:1`
  (`# ruff: noqa: ARG002 - each placeholder method raises before reading its arguments`)
- **Description:** The file-level `noqa` disables unused-argument checking for the whole
  composition-root module, including `real_adapters`/`dry_run_adapters` and anything added
  later, to accommodate the four placeholder classes.
- **Suggested fix:** Move the placeholders into their own module (for example
  `cli/placeholders.py`) and keep the file-level `noqa` there. Or use per-line `# noqa: ARG002`,
  or `del` the arguments as `WpDatabase`'s stubs already do.

### F6 — LOW — kind: claim — `NoopRunJournal` uses a non-`RestorePhase` phase name

- **Location:** `src/l3io/wp/backup/adapters/noop.py:502-517` (`JOURNAL_PHASE = "journal"`)
- **Claim:** "Every no-op twin emits `phase_completed` with `outcome="skipped_dry_run"` and `bytes=0`".
- **Description:** The claim is met, but each journal call opens a separate `"journal"` phase
  record rather than joining the restore phase it belongs to. That phase is carried in
  `journal_phase` instead. A restore Dry Run's log will therefore show one standalone `journal`
  phase per journal call, interleaved with the real phases. This is noted so that Epic 3's log
  consumers and any phase-name allow-list expect it. `JOURNAL_PHASE` is also not in `noop.__all__`.
- **Suggested fix:** Either join the journaled `phase` (`_skip(phase.value, ...)`) where one is
  given, or record this record shape in ADR-0020/0021, and export `JOURNAL_PHASE`.
