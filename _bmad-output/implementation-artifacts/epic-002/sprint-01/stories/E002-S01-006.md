# E002-S01-006: Supply credentials without exposing them


**Implements:** FR-15


As an operator,
I want database credentials never to appear where another user or a log reader can see them,
So that backing up a site does not leak the site.

**Acceptance Criteria:**

**Given** any backup or restore that touches the database
**When** credentials must reach a MySQL client tool
**Then** they get there only through `l3io-wp-database`'s `dump` and `load`, which pass them through an anonymous-pipe option file (database ADR-0002); this package builds no argument vector and no option file for a client tool, guarded by `tests/contracts/test_no_mysql_client.py` (ADR-0015)
**And** `MYSQL_PWD` is never set by this package
**And** no credential appears in any log record at any level, asserted against captured structured and stdlib records across a full backup and a full restore
**And** every `repr` and any exception raised to a caller is clean — a traceback is log output under another name

## Business acceptance criteria

### Outcome

Across a full backup and a full verify — and, once Epic 3 lands, a full restore — no database credential appears in any log record at any level (including DEBUG), in any `repr`, in any exception message or traceback raised to a caller, in any argument vector or environment this package builds, in the CLI's stdout or stderr, or in any Archive Manifest. Credentials reach the MySQL client tools only through `l3io-wp-database`'s `dump` and `load`. Only `adapters/database.py` constructs a database credential source; composition roots pass backup-owned credential specs. This package owns exactly one redaction implementation, applied where text leaves the program (ADR-0018), which Epic 6's tracing adapter must reuse. A reviewer can tell it happened by running the backup with a planted sentinel password at DEBUG and searching every captured output for the sentinel: zero hits. ADR-0015 (with its 2026-10-27 amendment) and ADR-0018 are binding (`docs/adr/`, not spec-indexed; reached through AD-7).

### Non-goals

- The option-file / anonymous-pipe mechanism and its `0600`-and-removed assertions (AD-7 enforcement item 5) — `l3io-wp-database`'s ADR-0002 and tests, per ADR-0015.
- Credential Providers beyond `wp-config.php` and an explicit spec (environment, AWS Secrets Manager) — Epic 5 story 5.1; binding them into the roots — Epic 8 (E008-S01-001).
- Administrator provisioning (`survey`, `ensure`) — E002-S02-009 implements the operations, Epic 3 decides when they run.
- Span-attribute redaction — Epic 6 story 6.4 calls this story's `redact`.
- Passphrase **encryption** — Epic 4 story 4.3 (the cipher and the `encryption` extra). This story owns the AD-26 resolution chain only.
- Registering the flags that select a credential or request a passphrase (`--admin-*`, `--db-credentials-aws-*`, `--encrypt-with-passphrase`) — E002-S02-011.
- The restore half of "a full backup and a full restore": restore does not exist in E002. The restore assertion is a reusable fixture Epic 3 story 3.1 must apply.

## Technical acceptance criteria

### Interface contracts

- **`adapters/redaction.py` — the one redaction implementation (AD-7, FR-15, FR-30, AG-14).** `REDACTED: Final = "***"` (the marker database's `ResolvedCredentials.__repr__` uses). `class SecretRegistry` — a per-Run, thread-safe set of secrets: `register(value: str) -> None` (ignores empty strings and values shorter than 4 characters, logging one WARNING `secret_too_short_to_redact` with the source label only) and `redact(text: str) -> str` (every registered secret, longest first, replaced with `REDACTED`) and `redact_argv(argv: Sequence[str]) -> list[str]`, so a registry satisfies E002-S01-004's `ports/tracing.Redactor` structurally. `redact_event(event_dict) -> event_dict` is a `structlog` processor that walks the event recursively (strings, mappings, sequences, exception text) and applies `redact`. **There is no other redaction code in the package** (contract test below). It lives in `adapters/` (it holds per-Run state) and is importable by `cli/`, `api/` and Epic 6's `adapters/tracing` without a cycle.
- **Redaction at the boundary, not in `domain/` (ADR-0018).** `BackupError.__str__` does no redaction (E002-S01-001). The boundary applies `redact`: `cli/exit.py`'s rendering of an error and any traceback to stderr (E002-S01-005); `redact_event`, installed by E002-S01-004's `configure_logging` as the last processor before the renderer for structlog-native and stdlib records alike; and, in Epic 6, the tracing adapter's span attributes. Messages are built from structured fields (source label, host, database name) and never interpolate a credential or a dependency exception's text — that is the primary control, and redaction is the backstop.
- **Registration point.** `adapters/database.py` registers every `ResolvedCredentials.password` with the Run's `SecretRegistry` **immediately after** it calls a source's `resolve()`, and every password in an explicit spec when it builds the source. The username is not a secret (matching database's `repr`). *(Decided 2026-10-27.)* The registry is created by the composition root **before the Run opens** — `run_backup`, `run_verify`, `run_restore` and each `api/` entry point create one `SecretRegistry()` first — and handed to `open_run(..., secrets=registry)`, which adopts it as `ctx.secrets` (E002-S01-004). A joined Run keeps the opener's registry, and a root that joins uses `ctx.secrets`.
- **`domain/credentials.py` (new, pure) — the AD-9 order and the backup-owned spec (ADR-0015 amendment).** `class CredentialOrigin(StrEnum)`: `EXPLICIT = "explicit"`, `ENVIRONMENT = "environment"`, `WP_CONFIG = "wp-config"`. `WORDPRESS_CREDENTIAL_PRECEDENCE: Final = (EXPLICIT, ENVIRONMENT, WP_CONFIG)`; `ADMIN_CREDENTIAL_PRECEDENCE: Final = (EXPLICIT, ENVIRONMENT)` — the administrator order has **no** `WP_CONFIG` step, because a provider never substitutes the WordPress account for the administrator; the docstring states both rules. AWS Secrets Manager is a kind of explicit source, not a fourth origin. Epic 5's `adapters/credential_providers.py` imports these tuples and declares no precedence of its own. Frozen `ExplicitCredentialSpec(username: str, password: str)` (`__repr__` shows `password='***'`) and `AwsSecretCredentialSpec(secret_id: str, region: str | None)`; `CredentialSpec: TypeAlias = ExplicitCredentialSpec | AwsSecretCredentialSpec`. This is what `cli/`, `api/` and `BackupRequest.credentials` (E002-S01-004) carry; database's `CredentialSource` never appears on the public API.
- **`adapters/database.py` builders — the only construction of database credential classes.** `wordpress_source(spec: CredentialSpec | None, *, wp_config: CredentialSource, environ: Mapping[str, str], secrets: SecretRegistry) -> CredentialSource`: `None` → the `wp-config.php` source; `ExplicitCredentialSpec` → `CredentialChain(Explicit(...), wp_config)` in `WORDPRESS_CREDENTIAL_PRECEDENCE` order with the environment step skipped; `AwsSecretCredentialSpec` → `UsageError` naming Epic 5 until Epic 8 binds Epic 5's provider. `admin_source(spec: CredentialSpec | None, *, environ: Mapping[str, str], secrets: SecretRegistry) -> CredentialSource | None`: `None` → `None`; `ExplicitCredentialSpec` → `Explicit(...)`; `AwsSecretCredentialSpec` → `UsageError` naming Epic 5. Every password is registered before return.
- **`cli/credentials.py` (new) — the composition roots' one seam.** `wordpress_spec(*, aws_secret_id: str | None, aws_region: str | None) -> CredentialSpec | None` and `admin_spec(*, username: str | None, password: str | None, aws_secret_id: str | None, aws_region: str | None) -> CredentialSpec | None` turn flag values into specs (a lone `username` or `password` is `UsageError`; `aws_region` without `aws_secret_id` is `UsageError`); `wordpress_source(...)` and `admin_source(...)` take a spec and delegate to the `adapters/database.py` builders. `cli/backup.py`, Epic 3's `cli/restore.py` and Epic 6's `api/` call these and construct no database class. Epic 8 (E008-S01-001) changes only this module's delegation, to Epic 5's providers.
- **`cli/passphrase.py::resolve_passphrase(*, explicit: str | None, environ: Mapping[str, str], prompt: Callable[[str], str] | None, secrets: SecretRegistry) -> ResolvedPassphrase | None` — the one AD-26 chain, shared verbatim by both composition roots.** Order, first present wins: (1) `explicit` — the library's `passphrase=` argument (no CLI flag takes a passphrase value); (2) **`L3IO_WP_BACKUP_PASSPHRASE`** from the `environ` passed in (the CLI passes `os.environ`; nothing deeper reads the environment); (3) `prompt` — the CLI binds `getpass.getpass` **only when `sys.stdin.isatty()`**, else `None`. An empty string at any step is "absent"; a prompt raising `EOFError`/`KeyboardInterrupt` stops the chain with `PassphraseUnavailableError(UsageError)` (added to `domain/errors.py` here). Returns `None` when nothing resolves. `secrets` is the registry the root created before the Run (above), not one the Run creates: the root resolves the passphrase into it, builds the cipher, then passes the same registry to the driver, so the passphrase is registered before `run_started` and before the request exists. Frozen `ResolvedPassphrase(value: str, source: Literal["argument", "environment", "prompt"])`, `__repr__` showing only `source`. **The value is registered with `secrets` before return.** A backup root calls it only when passphrase encryption is requested; with no encryption requested nothing is prompted (AD-26 as decided 2026-10-20). A restore root calls it on every restore, because the one passphrase both decrypts an encrypted Archive and encrypts the Safety Snapshot; when none resolves, an encrypted Archive is refused at plan time and a plain one restores with the AD-26 unencrypted-Snapshot WARNING *(ADR-0024; Gate E004 AG-6, 2026-10-30)*. `api/` imports it from `cli/passphrase.py` (one layer with `cli/`).
- **Clean `repr` (AD-7 item 3, AG-14).** Every package type that holds or wraps a credential source, `ResolvedCredentials`, a spec, a passphrase or an identity — the `AdapterSet`, `ExplicitCredentialSpec`, `ResolvedPassphrase`, Epic 4's `AgePayloadCipher` *(ADR-0024)* — defines `__repr__` without the secret. A contract test enumerates every class in the package (walked, not listed) whose annotations mention `ResolvedCredentials` or `CredentialSource`, or that has a field named `password`, `passphrase`, `identity` or `identities`, and asserts it overrides `__repr__`.
- **No argument vector, no option file, no `MYSQL_PWD`, no PyMySQL (ADR-0015, AD-7).** This package constructs no `subprocess` call to a MySQL client, never writes `MYSQL_PWD` into `os.environ` or an `env=` mapping, and imports no `pymysql`.

### Error and edge case handling

- A secret that is a substring of another: longest-first replacement, so the longer one is fully redacted.
- A secret URL-encoded or split across two log fields: not caught by string redaction — stated as a limit in the module docstring. The guard is upstream: no code path builds a URL or connection string containing a credential (no `pymysql`, no `mysql://`/`mysql+` literal).
- A secret shorter than 4 characters: not registered; the WARNING names the source label only. It still never reaches a log, because nothing logs credentials in the first place.
- A credential source that raises while resolving: re-raised as `CredentialsError` naming the source label and the failure class, never the value.
- A lone `--admin-username` or `--admin-password` (or library half): `UsageError` naming the missing half. An AWS spec before Epic 8 binds Epic 5: `UsageError` naming Epic 5.
- Passphrase encryption requested with no argument, no environment value and no TTY: `PassphraseUnavailableError` → `USAGE`, naming `L3IO_WP_BACKUP_PASSPHRASE` and stating no prompt was possible; nothing read from the Site.
- A passphrase shorter than the registry's 4-character floor: refused with `PassphraseUnavailableError(reason="too short to protect")`, because an unredactable passphrase is the one secret redaction cannot back up.
- `L3IO_WP_BACKUP_PASSPHRASE` set but passphrase encryption not requested: ignored, one DEBUG record naming the variable (never the value).
- A host that configures logging itself instead of calling `configure_logging`: its chain lacks `redact_event`, and the guarantee rests on the primary control. Epic 6's `api/` documentation must say so (ADR-0018 "What this does not cover").

### Observability requirements

- Every place a command line or a connection is described in a log record uses `redact_argv` / `redact`; logged connection descriptions carry `db_host`, `db_port`, `db_name` and `credential_source` (the label), never `username` with `password`.
- The redaction processor emits no record itself; one DEBUG `secrets_registered` with a count is emitted per Run.

### Security considerations

- Threat: credential disclosure through `ps`/`/proc` (argv, environ), logs, tracebacks, `repr`, span attributes, CLI output and the Archive itself. Each has a mechanical assertion in Testability; none rests on review.
- The `SecretRegistry` holds plaintext secrets for the Run's lifetime only; it is never logged or pickled, its `__repr__` shows only a count, and it is dropped with the Run Context.
- The passphrase never appears in `argv` (no flag accepts it), is read from the environment only at the composition root, is registered before it leaves `resolve_passphrase`, and is passed to Epic 4's cipher by reference. The environment source is documented with its exposure (`/proc/<pid>/environ` is readable by the same user).
- No credential is written to the Run workspace by this package (the Dump is data, not connection credentials).

### Testability approach

- `tests/unit/adapters/test_redaction.py`: longest-first, nested structures, exception text in an event, short-secret warning without the value.
- `tests/contracts/test_single_redaction.py`: fails if any module other than `adapters/redaction.py` contains the literal `"***"` or defines a function whose name contains `redact` — every module walked, scope-asserted; this is what keeps `domain/` and `core/` free of redaction code (ADR-0018).
- `tests/contracts/test_credential_hygiene.py`, **the AD-7 items 1–4 assertions**, driven by a reusable fixture `credential_sentinel` (in `tests/conftest.py`) that plants a unique sentinel password in a temp `wp-config.php` and captures: (1) every structlog event (`structlog.testing.capture_logs`) and every stdlib record (`caplog` at level 1), at every level, plus rendered output; (2) the CLI's stdout and stderr, including the rendered error on failure-injected runs; (3) `str()`, `repr()` and `traceback.format_exception()` of **every exception the drivers raise**, taken directly with no redaction applied — the surface ADR-0018 leaves to the primary control; (4) `repr()` of every object the composition root builds, every `subprocess.Popen` argv and `env` (spy), `os.environ` before and after, and the produced Archive's Manifest bytes. Each is asserted sentinel-free. Runs for backup `all`, backup `db`, verify, and a backup that fails at authentication; `@pytest.mark.integration` where it needs the CI database, with a unit variant over a database double that records what it was handed. Its docstring states Epic 3 story 3.1's obligation to apply it to a full restore, and a tripwire test fails once `core/restore` exists without a restore case (the `test_extraction.py` shape). A passphrase parameter of the fixture drives `resolve_passphrase` with a sentinel in the environment and asserts it absent from every captured surface; Epic 4 (E004-S01-003) applies the same parameter to an encrypted Run.
- `tests/contracts/test_repr_clean.py`: the walked-class `__repr__` check.
- `tests/contracts/test_no_mysql_client.py` unchanged; `tests/contracts/test_no_mysql_pwd.py` and `tests/contracts/test_no_pymysql_import.py` added beside it, AST-based like their sibling.
- `tests/contracts/test_credential_sources_built_once.py`: an AST walk of every module under `src/l3io/wp/backup/` (scope-asserted non-empty), excluding `adapters/database.py` and, once it exists, `adapters/credential_providers.py` (each checked to exist when excluded), fails on any call to `Explicit`, `Environment`, `AwsSecretsManager`, `WpConfigFile` or `CredentialChain`; a planted violation in a temp `cli/x.py` proves it fires. A second check walks `typing.get_type_hints` of every public request type (`BackupRequest`, `VerifyRequest`, and Epic 6's once they exist) and fails on any annotation from `l3io.wp.database`.
- `tests/unit/domain/test_credential_precedence.py`: no duplicate in either tuple; `WP_CONFIG` absent from `ADMIN_CREDENTIAL_PRECEDENCE`; the WordPress tuple ends with `WP_CONFIG`; `repr(ExplicitCredentialSpec(...))` hides the password.
- `tests/unit/cli/test_credentials.py`: a password reaching either builder is registered before return (spy `SecretRegistry`); a lone half is `UsageError`; an AWS spec is `UsageError` naming Epic 5.
- `tests/unit/cli/test_passphrase_chain.py`: precedence argument > environment > prompt, each absent in turn; empty strings skipped; prompt not called without a TTY (pseudo-TTY via `pty.openpty` for the positive case); `EOFError` stops the chain; the value is in the registry on return; `repr` shows only the source; the CLI root and the library root both hold this function object (identity check).

### Existing-library check

- Credential transport to client tools: `l3io-wordpress-database` v0.2.0 (`dump`, `load`; its ADR-0002 pipe option file) — ADR-0015; nothing reimplemented. Credential sources and chains: database's `Explicit`, `WpConfigFile`, `CredentialChain`.
- Credential-source `repr` redaction for database's own types: already provided (`ResolvedCredentials`, `Explicit`).
- Log capture in tests: `structlog.testing.capture_logs` and pytest's `caplog`. Passphrase prompt: stdlib `getpass`.
- Value redaction itself: no maintained library redacts *known runtime values* across structlog event dicts; pattern-based scrubbers are the wrong tool because the secret's shape is unknown. The custom code is one small processor under the ~100-line threshold that would require an ADR; if it grows past that, stop and raise it.
