# E002-S01-003: Verify an archive without touching a site


**Implements:** FR-3


As an operator,
I want to check that an archive is still good,
So that I find out before a restore rather than during one.

**Acceptance Criteria:**

**Given** an Archive produced by this tool
**When** verification runs
**Then** it reports pass or fail and makes no write outside its own temporary workspace
**And** a truncated or corrupted Archive fails
**And** a Manifest declaring a Dump that is absent is a verification failure, not a restore-time surprise
**And** the result carries `integrity` (`VERIFIED` or `STRUCTURAL_ONLY`), not only pass or fail, so a v0 Archive passes as `STRUCTURAL_ONLY` (AD-23)

## Business acceptance criteria

### Outcome

`wpbackup2 verify --archive <target>` (and the library verify driver, E002-S01-004) reads an Archive and reports one of three results: **pass with `integrity: VERIFIED`** — a v1 Archive whose Manifest parses, whose `format_version` is supported, whose outer tar holds exactly `manifest.json` and the payload it names, whose payload's size and checksum match the bytes as stored, and whose member index is well formed *(ADR-0024)*; **pass with `integrity: STRUCTURAL_ONLY`** — a v0 Archive (no Manifest) in one of the two shapes 0.2.21 wrote, `database.sql` plus `wp-root/…`, or `wp-root/…` alone (the files-only Archive of 0.2.21's `--mode files`, which passes with `dump_present=False`, restores files only, and is refused by a Restore Mode naming the database); or **fail** naming the first reason. It writes nothing outside its own private workspace and touches no Site. The same verifier is the one E002-S01-010's publish gate runs and the one Epic 3 runs before any destructive step. A reviewer can tell it happened by corrupting one byte of a v1 Archive and seeing a fail that names the payload *(ADR-0024)*.

### Non-goals

- Running verification automatically before a destructive restore step — Epic 3 story 3.1 (AG-29); this story ships the verifier that story calls.
- Restoring an Archive onto a Site — Epic 3. (The extraction *function* lands here because `adapters/tar` is Epic 2's; see Interface contracts.)
- Deciding what restore does with an absolute or out-of-Site-Root symlink, which `tarfile`'s `data` filter refuses at extraction although the Archive verifies — an Epic 3 / AD-11 decision (ADR-0017 Concern); this story neither refuses nor rewrites such links.
- The `age` cipher — Epic 4's `AgePayloadCipher` (E004-S01-003). Verification needs no key: the payload is checksum-verified over its bytes as stored. This story's `decrypt_payload` only streams the payload through a `PayloadCipher` it is handed *(ADR-0024)*.
- The committed v0 fixture Archives — Epic 4 (story 4.2). This story writes the v0 classifier branch and tests it against v0-shaped tars built in the test.
- Remote Storage Targets — v1.1.

## Technical acceptance criteria

### Interface contracts

Files added or changed under `src/l3io/wp/backup/`, with the conventions E002-S01-001 records.

- **`ports/archive.py` — `ArchiveProbe` (AD-23, AG-7), a query port.** `member_index(source: StorageTarget) -> MemberIndex` and `member_digests(source: StorageTarget) -> Mapping[str, MemberDigest]`, which streams every member once. Raw facts only; it never decides a format. Neither accepts nor returns `bytes` (AD-21).
- **`domain/archive_format.py` additions (this module is Epic 2's alone, v0 branch included — Epic List ownership note).**
  - Frozen `MemberIndex(names: tuple[str, ...], first_member: str | None, manifest_text: str | None, readable_to_end: bool, gzip: bool)` — `names` keeps duplicates in tar order. `class TarMemberType(StrEnum): FILE, DIR, SYMLINK, HARDLINK, OTHER`; frozen `MemberDigest(tar_type: TarMemberType, size: int, sha256: str | None, link_name: str | None)`. These are domain types so the port can return them without `domain/` importing `ports/` (AD-1).
  - **`SUPPORTED_FORMAT_VERSIONS: Final[frozenset[int]] = frozenset({1})`** (ADR-0017). The runtime classifier compares against this constant; the committed fixtures are the evidence it is right (see Testability). v0 has no `format_version` and is detected by shape, not through the constant.
  - `classify(index: MemberIndex) -> ArchiveView` recognises exactly three shapes: (1) first member `manifest.json` → v1, whose `format_version` must be in `SUPPORTED_FORMAT_VERSIONS` (else `UnsupportedFormatVersionError(found=...)`); (2) no Manifest, members `database.sql` **and** `wp-root/…` → v0 with a Dump (`dump_present=True`); (3) no Manifest, `wp-root/…` and **no** `database.sql` → v0 files-only (`dump_present=False`, no `dump`-role member). Anything else — `database.sql` without `wp-root/` included (0.2.21 never wrote one) — raises `UnrecognisedArchiveError(found=<first few member names>)`. Detection never looks at a filename or extension.
  - Frozen `ArchiveView(format_version: int | None, members: tuple[ViewMember, ...], dump_present: bool, config_path: str | None, integrity: Integrity, encrypted: bool, payload: ManifestPayload | None)` — `encrypted` and `payload` copied from the v1 Manifest, `False` and `None` for v0 *(ADR-0024)*; `ViewMember(path, role, kind, link_target: str | None)`, with no checksum and no `encrypted` field *(ADR-0024)* (`link_target` from the v1 Manifest's `ManifestMember.link_target`, `None` for v0 and for non-links; added 2026-10-28 so a restore Dry Run can name the symlinks it would skip, ADR-0017 amendment) with **synthesized roles** for v0 (`database.sql` → `dump`, `wp-root/…` → `site-root`); `class Integrity(StrEnum): VERIFIED = "VERIFIED"; STRUCTURAL_ONLY = "STRUCTURAL_ONLY"`. For v1, `config_path` is the Manifest's `config_path` value copied as found (or `None`); the classifier does not interpret it — Epic 7's `place_config` converts it with `ConfigLocation(...)` and refuses any other value, so an untrusted value never becomes a path here (AD-11). For v0 it is `"wp-root/wp-config.php"` when that member is present, synthesized as the roles are (AD-23), and `None` otherwise *(Gate E004 AG-11, 2026-10-30)*. Its value is a member path for v0 and a `ConfigLocation` value for v1, so a consumer that needs the config's original location reads it only when the view has a `config`-role member (E007-S01-002), and a consumer that reads the config's bytes reads the `config`-role member when there is one, else the member `config_path` names (E003-S02-006).
  - Verification result types, here so `domain/errors.py` can carry them: `class VerificationReason(StrEnum)`: `CHECKSUM_MISMATCH`, `SIZE_MISMATCH`, `MEMBER_MISSING`, `UNDECLARED_MEMBER`, `KIND_MISMATCH`, `UNSUPPORTED_MEMBER_TYPE`, `DUMP_DECLARED_ABSENT`, `TRUNCATED`, `UNREADABLE`, `UNRECOGNISED_FORMAT`, `UNSUPPORTED_VERSION`, `UNSAFE_MEMBER_PATH`; frozen `VerificationFailure(member: str | None, reason: VerificationReason)`; frozen `VerificationResult(passed: bool, integrity: Integrity, format_version: int | None, failures: tuple[VerificationFailure, ...])`; frozen `ExtractResult(members: int, bytes: int, skipped_links: tuple[SkippedLink, ...])`; frozen `SkippedLink(path: str, link_target: str, reason: Literal["absolute", "outside_destination"])` *(amended 2026-10-28, ADR-0017 amendment)*.
  - **No module outside `domain/archive_format.py` branches on format version** (contract test below).
- **`core/verify.py` — pure comparison.** `verify(view: ArchiveView, digests: Mapping[str, MemberDigest], index: MemberIndex) -> VerificationResult`. v1 rules, keyless (ADR-0017 as amended by ADR-0024): `manifest.json` occurs exactly once, as the first member — a second occurrence anywhere is `UNDECLARED_MEMBER`; the only other outer member is the payload the Manifest names (`UNDECLARED_MEMBER` for any other, `MEMBER_MISSING` when absent); a `HARDLINK` or `OTHER` outer member is `UNSUPPORTED_MEMBER_TYPE`, and a payload that is not a regular file is `KIND_MISMATCH`; the payload's size and SHA-256 must equal `payload.size` and `payload.sha256` (`SIZE_MISMATCH` / `CHECKSUM_MISMATCH`, naming the payload); the member index read from the Manifest must be well formed — every path passes `member_path`'s rules (`UNSAFE_MEMBER_PATH`), no path occurs twice, only a `symlink` entry carries a `link_target` (`UNREADABLE` otherwise) — and `dump_present: true` with no `dump`-role entry is `DUMP_DECLARED_ABSENT`. The inner tar is not opened: per-file checksums are withdrawn (ADR-0024). v0: the stream reads to the end and one of the two v0 shapes holds. `integrity` is never omitted: a v1 pass is `VERIFIED`, a v0 pass `STRUCTURAL_ONLY`; a v1 Archive cannot pass as `STRUCTURAL_ONLY` (AG-17).
- **`adapters/tar.py` — `TarArchiveProbe`, the verifier and the one extraction function.**
  - `TarArchiveProbe` implements `ArchiveProbe` with stdlib `tarfile` in stream mode (`r|*`, gzip and plain tar), reading each file member in fixed-size chunks into `hashlib.sha256`.
  - `verify_archive(path: Path) -> VerificationResult` composes probe, `classify` and `core/verify`. `verify_or_raise(path: Path) -> None` raises `VerificationFailedError(result)` when `passed` is false; it is what every backup root binds into `LocalArchiveStore(verify=...)`, replacing E002-S01-010's `structural_check`, which this story deletes.
  - `extract_archive(source: StorageTarget, destination: Path, view: ArchiveView, *, roles: frozenset[MemberRole], exclude: frozenset[PurePosixPath] = frozenset(), payload: Path | None = None) -> ExtractResult` — the single extraction function AD-11 requires for every restore path. For v1 it opens the plain payload with `tarfile.open(..., mode="r:gz")`: `payload` when given (the file `decrypt_payload` wrote), else the outer tar's payload member; `payload=None` with `view.encrypted` raises `ValueError` (a programming error, refused earlier at plan time). For v0 (`view.payload is None`) it opens the Archive itself *(ADR-0024)*. `filter="data"` passed explicitly when `hasattr(tarfile, "data_filter")`, refusal (never `fully_trusted`) where it is absent, and containment re-checked against `destination` after role-prefix stripping. `exclude` holds role-relative paths (e.g. `wp-config.php`) that are skipped — the filter callable returns `None` for them, `tarfile`'s documented skip, so their bytes are never written; each entry must be relative with no `..` (`ValueError`, a programming error); the skip happens after the `data` filter's checks, so an excluded member that is also unsafe still refuses the Archive. Epic 3 cannot add it because `adapters/tar` is Epic 2's; `verify` does not use it. E002-S02-012's `SiteFilesCommand.extract` delegates to it.
  - `decrypt_payload(source: StorageTarget, view: ArchiveView, *, cipher: PayloadCipher, destination: Path) -> Path` *(ADR-0024)* streams the outer tar's payload member through `cipher.decrypt(reader, writer)` into `destination`, a new `0600` file in the Run workspace, and returns it. It is the one place a payload is decrypted; restore's `VERIFY` calls it (E003-S01-001). `age` authenticates every chunk, so a wrong passphrase, a damaged chunk or a truncated stream raises from `cipher.decrypt` (E004-S01-003's two errors) and `destination` is removed. A view that is not encrypted raises `ValueError`. It writes nothing else.
- **Unsupported symlinks are skipped, not refused** *(Shawn, 2026-10-28; E003 gate AG-2; ADR-0017 amendment)*. The filter callable wraps `tarfile.data_filter`. When a **symlink** member (`TarInfo.issym()`) makes it raise `tarfile.AbsoluteLinkError` or `tarfile.LinkOutsideDestinationError`, the callable returns `None` — `tarfile`'s documented skip — so nothing is written at that path, appends a `SkippedLink` (path relative to its role prefix, target verbatim) to `ExtractResult.skipped_links`, and extraction continues. Every other `tarfile.FilterError` still refuses the Archive: an absolute or `..` member name, a member outside the destination, a hard link pointing outside it or at an absolute path, a special file. **A hard link that stays inside the destination is also refused, by the callable itself:** `data_filter` allows it (checked against CPython 2026-11-03), so before calling `data_filter` the callable refuses any member with `TarInfo.islnk()`, the same refusal a `FilterError` produces. ADR-0017 never writes `LNKTYPE` members, so a hard link in a payload is only ever crafted, and one pointing at the kept `wp-config.php` would otherwise overwrite it. Containment otherwise stays `tarfile`'s; the callable adds only this one check and the symlink skip *(pre-build re-check MAJOR 1, 2026-11-03)*.
- **CLI.** `cli/parser.py` gains a `verify` subcommand taking `--archive` (required) — an addition AD-22 permits. `cli/verify.py::run_verify(args) -> int` returns `0` on pass and non-zero on fail (E002-S01-005 makes it `VERIFICATION_FAILED`). The human output names `integrity`; a v0 pass says integrity was not checked because v0 carries no checksums.
- **Errors added to `domain/errors.py`:** `VerificationFailedError(BackupError)` (`result: VerificationResult`); `UnrecognisedArchiveError(BackupError)` (`found`); `UnsupportedFormatVersionError(BackupError)` (`found`); `ArchiveNotFoundError(BackupError)` (`path`); `ArchiveHasNoDumpError(RefusedError)` (`archive: str`, `backup_scope: str | None` — `None` for v0) — raised by Epic 3's `build_restore_plan` from `view.dump_present is False`, so the class Epic 3 raises is Epic 2's and exits `REFUSED` through `RefusedError`.
- *(Added 2026-10-27, ADR-0016 amendment.)* **`ArchiveProbe.read_member(source: StorageTarget, view: ArchiveView, path: str, *, max_bytes: int, payload: Path | None = None) -> bytes`** — a query: reads one regular-file member into memory, streaming, and returns its bytes. It reads through the plain payload by the same rule as `extract_archive` (`payload`, else the outer tar's payload member; `ValueError` for an encrypted view with no `payload`; the Archive itself for v0) *(ADR-0024)*. Refuses a member that is not a regular file, a path not in the member index, or one larger than `max_bytes` (`MemberReadRefusedError(RefusedError)`); writes nothing anywhere and extracts nothing. Its callers read the config member: the restore root, for a target with no `wp-config.php` (E003-S02-006), and `REWRITE_CONFIG` under `--overwrite-wp-config` (E003-S01-001). The Manifest stores no digest for a single member, so there is none to compare against *(ADR-0024)*. `TarArchiveProbe` implements it with the same stream reader as `member_digests`; the no-op set binds the real one, since it is a query.

### Error and edge case handling

- Truncated gzip or tar stream (cut at any byte offset, including inside the Manifest), in any shape: fail, `TRUNCATED`; never an unhandled `EOFError`/`tarfile.ReadError`.
- One byte flipped inside the payload: fail, `CHECKSUM_MISMATCH` naming the payload *(ADR-0024)*.
- Manifest declares `dump_present: true` and no `dump`-role member exists: fail, `DUMP_DECLARED_ABSENT` (FR-3).
- An outer member other than `manifest.json` and the named payload, a second `manifest.json`, or no payload: `UNDECLARED_MEMBER` / `MEMBER_MISSING` *(ADR-0024)*.
- A hard-link, device, FIFO or socket outer member, or one in a v0 tar: `UNSUPPORTED_MEMBER_TYPE`. A payload that is not a regular file: `KIND_MISMATCH`. Inside the payload, a special file is refused at extraction by the `data` filter, and a hard link in any position by the filter callable, because `data_filter` allows one that stays inside the destination *(ADR-0024; pre-build re-check MAJOR 1, 2026-11-03)*.
- A symlink member with an absolute target, or a target resolving outside the destination: **not a Verification failure** (ADR-0017), and at extraction skipped and reported in `ExtractResult.skipped_links` rather than refused (Interface contracts). A hard-link member pointing anywhere is still refused.
- `manifest.json` present but not the first member: not v1 — fail `UNRECOGNISED_FORMAT`; a v0 shape with a stray `manifest.json` later is also `UNRECOGNISED_FORMAT`, not silently v0.
- `manifest.json` not valid JSON, missing `format_version`, or larger than the cap: `UNREADABLE`; a `format_version` not in `SUPPORTED_FORMAT_VERSIONS`: `UNSUPPORTED_VERSION` naming the version found.
- A member path that is absolute, contains `..` or escapes its role prefix: `UNSAFE_MEMBER_PATH`, before any caller extracts.
- v0 with `wp-root/` and no `database.sql`: **pass**, `STRUCTURAL_ONLY`, `dump_present=False`. v0-shaped with `database.sql` and no `wp-root/`: `UNRECOGNISED_FORMAT` naming the members found.
- Empty file, non-tar file, a `.zip`: `UNRECOGNISED_FORMAT` naming what was found.
- Archive path does not exist or is unreadable: `ArchiveNotFoundError` with `raise ... from` the `OSError` — not a bare `FileNotFoundError` (AD-14's named example).
- A non-`file:` Storage Target: `UnsupportedStorageSchemeError` from E002-S01-001's grammar.

### Security considerations

- An Archive is untrusted input (AD-11, NFR-5): the probe reads headers and streams member bodies into a hash; it never writes a member to disk, never follows a link target, and never calls `extractall`. Verification writes nothing except, if it needs one, the Run workspace — asserted by a test that snapshots the parent directory, the Archive's directory and a Site Root before and after.
- Member names from the Archive reach logs and errors only after `repr()`-style escaping, so a crafted name cannot inject log lines or terminal escapes.
- Manifest JSON is parsed with stdlib `json.loads` and capped at 16 MiB (`UNREADABLE` above it), so a crafted Archive cannot exhaust memory through the one member read whole.
- `extract_archive` refuses on an interpreter without `tarfile.data_filter` rather than extracting unfiltered.
