# E002-S01-001: Produce an archive of a site's files and database


**Implements:** FR-1


As an operator,
I want one command to capture my whole WordPress site into a single file,
So that I have something to restore from.

**Acceptance Criteria:**

**Given** a Site Root containing a readable `wp-config.php`
**When** a backup runs naming only that directory
**Then** one Archive is produced containing a Dump, the Site Root tree and a Manifest
**And** with no Credential Provider given, the database credentials are resolved from that `wp-config.php` (FR-1)
**And** the Dump is produced by `l3io-wp-database`'s `dump`; this package invokes no MySQL client tool (ADR-0015)
**And** the Site is byte-identical afterwards — file mtimes, database contents and `wp-config.php` unchanged
**And** the Archive becomes visible at its destination only once complete and verifiable (NFR-2)
**And** no step reads the whole Archive or Dump into memory (AD-21)

*(The **Then** criterion and the last three **And** criteria — one Archive produced, the Site byte-identical afterwards, visible only once complete, nothing buffered whole — are delivered by E002-S01-010 after the 2026-10-27 split.)*

## Business acceptance criteria

### Outcome

The backup's contracts exist and its data source works, so E002-S01-010 can write and publish an Archive without inventing a type. Concretely: the Site Descriptor, the v1 archive format and Manifest (member index included), the Storage Target grammar, the Backup Scope enum, the exclusion value types, the package exception hierarchy, the backup ports, and the backup half of `adapters/database.py` — which locates `wp-config.php`, builds the Site Descriptor from it, resolves the WordPress credentials from it when no Credential Provider is given, checks dump readiness and produces the Dump through `l3io-wp-database`'s `dump`. A reviewer can tell it happened by building a descriptor from `tests/data/wp-config.php`, dumping the CI database into a temp directory through `adapters/database.py` with no other credential given, and round-tripping a Manifest through JSON.

Stories cite signatures, not line numbers.

**Timestamps.** Every timestamp this package writes — the Manifest's `created_at`, log records (E002-S01-004), the lock holder record (E002-S02-008) — is UTC ISO-8601 with the **`Z`** designator (e.g. `2026-10-27T09:15:00Z`). This is the one spelling; other stories refer here.

- **`domain/site.py` — the Site Descriptor (AD-3, AG-8).** `@dataclass(frozen=True, slots=True) class SiteDescriptor` with `site_root: PurePosixPath` (absolute, canonicalised by the caller), `db_host: str`, `db_port: int`, `db_name: str`, `table_prefix: str`, `site_url: str | None`, `home_url: str | None`, `credential_source: str` (the provider's label, never a secret). A Glossary field with no source in `wp-config.php` is `None`, never defaulted. No setters; `dataclasses.replace` is the only way to derive a changed value. Invalid values (relative `site_root`, empty `db_host`/`db_name`, port outside 1–65535) raise `InvalidSiteDescriptorError` from `__post_init__`. `database_location() -> DatabaseLocation`. The descriptor holds no credential object (AD-1: `domain/` may not import `ports/`).
- **`domain/database.py` — the database facts the backup ports carry.** Frozen `DatabaseLocation(host: str, port: int, name: str)` with `with_name(name) -> DatabaseLocation` (a derived name is never re-parsed); frozen `Readiness(ready: bool, blockers: tuple[str, ...], warnings: tuple[str, ...])` — finding **codes** only, from database's `Verdict`; frozen `DumpResult(bytes: int, duration_ms: float)`. E002-S02-012 adds the restore-side values to this module.
- **`domain/archive_format.py` — the one owned archive contract (AD-6, ADR-0017).**
  - `FORMAT_VERSION: Final = 1`; `MANIFEST_MEMBER: Final = "manifest.json"`; `class MemberRole(StrEnum): DUMP = "dump"; SITE_ROOT = "site-root"; CONFIG = "config"`; `member_path(role, relative: str) -> str` returns the role-prefixed tar name and raises `UnsafeMemberPathError` for an absolute path, a `..` segment, a NUL or a backslash.
  - `class MemberKind(StrEnum): FILE = "file"; DIR = "dir"; SYMLINK = "symlink"`; frozen `ManifestMember(path: str, role: MemberRole, kind: MemberKind, size: int, link_target: str | None)` *(ADR-0024)*. The member index, frozen for v1 at first release (ADR-0017 as amended by ADR-0024), lists the members of the payload's inner tar: every inner member has exactly one entry and every entry exactly one inner member. `file` (regular files, the Dump, the `config` member): `size` in bytes, `link_target=None`. `dir` (the Site Root and every directory under it, empty or not; `site-root` role only; no trailing slash): `size=0`. `symlink`: `size=0`, `link_target` the target verbatim. An index entry carries no checksum and no `encrypted` flag *(ADR-0024)*. Mode, mtime, uid and gid are carried by the tar header only — not in the Manifest. **The outer tar (ADR-0024)** is uncompressed and holds exactly two members: `manifest.json` first, never encrypted and not listed in its own index (stated in this module, and it must occur exactly once); then the payload, named `PAYLOAD_MEMBER: Final = "payload.tar.gz"` or, when encrypted, `ENCRYPTED_PAYLOAD_MEMBER: Final = "payload.tar.gz.age"`. The payload is a gzip-compressed inner tar holding the `dump`-role member first when the scope includes the database, then the other members in the writer's order (E002-S01-010); inner member names are `member_path`'s role-prefixed names.
  - `class ConfigLocation(StrEnum): SITE_ROOT = "wp-config.php"; PARENT = "../wp-config.php"` — the two places `wp-load.php` searches. Epic 7 imports it and defines no second enum.
  - Frozen `ManifestOrigin(kind: OriginKind, restore_mode: str, run_id: str)`, `class OriginKind(StrEnum): SAFETY_SNAPSHOT = "safety_snapshot"` (E003-S02-003; `restore_mode` is the `RestoreMode` value carried as `str`, so this module imports no restore type).
  - Frozen `ManifestExclusions(source: Literal["default", "custom", "none"], patterns: tuple[str, ...], excluded: tuple[ExcludedEntry, ...])` (E004-S01-001).
  - Frozen `Manifest(format_version: int, created_at: str, backup_scope: str, source: Mapping[str, str | int | None], encrypted: bool, payload: ManifestPayload, members: tuple[ManifestMember, ...], dump_present: bool, origin: ManifestOrigin | None, exclusions: ManifestExclusions | None, config_path: str | None)`. `source` is a `MappingProxyType`, so the Manifest is deeply immutable; it is the descriptor projected without any credential, and reserves two optional keys, `stored_siteurl`/`stored_home`, written only when `l3io-wordpress-database` exposes a read of those two options as the WordPress account — at v0.2.0 it does not (`survey` reads only `db_version`, as the administrator), and this package issues no SQL (ADR-0015), so both are absent and E007-S01-003's reading stands. `created_at` is supplied by the caller (`domain/` reads no clock). Optional keys (`origin`, `exclusions`, `config_path`, the reserved `source` keys) are serialised only when set, so a Manifest without them is byte-identical to one written before they existed. Frozen `ManifestPayload(name: str, size: int, sha256: str)` describes the payload member: its name (one of the two constants above), and its size and SHA-256 over the bytes **as stored** (the `age` file when `encrypted`) *(ADR-0024)*. `manifest_to_json(m) -> str` / `manifest_from_json(text) -> Manifest` use stdlib `json`; reads ignore unknown keys. The Manifest carries **no key material, no KDF parameters and no salt** (ADR-0014, ADR-0024).

### Error and edge case handling

- `--wp-dir` missing or not a directory: `InvalidSiteDescriptorError`. `wp-config.php` unreadable: database's `ConfigUnreadableError` re-raised as `CredentialsError` naming the path.
- `--wp-config` names a file that does not exist or is not a regular file: `InvalidSiteDescriptorError` naming the stated path; nothing is searched instead.
- Neither `<root>/wp-config.php` nor a usable `<root>/../wp-config.php` (absent, or the parent holds `wp-settings.php`): `InvalidSiteDescriptorError` naming both paths.
- A stated path outside both search locations: accepted, `location=None`; logged WARNING `wp_config_outside_search_path` with the path.
- `wp-config.php` defines `DB_USER` but not `DB_PASSWORD` (or the reverse): database raises `CredentialsUnobtainableError`; re-raised as `CredentialsError` naming the source label and the missing key, never the value.
- Database unreachable or authentication refused: database's `DatabaseUnreachableError` / `AuthenticationFailedError` re-raised as `DatabaseUnreachableError` / `CredentialsError` with `raise ... from`.
- `mysqldump` absent or killed mid-stream: database raises `TransferError`; re-raised as `DumpFailedError`; database leaves no partial Dump at `destination`.
- `check_dump` verdict with blockers: returned as `Readiness(ready=False, blockers=<codes>)` — not raised; the caller decides.
- The `database` extra not installed: `MissingExtraError(extra="database")` at the first call, before any write.
- `site_descriptor_from_archive_config` given no config file (a `database`-scope Archive, or a v0 Archive whose `wp-root/` lacks `wp-config.php`): `InvalidSiteDescriptorError(reason="archive has no wp-config.php")`.
- A Manifest whose `origin.kind` this build does not know: read as `origin=None` plus a WARNING naming the value (forward compatibility); a malformed `origin` (not an object, no `run_id`) raises the same error as any malformed Manifest field. A member entry with an unknown `kind`: malformed (a new kind is format v2, ADR-0017).

### Security considerations

- Credentials are resolved only by database's sources inside `adapters/database.py`, passed straight to `dump`, and never stored on the Site Descriptor, in the Manifest, in a log record or in an exception message.
- `repr(SiteDescriptor)` contains no credential (it holds none); a test asserts it. The full no-credential-anywhere assertion is E002-S01-006's.
- The Manifest's `source` projection, `ManifestOrigin` and `ManifestExclusions` carry no credential, recipient, identity or passphrase; a test plants a known password in `wp-config.php` and searches the serialised Manifest (with every optional key set) for it.
- `member_path` rejects escaping paths, so a member name can never leave its role prefix. Symlink targets are recorded verbatim and, like member names, are visible to anyone holding the Archive (ADR-0017).

### Testability approach

- **Unit (pure, no I/O)**, under the new `tests/unit/`, which mirrors the package's layer directories and needs no conftest beyond `tmp_path`: `tests/unit/domain/test_site.py` (frozen, no setter, construction-time errors, repr, `database_location`); `tests/unit/domain/test_archive_format.py` (`member_path` rejects `..`, absolute, NUL, backslash; Manifest JSON round-trip with every `MemberKind` and with `encrypted` both ways, `payload` included; `ManifestMember` has no `sha256` or `encrypted` field *(ADR-0024)*; `origin`, `exclusions` and `config_path` round-trip; a Manifest without the optional keys serialises byte-identically to a committed golden string; unknown keys ignored; unknown `origin.kind` reads as `None`; unknown member `kind` is malformed; `source` is read-only; no KDF or key field exists; `stored_siteurl`/`stored_home` absent, plus a check that `l3io.wp.database` exports no WordPress-account options read, which fails when database ships one so the keys get written); `tests/unit/domain/test_storage_target.py` (bare path, `file`, `s3` → `UnsupportedStorageSchemeError`, which is a `RefusedError`; default name in UTC).
- **Adapter tests:** `tests/adapters/test_locate_wp_config.py` (real files in `tmp_path`: in-root wins over parent; parent used only without `wp-settings.php`; parent with `wp-settings.php` refused naming both; `stated` wins and is never re-derived; `location is None` for a stated path elsewhere); `tests/adapters/test_descriptor.py` (both constructors against `tests/data/wp-config.php` and a copy placed as an extracted config member; `site_root` points at the target; a missing file raises `InvalidSiteDescriptorError`); `tests/adapters/test_database_backup.py` (`@pytest.mark.integration`, CI MySQL 8.4 / MariaDB 11.4: `check_dump` returns `Readiness(ready=True)`; `dump_to` writes a `0600` Dump with no credential given other than `wp-config.php`; wrong password → `CredentialsError`; a database double raising `TransferError` → `DumpFailedError`).
- **AD-14:** `tests/contracts/test_exception_hierarchy.py` imports every module under `src/l3io/wp/backup/`, collects every `Exception` subclass defined there and asserts each derives from `BackupError` — scope derived by walking the package. It also asserts `UnsupportedStorageSchemeError`, `ArchiveExistsError` and `DatabaseRefusedError` are `RefusedError` subclasses, and that no module under `domain/` imports from `adapters/` or `cli/` (the import-linter contracts already enforce it; this pins the ADR-0018 reason).
- **AD-21:** `tests/contracts/test_port_types.py` walks every Protocol in `ports/` with `typing.get_type_hints` and fails if any parameter or return annotation is `bytes` — scope from the `ports/` package, scope-asserted non-empty. Adding the first `ports/` module trips `tests/contracts/test_streaming.py::test_the_real_streaming_bound_is_still_owed`; this story **retargets** that tripwire from "a `ports/` module exists" to "`adapters/tar.py` defines `write_archive`", stated in its docstring, and E002-S01-010 replaces it with the RSS bound.
- **AD-11 tripwire:** adding `adapters/database.py` trips `tests/contracts/test_extraction.py::test_the_real_containment_test_is_still_owed`; this story retargets it from "any adapter module exists" to "`adapters/tar.py` defines `extract_archive`", so it still fires on the event it stands for; E002-S01-003 replaces it with the real containment test.
- **AD-6 single owner:** the literal grep described under Interface contracts, in `tests/contracts/test_archive_format_owner.py`.
