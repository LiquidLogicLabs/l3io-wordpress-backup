# E002-S01-004: Trace a run end to end by one identifier


**Implements:** FR-20


As an operator,
I want every line a run emits to carry the same identifier,
So that I can pull one run out of a week of logs.

**Acceptance Criteria:**

**Given** any run
**When** it emits records
**Then** every record carries the same Run ID, including those emitted around subprocess boundaries
**And** the Run ID is reported at the start and end of the run
**And** logging is configured once at a composition root and never in a library module
**And** `l3io-wp-config`'s (`l3io.wp.config`) stdlib records are pulled into the same structured stream without that package taking a logging dependency (AD-2, AD-10)
**And** a library caller can bind their own correlation ID and see it on these records
**And** each phase emits `phase`, `duration_ms`, `exit_code` and `bytes` as fields, so `jq` over a log file is sufficient

## Business acceptance criteria

### Outcome

Every record a Run emits — this package's, `l3io.wp.database`'s and `l3io.wp.config`'s — carries the same `run_id` (a UUIDv4), so `jq 'select(.run_id=="…")'` over a week of JSON logs returns exactly one Run, start to finish. The Run ID is printed when the Run starts and when it ends. Output is human-readable on a TTY by default and JSON when selected or when stderr is not a TTY; `--log-level` defaults to INFO. Each phase emits `phase`, `duration_ms`, `exit_code` and `bytes`. A library caller can bind their own correlation ID and see it on these records. The Run Context that carries the Run ID is created exactly once per Run, binds its adapter set exactly once, and is joined, never duplicated, by any nested entry point; backup and verify each have an argument-free driver that the CLI and Epic 6's `api/` share.

### Non-goals

- The Site Lock — E002-S02-008 adds the Run Context's `site_lock` field, `open_run`'s lock acquisition, and every test of lock order, lock joining and lock refusal (including the root span being open before the lock).
- Dry Run — E002-S02-007 adds `BackupRequest.dry_run`, `dry_run_adapters(...)` and the driver's selection between the two sets.
- OpenTelemetry spans, the `trace_id`/`span_id` processor and the `otel` extra — Epic 6 story 6.4 (`adapters/tracing`). This story leaves no-op-capable hooks and a processor slot but adds no tracing code.
- Exit-code numbers — E002-S01-005. `exit_code` fields carry what `exit_code_for` yields once that story lands (until then `0` on success, `1` on failure).
- Cross-package verbosity *implementation* in `l3io-wp-config` or `l3io-wp-database` — not edited; consistency is asserted against their published CLIs.
- Log message wording — not part of the §8 contract.

### Interface contracts

- **`ports/adapter_set.py` — `AdapterSet`, defined here and nowhere else (ADR-0016, resolution of its Concern).** `@dataclass(frozen=True, slots=True) class AdapterSet` with the ports that exist in sprint 1: `archive_store_query: ArchiveStoreQuery`, `archive_store_command: ArchiveStoreCommand`, `archive_probe: ArchiveProbe`, `database_query: DatabaseQuery`, `database_command: DatabaseCommand`, `tracer: Tracer`. Its `__repr__` names each field's type only (the database halves hold a credential source, E002-S01-006). E002-S02-007 and E002-S02-012 **add fields** to this class for the ports they introduce; no story defines a second container. The cipher and the exclusion policy are not fields: they are per-call arguments of `backup(...)`, so a Safety Snapshot states its own (E003-S02-006).
- **`cli/adapter_sets.py::real_adapters(*, wordpress_source: CredentialSource, secrets: SecretRegistry, tracer: Tracer) -> AdapterSet`** — the real constructor, in the composition-root layer: `LocalArchiveStore(verify=verify_or_raise)` for both store halves (E002-S01-010, E002-S01-003), `TarArchiveProbe()`, one `WpDatabase(wordpress_source, secrets)` for both database halves (E002-S01-001), and `tracer`. Later stories extend its keyword arguments; E002-S02-007 adds the only other constructor, `dry_run_adapters(...)`.
- **`cli/context.py` — the Run Context (AD-16, ADR-0016).** `@dataclass(frozen=True, slots=True) class RunContext` with `run_id: str` (`uuid.uuid4()`, never derived from time or path), `started_at: datetime` (UTC, tz-aware), `workspace: Path` (E002-S01-010's `run_workspace`, now opened here; no other code creates a workspace), `logger: structlog.stdlib.BoundLogger`, `clock: Clock`, `secrets: SecretRegistry` (E002-S01-006; the opener's, see below), `tracer: Tracer`, `run_span: RunSpan` (the root span `open_run` entered; a joined Run shares the opener's), and a private write-once adapter holder. `ctx.adapters` is a read-only property: reading it before a bind raises `AdaptersNotBoundError`. `ctx.bind_adapters(adapter_set: AdapterSet) -> None` sets it exactly once; a second call raises `AdaptersAlreadyBoundError`. Both are programming errors, added to `domain/errors.py` as `BackupError` subclasses (exit `FAILED`). `ports/clock.py` declares `Clock` (`now() -> datetime`, a query port), with `adapters/clock.py::SystemClock`.
- **Exactly once, joinable.** *(Decided 2026-10-27.)* `open_run(*, operation: str, tracer: Tracer | None = None, secrets: SecretRegistry | None = None, command_args: Sequence[str] | None = None, workspace_parent: Path | None = None) -> ContextManager[RunContext]` creates the context **without adapters**, binds `run_id` with `structlog.contextvars.bind_contextvars`, logs `run_started` (`run_id`, `started_at`, `operation`, package version), yields, and in its `finally` logs `run_finished` (`run_id`, `exit_code`, `duration_ms`), unbinds only what it bound, and removes the workspace. **The Secret Registry is created before the Run, by the composition root.** A root creates one `SecretRegistry()`, resolves the passphrase into it (`resolve_passphrase(..., secrets=registry)`, E002-S01-006) and builds the cipher with it, and only then passes it to the driver, which passes it to `open_run(..., secrets=registry)`. `open_run` **adopts** the registry it is given as `ctx.secrets` and creates its own only when given `None`. So a passphrase is registered before the Run, and the request's `cipher` exists before the driver is called. The active Run is a module-level `contextvars.ContextVar[RunContext | None]`. `open_run` while one is active raises `RunContextActiveError(RefusedError)` (added to `domain/errors.py`; exit `REFUSED`) naming the active `run_id`. `join_or_open(ctx: RunContext | None, *, operation: str, tracer: Tracer | None = None, secrets: SecretRegistry | None = None, command_args: Sequence[str] | None = None) -> ContextManager[RunHandle]`, frozen `RunHandle(ctx: RunContext, opened: bool)`: given a context it **joins** — creates nothing, binds nothing, configures nothing, opens no span, `opened=False`, and keeps the opener's registry (`ctx.secrets`) — and otherwise opens one with `opened=True`, forwarding `tracer`, `secrets` and `command_args` to `open_run`. A root that joins a given context resolves its passphrase into `ctx.secrets` and creates no registry. A driver binds adapters only when `opened` is true; it never tests whether a set is already bound.
- **`cli/logging.py::configure_logging(level: str, fmt: Literal["console", "json"] | None, *, trace_processors: Sequence[Processor] = ()) -> None` — the only logging configuration in the package (AD-10).** Called once by the CLI's `main` before `open_run`; `api/` (Epic 6) calls it only when asked. Processor chain, in order: `structlog.contextvars.merge_contextvars` **first**; `add_log_level`; `add_logger_name`; `TimeStamper(fmt="iso", utc=True)` (the `Z` spelling E002-S01-001 fixes for every timestamp); `format_exc_info`; `trace_processors` (the slot Epic 6 fills with `add_trace_ids`; the CLI passes `()`); E002-S01-006's `redact_event`; then `JSONRenderer()` or `ConsoleRenderer()`. Stdlib records (`l3io.wp.config`'s, third-party) go through `structlog.stdlib.ProcessorFormatter` with `foreign_pre_chain` equal to the pre-renderer processors, on one root handler on stderr, so `l3io.wp.config` takes no `structlog` dependency (AD-2). `l3io.wp.database` uses `structlog.get_logger` and is covered by the same configuration. Idempotent: a second call replaces the root handler.
- **CLI flags (AD-22, AG-15).** `--log-level` keeps its v0.2.21 spelling and top-level position with its **default changed from `CRITICAL` to `INFO`** (triage E-14; a behaviour fix AD-22 permits, named in the release notes); stdlib level names, case-insensitive. New top-level `--log-format {console,json}`; when omitted, `console` if `sys.stderr.isatty()` else `json`. These match `l3io-wp-database` v0.2.0's CLI (`--log-level` default `INFO`, `--log-format {console,json}`); `l3io-wp-config` ships no logging CLI to compare.
- **Library rule.** No module outside `cli/logging.py` calls `structlog.configure`, `structlog.configure_once`, `logging.basicConfig`, `logging.config.*`, or adds a handler to the root logger.
- **Caller correlation ID.** A caller that bound `correlation_id` with `bind_contextvars` before entering the API sees it on every record, because `merge_contextvars` is first and `open_run` never clears pre-existing variables.
- **Naming (AG-23).** The config package is `l3io-wp-config` / `l3io.wp.config` everywhere; the string `wpconfigr` appears nowhere under `src/l3io/` (contract test).
- **Tracing hooks (AD-24; E006-S01-004).** `ports/tracing.py`: `class Redactor(Protocol)`: `redact(text: str) -> str`, `redact_argv(argv: Sequence[str]) -> list[str]` — the Run's `SecretRegistry` (E002-S01-006) satisfies it structurally, and is what every call below passes; `ports/` may not import `adapters/` (the import-linter layers contract), so the port names the protocol, not the class. `class Tracer(Protocol)`: `run_span(*, run_id: str, operation: str, dry_run: bool, command_args: Sequence[str] | None, secrets: Redactor) -> AbstractContextManager[RunSpan]`, `phase_span(phase: str, *, secrets: Redactor) -> AbstractContextManager[PhaseSpan]`; `class RunSpan(Protocol)`: `set_attributes(*, db_name: str | None = None, archive_bytes: int | None = None) -> None`, `set_outcome(*, exit_code: int, error_type: str | None) -> None`; `class PhaseSpan(Protocol)`: `set_outcome(*, exit_code: int, archive_bytes: int | None) -> None`. These carry every attribute AD-24 names: `process.command_args` (redacted by the adapter through `secrets`, ADR-0018), `dry_run` and the Run ID when the span opens; `db.name` and `archive.bytes` once known, because the descriptor is read and the Archive written after the Run opens (`drive_backup` calls `ctx.run_span.set_attributes(db_name=...)` after the config read and `set_attributes(archive_bytes=...)` after publishing; `drive_restore` sets `db_name` the same way); the phase, its exit code and bytes on the phase span; the Run's exit code and `error.type` through `set_outcome`. All are observation ports, neither query nor command; E002-S02-007 lists them on the single-role allowance when it makes the split a test. `adapters/noop.py::NoopTracer` implements `Tracer`, `RunSpan` and `PhaseSpan` and does nothing; `tracer=None` means `NoopTracer()`. (1) **Root span:** `open_run` enters `tracer.run_span(..., command_args=command_args, secrets=ctx.secrets)` right after the Run ID is created and the registry adopted; its `finally` calls `set_outcome` with the Run's exit code and the failing `BackupError` subclass name, then exits the span after `run_finished`. `join_or_open` given a context opens no span. (2) **Phase span:** `open_run` sets `adapters/phase.py::ACTIVE_TRACER` (a `ContextVar[tuple[Tracer, Redactor] | None]`, default `None`, meaning `NoopTracer()`) to the Run's tracer and registry, and resets it in its `finally`; E002-S01-010's `phase(name)` enters `tracer.phase_span(name, secrets=registry)` around the block that emits `phase_completed`, and calls the phase span's `set_outcome` with the same `exit_code` and `bytes` it logs, so `phase()` needs no `RunContext` (`adapters/` may not import `cli/`). (3) **Processor slot:** `trace_processors` above. The tracer passed to `open_run` is the same instance `real_adapters` puts in `AdapterSet.tracer`. The CLI roots always pass `None` (AD-24: tracing is API-only), and pass no `command_args`; Epic 6's `api/` passes its `adapters/tracing` implementation and `command_args=None` — a library call has no command line of its own, and the host's `sys.argv` may carry the host's secrets, which this package's registry cannot know (corrected 2026-10-28). So in v1 no command line reaches a span, and that is correct: the CLI binds the no-op tracer, which records nothing. Nothing in Epic 2 imports `opentelemetry`.

### Error and edge case handling

- `open_run` inside an active Run: `RunContextActiveError` (exit `REFUSED`), never a second Run ID.
- `ctx.adapters` read before `bind_adapters`: `AdaptersNotBoundError`; a second `bind_adapters`: `AdaptersAlreadyBoundError` — both exit `FAILED` and indicate a defect, not an operator error.
- A failure anywhere inside the Run: `run_finished` is still emitted (from `finally`) with the failure's `exit_code`, and the workspace is removed. `KeyboardInterrupt`/`SystemExit` also reach the `finally`; SIGTERM handling is E002-S02-008's and routes through the same `finally`.
- `configure_logging` called twice in one process: replaces the root handler rather than stacking a second, so no record is emitted twice.
- Records from a thread spawned inside the Run (database's stderr drainer): `contextvars` do not propagate to a raw `threading.Thread`; such records carry `run_id` only if the thread was started under `contextvars.copy_context().run`. This package starts no threads; the test asserts database's records around `dump` carry `run_id`, and if any do not, that is raised against `l3io-wp-database` rather than patched here.
- A tracer whose `run_span`, `phase_span` or `set_outcome` raises: caught at the call site, logged once at WARNING `tracer_failed` with the tracer's type name, and the Run continues with `NoopTracer` — tracing never changes an outcome or exit code (AD-24).
- `drive_backup` given a `site_root` that does not exist: `InvalidSiteDescriptorError` before any Run is opened, exactly as `run_backup` reports it.
- Invalid `--log-level` or `--log-format`: argparse usage error.
- stderr closed or a broken pipe (`| head`): logging errors do not mask the Run's exit code; `logging.raiseExceptions` stays at its default and the CLI catches `BrokenPipeError` on exit.

### Security considerations

- `redact_event` sits after every enrichment processor (the trace slot included) and before the renderer, so nothing added late escapes redaction; a test asserts its index is `len(chain) - 2`.
- Raising verbosity to DEBUG never introduces a credential (FR-20) — exercised by E002-S01-006's `credential_sentinel` at DEBUG through this configuration.
- The Run ID is random (UUIDv4), so it leaks neither time nor path; the workspace path is logged only at DEBUG. `AdapterSet.__repr__` shows no credential source contents.
