# E002-S01-010: Write and publish an archive


**Implements:** FR-1, NFR-2, AD-12, AD-20, AD-21

*(Split from E002-S01-001 on 2026-10-27, arch gate finding AG-42. E002-S01-001 keeps the contracts and the database adapter; this story writes, stages and publishes the Archive and drives a backup end to end.)*


As an operator,
I want `wpbackup2 backup` to leave exactly one complete Archive or nothing at all,
So that a file at the destination is always one I can restore from.

**Acceptance Criteria:**

**Given** a Site Root containing a readable `wp-config.php` and a reachable database
**When** `wpbackup2 backup --wp-dir <Site Root>` runs
**Then** *(superseded by ADR-0024 — see the note below)* one v1 Archive is produced: a gzipped tar whose first member is `manifest.json`, followed by the `config` member, the `dump`-role member and the `site-root`-role tree
**And** *(superseded by ADR-0024 — see the note below)* every tar member except `manifest.json` has exactly one Manifest index entry with its kind, and every file member's checksum is over its bytes as stored (ADR-0017)
**And** the Site is byte-identical afterwards — file mtimes, database contents and `wp-config.php` unchanged
**And** the Archive becomes visible at its final name only after the injected verifier passes on the staged file, through `os.replace` in the destination directory (AD-20, NFR-2)
**And** an existing file at the final name is refused before any dump is taken, and a failed backup leaves nothing at the final name and no workspace behind
**And** no step reads the whole Archive or Dump into memory: peak RSS stays under the AD-21 bound for a site ten times larger than it (AD-21)

*(ADR-0024, 2026-10-29: the layout in the first two AC lines is superseded. The Archive is an uncompressed outer tar holding `manifest.json`, then one payload member, a gzip inner tar with the `dump`-role member first; the Manifest indexes the inner members without per-file checksums and carries the payload's size and SHA-256 over its bytes as stored.)*

## Business acceptance criteria

### Outcome

`wpbackup2 backup --wp-dir <Site Root> [--archive <target>] [--wp-config <path>]` produces exactly one v1 Archive at the Storage Target, written in a private per-Run workspace, staged under a temporary name beside the final one, verified, and only then renamed into place. A failed backup — database down, disk full, a file changing mid-write, a verifier failure — leaves nothing at the final name and removes its workspace. A reviewer can tell it happened by listing the Archive's members, reading its Manifest, confirming the Site, the database and `wp-config.php` are byte-identical before and after, and forcing the verifier to fail and seeing no final name.

### Non-goals

- The contracts this story writes against — Site Descriptor, archive format and member index, Storage Target, errors, ports, the database adapter — E002-S01-001.
- `--mode files|db`: this story always plans Backup Scope `all`; E002-S01-002 adds the other plans.
- The real verifier (`verify_archive`), the classifier and the `verify` command — E002-S01-003, which replaces this story's structural check in the publish gate.
- The Run Context, Run ID, the `backup(..., ctx=...)` entry point and the argument-free `drive_backup` — E002-S01-004, which restructures `run_backup` around them. Exit-code numbers — E002-S01-005. Dry Run and the archive-writer command port — E002-S02-007 (ADR-0019). The Site Lock — E002-S02-008.
- Encryption: the writer takes a `PayloadCipher` *(ADR-0024)*; every root binds `None` until E008-S01-001 binds Epic 4's (E004-S01-003). Exclusions: the traversal takes an `ExclusionPolicy`; this story's root passes E002-S01-001's `INCLUDE_EVERYTHING`. From E002-S01-004 the backup default is `default_exclusion_policy()`, the same for the CLI and the library, and E008-S01-001 points it at Epic 4's default set (story 4.1); including everything is then an explicit choice. *(Decided 2026-10-27.)*
- The Secret Registry's place in the sequence: the composition root creates it before the Run, resolves the passphrase into it and passes it to `open_run`, which adopts it (E002-S01-004, E002-S01-006). This story's root, which predates the Run Context, creates its registry first, before any phase; E002-S01-004 moves the hand-off into `open_run`.
- Refusing or restoring outward or absolute symlinks: they are stored as found. Whether they can be extracted is an Epic 3 / AD-11 decision (ADR-0017 Concern), not this story's.

## Technical acceptance criteria

### Interface contracts

Files added under `src/l3io/wp/backup/`, with the conventions E002-S01-001 records (module docstring naming the AD, `from __future__ import annotations`, `__all__`, no new `__init__.py`, pure layers inside `tools/check_purity.py` and the import-linter contracts).

- **`core/backup.py` — the plan (AD-1).** `build_backup_plan(site: SiteDescriptor, scope: BackupScope, target: StorageTarget, *, encrypted: bool) -> BackupPlan` — pure; `scope` and `encrypted` are required with no default, so no caller selects a scope or skips encryption by omission. `class BackupStep(StrEnum)`: `DUMP`, `COLLECT_SITE_ROOT`, `ENCRYPT`, `WRITE_ARCHIVE`, `VERIFY`, `PUBLISH`. Frozen `BackupPlan(scope: BackupScope, target: StorageTarget, steps: tuple[BackupStep, ...])`. For `ALL`: `DUMP, COLLECT_SITE_ROOT, [ENCRYPT,] WRITE_ARCHIVE, VERIFY, PUBLISH`, with `ENCRYPT` present iff `encrypted`. The core never receives a filesystem path it did not get from its arguments (AD-12). E002-S01-002 adds the per-scope plans; E002-S02-007 adds `required_tools` to `BackupPlan`, and the active exclusion set (`exclusion_source`, `exclusion_patterns`) to both `build_backup_plan` and `BackupPlan`, so a Dry Run reports it.
- **`adapters/tar.py` — the writer and the Site Root traversal.**
  - `collect_site_root(site_root: Path, policy: ExclusionPolicy) -> SiteRootCollection` (`.members: tuple[ArchiveMemberSource, ...]`, `.excluded: tuple[ExcludedEntry, ...]`). It walks with `os.scandir`, never following a symlink, and calls `policy.decide` once per entry **before** descending; an excluded directory is pruned unlisted and only the top-most pruned path is recorded. `wp-config.php` at the Site Root is never excluded: the traversal checks the path itself and ignores `excluded=True` for it. `INCLUDE_EVERYTHING` is the policy whose `decide` always returns `excluded=False`. Per ADR-0017: every directory (the Site Root included, empty or not) becomes a `dir` entry; a symlink becomes a `symlink` entry with `os.readlink`'s target, and one whose target is absolute or resolves outside the Site Root is logged at WARNING `symlink_outside_site_root`; a path whose inode has more than one link becomes an ordinary `file` with its full content (a regular `TarInfo` is built, not `tarfile.gettarinfo`'s inode tracking), the dropped relationship logged once per inode with its paths; sockets, FIFOs and devices are skipped and logged, and never indexed.
  - `write_archive(out: IO[bytes], manifest_builder: Callable[[tuple[ManifestMember, ...]], Manifest], members: Iterable[ArchiveMemberSource], *, workspace: Path, cipher: PayloadCipher | None) -> Manifest` *(ADR-0024)*. `manifest_builder` is supplied by the executor: given the member index the writer computed, it returns the `Manifest` (the executor fills `created_at`, `backup_scope`, `source`, `origin`, `exclusions`, `config_path`, `dump_present`); the writer then sets `encrypted` and `payload` with `dataclasses.replace`. Three steps, in order. (1) **The payload**, written into `workspace` with `tarfile.open(<workspace>/payload.tar.gz, mode="w:gz")`: the `dump` member first, then the `config` member (`config/wp-config.php`, the located file, never as a `../` path — an in-root config also travels inside the `site-root` tree), then `site-root/…` in sorted order (a directory before its contents). A file whose size changes while it is written fails the backup naming it. (2) **With a cipher**, the payload is streamed once through `cipher.encrypt(reader, writer)` into `<workspace>/payload.tar.gz.age` and the plain payload is deleted; without one, the plain payload is the payload. The payload's SHA-256 and size are taken over the bytes as stored, as they are written. (3) **The Archive**, an uncompressed tar (`tarfile.open(fileobj=out, mode="w|")`): `manifest.json` first, then the payload member, copied in fixed-size chunks and deleted from the workspace once copied. *(Phases, corrected 2026-11-07 against `adapters/tar.py`: `TarArchiveWriter.write` calls `write_archive` inside its own `phase("WRITE_ARCHIVE")`, so steps (1) and (3) — the inner payload and the outer Archive — are recorded by `WRITE_ARCHIVE`, whose `bytes` is the payload size; step (2) emits `ENCRYPT` through its own `phase("ENCRYPT")`, nested inside `WRITE_ARCHIVE`, with the encrypted bytes. Site Root collection runs before both, inside `COLLECT_SITE_ROOT`.)* Workspace disk use is bounded by the Dump plus about two compressed payloads at the encryption step; memory stays bounded (every copy is a fixed-size chunked stream). The bound is stated in the docstring. `manifest.json` never passes through the cipher.
  - `structural_check(path: Path) -> None` — the publish gate's verifier **until E002-S01-003 lands**: it reads the staged file in stream mode and raises `ArchiveWriteError(reason="structural check failed")` unless `manifest.json` is the first member and parses, and the only other member is the payload the Manifest names *(ADR-0024)*. E002-S01-003 replaces this binding with `verify_archive` and deletes `structural_check`.
- **`adapters/store.py` — `LocalArchiveStore` (AD-20, AG-21).** Implements `ArchiveStoreQuery` and `ArchiveStoreCommand`. `__init__(self, *, verify: Callable[[Path], None])` — no default, so a store that skips verification cannot be built by omission. `exists(target)` checks the final name. `stage(target)` opens a temporary name **in the destination directory** (same filesystem, so the rename is atomic) with `O_CREAT | O_EXCL` and mode `0600`. `publish()` runs `verify` on the staged file inside `phase("VERIFY")`, then — only on a pass, and refusing with `ArchiveExistsError` if the final name now exists — `os.replace` onto the final name inside `phase("PUBLISH")`, so verification runs exactly once and each step emits its own record. `publish() -> bool` returns `True` once the rename lands (the no-op store's `publish()` returns `False`, ADR-0022) *(corrected 2026-11-07)*. `discard()` removes the temporary file. Any exception between `stage()` and `publish()` calls `discard()` in a `finally`.
- **`adapters/workspace.py` — the per-Run private workspace (AD-12, AG-18).** `run_workspace(parent: Path | None) -> ContextManager[Path]` creates the directory with `tempfile.mkdtemp(prefix="l3io-wp-backup-")` (mode `0700` by construction), yields it, and removes it with `shutil.rmtree` in a `finally` on success **and** failure. `parent` overrides only *where*. The Dump lives only inside it under a per-Run name — never `/tmp/database.sql`. E002-S01-004 moves the workspace under the Run Context.
- **`adapters/phase.py::phase(name: str) -> ContextManager[PhaseRecord]`** — emits on exit one `phase_completed` record with `phase`, `duration_ms` (monotonic clock), `bytes` (set by the step; `0` when not applicable), `outcome` (`ok`/`failed`) and `exit_code`. Every `BackupStep` runs inside it. E002-S01-004 adds the tracing hook; E002-S01-005 supplies the mapped `exit_code` (until then `0` on success, `1` on failure).
- **`cli/backup.py` — the backup composition root.** `cli/parser.py` gains, on the backup subparser, `--wp-dir` (required) and `--archive`, spelled exactly as v0.2.21 (AD-22), and `--wp-config PATH` (an addition AD-22 permits; help: "use this wp-config.php instead of searching for it"). `cli/__init__.py::main` dispatches `backup` to `run_backup(args) -> int`, which: canonicalises `--wp-dir` with `Path.resolve(strict=True)`; splits `--archive` with `urllib.parse.urlsplit` and calls `parse_storage_target` (default `default_archive_name(...)` in the current directory); calls `locate_wp_config(..., stated=args.wp_config)` and `site_descriptor_from_wp_config`; opens `run_workspace`; refuses with `ArchiveExistsError` if `ArchiveStoreQuery.exists(target)`, before any dump; builds the plan; and runs the executor. `execute_backup_plan(plan: BackupPlan, *, site: SiteDescriptor, config: LocatedConfig, workspace: Path, database: DatabaseCommand, store: ArchiveStoreCommand, cipher: PayloadCipher | None, exclusion: ExclusionPolicy, origin: ManifestOrigin | None, now: datetime) -> BackupResult`, frozen `BackupResult(path: PurePosixPath, scope: BackupScope, bytes: int, encrypted: bool)`, runs each step in order inside `phase(step)`: `DUMP` → `database.dump_to(site.database_location(), workspace / <per-Run name>)`; `COLLECT_SITE_ROOT` → `collect_site_root`; `ENCRYPT`/`WRITE_ARCHIVE` → `write_archive` into `store.stage(target).stream`; `VERIFY`/`PUBLISH` → `publish()`. `run_backup` returns `0` on success and non-zero on every failure. E002-S01-004 moves the Run-scoped parts into its `backup()`/`drive_backup` and reduces `run_backup` to argument translation; E002-S02-007 moves the `write_archive` call behind a command port (ADR-0019).

### Error and edge case handling

- Final name already exists: `ArchiveExistsError` (a `RefusedError`) before any dump is taken; checked again at `publish()`.
- Destination directory missing, unwritable, or full (`ENOSPC`) mid-write: `ArchiveWriteError` naming the path; temporary file removed; final name absent.
- Database unreachable, credentials refused, dump failed: E002-S01-001's errors propagate; the staged Archive is discarded and the workspace removed.
- A Site Root file vanishing or changing size while it is written into the payload: the backup fails naming the member; never silently skipped or published short *(ADR-0024)*.
- The verifier fails: no `os.replace`; the staged file is discarded; the verifier's `BackupError` propagates.
- A cipher that raises mid-payload: the workspace payload files and the staged Archive are discarded *(ADR-0024)*; the cipher's own `BackupError` (or `ArchiveWriteError` for an `OSError`) propagates.
- An `ExclusionPolicy` that raises: the backup fails naming the path being decided; it is never treated as "include".
- Symlinks are never followed; an outward or absolute one is stored as a link with a WARNING. A hard-linked pair is stored as two files. Special files are skipped and logged.
- Empty Site Root apart from `wp-config.php`, an empty database, and an empty subdirectory: all produce a valid Archive, the empty directory as a `dir` entry (boundary).
- `--wp-config` handling and the `wp-config.php` search: as E002-S01-001 defines.

### Observability requirements

- Every `BackupStep` emits one `phase_completed` through `adapters/phase.py` with `phase`, `duration_ms`, `bytes`, `outcome` and `exit_code` — the fields E002-S01-004 requires, so that story binds the Run ID onto records that already exist. `VERIFY` and `PUBLISH` are emitted from inside `publish()`, once each, and `LocalArchiveStore.publish()` returns `True` once the `os.replace` has landed (the port's `-> bool`, E002-S01-001) *(pre-build re-check MAJOR 2, 2026-11-03)*.
- On success: the Archive's final path, format version (`1`), member count by kind and total bytes. WARNINGs `symlink_outside_site_root`, `hard_link_stored_as_file` and `special_file_skipped` name the paths.
- Loggers via `structlog.get_logger(__name__)`; nothing here configures logging (AD-10).

### Security considerations

- The Dump lives only in the `0700` workspace, written `0600` by database; the staged Archive is created `0600`; the published Archive keeps `0600` (it contains the whole database — PRD §7.2).
- Site Root traversal never follows a symlink out of the tree; member paths come only from `member_path`.
- `MYSQL_PWD` is never set; no argument vector or option file is built here (ADR-0015).
- On the encrypted path the Manifest names no recipient and no key material (ADR-0014); asserted by the encrypted writer test.

### Testability approach

- `tests/unit/core/test_backup_plan.py`: step order for `ALL`; `ENCRYPT` present iff `encrypted=True`, in position.
- `tests/adapters/test_tar_writer.py`: the outer tar is uncompressed and holds exactly `manifest.json` then `payload.tar.gz`; the payload is gzip and its first member is the `dump` member; the Manifest's `payload.size` and `payload.sha256` equal the stored payload's; a file changing size while written fails; inner members and index entries correspond one-to-one *(ADR-0024)*; an empty directory is a `dir` entry; a relative symlink is a `symlink` entry whose tar link name equals `link_target`; an absolute symlink is stored and logged at WARNING; a hard-linked pair is two `file` members with equal content and no `LNKTYPE` member; a socket is skipped and logged; an out-of-root config produces `config/wp-config.php`, no member path contains `..`, and `config_path == "../wp-config.php"`; an in-root config produces both the `config` member and `site-root/wp-config.php` with equal content. An encrypted case driven by a **test-only reversible `PayloadCipher` double** (e.g. XOR with a constant, defined in `tests/`): the payload member is `payload.tar.gz.age`, `encrypted: true`, its checksum over the stored bytes, and it reverses to a gzip tar equal to the plain case's members; the Manifest plaintext and free of key material; the cipher called once; the workspace empty afterwards *(ADR-0024)*.
- `tests/adapters/test_tar_traversal.py`: a recording `ExclusionPolicy` sees each entry once and never a pruned directory's children; `excluded` lists only top-most pruned paths; a policy returning `excluded=True` for `wp-config.php` does not remove it.
- `tests/adapters/test_local_store.py`: a failed write leaves no final name; an existing final name is refused; `os.replace` happens only after the verifier passes (a verifier double that fails); the verifier is called exactly once; `discard` on exception.
- `tests/adapters/test_workspace.py`: mode `0700`; removed on success and on an exception.
- `tests/integration/test_backup_end_to_end.py` (`@pytest.mark.integration`, CI MySQL 8.4 / MariaDB 11.4, `tests/data/wp-config.php`): one Archive; outer members `manifest.json`, `payload.tar.gz`, and inner members `dump/…`, `config/…`, `site-root/…` *(ADR-0024)*; mtimes, a `CHECKSUM TABLE` over every table and the `wp-config.php` bytes identical before and after; a verifier forced to fail leaves no final name.
- **AD-21:** `tests/contracts/test_streaming.py`'s tripwire (retargeted by E002-S01-001 to fire when `adapters/tar.py` defines `write_archive`) is **replaced**, as its docstring directs, by a test that drives the real backup path against a site whose Site Root and Dump total at least 10× `RSS_BOUND_BYTES` and asserts peak RSS stays under the bound, keeping the existing two-way calibration.
