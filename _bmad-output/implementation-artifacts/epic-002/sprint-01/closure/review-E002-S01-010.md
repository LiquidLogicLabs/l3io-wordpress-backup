## Findings

### F-01 — HIGH — kind: claim — `tests/contracts/test_streaming.py:161-162` (with `:209-227`)

**Problem.** The AD-21 test builds its "ten times the bound" site from `_fill`, which writes `b"\xa5" * MIB` blocks. That data compresses about 1000:1, so the 256 MiB Site Root and Dump become a payload of about 255 KiB, and the Archive is about 256 KiB. Of the paths the AC names, only reading input files and gzip-compressing them ever handles large data. Three paths only ever see a few hundred KiB:

- the outer copy of the payload into the Archive (`_write_outer`);
- the verifier's payload read (`structural_check` → `hashlib.file_digest`);
- the staged-file write (`_DestinationWriter`).

A `payload.read_bytes()` in `_write_outer`, or a `body.read()` in `_check`, would buffer the whole payload and still pass. The scope assertion (`indexed_bytes >= 10 * RSS_BOUND_BYTES`) measures the *input*, not the Archive, so it does not catch this.

The AC is contradicted. It says: "no step reads the whole Archive or Dump into memory: peak RSS stays under the AD-21 bound for a site ten times larger than it". The test's Archive is about 1% of the bound.

**Why it matters.** This is the false-green failure mode the global rules single out. A guard that reports AD-21 as satisfied cannot see a regression in two of the three byte-moving steps.

**Fix.**
1. Fill at least the Site Root file with incompressible bytes, generated in chunks so the parent's RSS stays flat (for example `random.Random(seed).randbytes(MIB)` per block, or `os.urandom(MIB)`).
2. Assert on the *output* as well. Report `Path(final).stat().st_size` and the Manifest's `payload.size` from the child, and assert both are `>= 10 * RSS_BOUND_BYTES`.
3. Optionally, plant a scope attack: monkeypatch `_write_outer`'s copy (or `structural_check`) in a child run to read the payload whole, and assert that the bound is breached.

### F-02 — HIGH — kind: claim — `src/l3io/wp/backup/adapters/tar.py:286-302` and `:150-155`, `:217`

**Problem.** `collect_site_root` checks each entry with `lstat`. The writer reopens each file **by path** much later: after the whole traversal and after every earlier member has been written. `_add_file` uses `os.open(member.source, O_RDONLY | O_NOFOLLOW)`, and `O_NOFOLLOW` guards only the final component. If any parent directory is replaced by a symlink in that window, the open follows it out of the Site Root. The only check after opening is `S_ISREG` and an equal size. The size of almost any file is visible to an unprivileged user through `stat`, so it is easy to match.

Reproduced: with `site/up/` swapped for a symlink to an outside directory after collection, `site-root/up/f.txt` in the Archive holds the outside file's bytes.

The traversal has the same window. After `entry.stat(follow_symlinks=False)` reports a directory, `_scan(Path(entry.path))` calls `os.scandir(path)`, which follows a symlink swapped in at that path. The traversal then descends outside the tree and lists outside files as `site-root/...` members.

The security AC is contradicted. It says: "Site Root traversal never follows a symlink out of the tree". The AC is also clear that symlinks are "never followed".

**Why it matters.** A backup usually runs with more privilege than the web server user who can write the Site Root (for example, a compromised plugin). Such a user can get root-only files copied into the Archive. A later restore writes those files into the Site, where that user can read them.

**Fix.** Bind every reopen to the inode that was checked:
- Record `(st_dev, st_ino)` on `ArchiveMemberSource` at collection.
- In `_add_file`, after `os.fstat`, refuse with `_member_changed` unless `(st_dev, st_ino)` match.
- For the traversal, open each directory with `os.open(path, O_RDONLY | O_DIRECTORY | O_NOFOLLOW)`, check its `fstat` inode against the entry's `lstat`, and call `os.scandir(fd)`. A file-descriptor walk with `dir_fd=` throughout is the stronger option.

Add a test that swaps a directory for a symlink between collection and write, using the monkeypatch hook style of `test_a_write_failure_discards_the_staged_archive`, and assert that the backup fails naming the member.

### F-03 — MEDIUM — kind: correctness — `src/l3io/wp/backup/cli/backup.py:222-225`

**Problem.** `_target` passes the operator's `--archive` text through `urlsplit` and keeps only `scheme` and `path`. For a bare path this silently changes the destination:
- `#` starts a fragment and `?` starts a query, so `--archive /backups/site#1.tar.gz` writes `/backups/site`;
- `file://host/x.tar` drops `host` and writes `/x.tar` locally;
- `file:///a%20b.tar` is not percent-decoded, so the name is literally `a%20b.tar`.

Each case exits `0` and prints the path it used, so nothing visible says the destination differs from the one asked for. AD-22 freezes `--archive` as v0.2.21 spelled it, and a v0.2.21 operator's bare path containing `#` or `?` is a legitimate filename.

**Why it matters.** Retention and offsite-copy scripts look for the name they passed, find nothing, and the operator believes the backup is missing. The existence refusal also checks the wrong name.

**Fix.** Refuse instead of reinterpreting. If `parts.netloc not in ("", "localhost")`, or `parts.query`, or `parts.fragment` is non-empty, raise `UsageError` naming the text. Alternatively, only split when the text has an explicit scheme (`"://" in text` or `text.startswith("file:")`) and pass a bare path through unchanged. Unquote `file:` URL paths with `urllib.parse.unquote`. Add one CLI test each for `#`, `?` and a non-empty netloc.

### F-04 — MEDIUM — kind: contract — `src/l3io/wp/backup/cli/backup.py:86-87` (and `adapters/tar.py:79`)

**Problem.** The inner member names `dump/database.sql` and `config/wp-config.php` are partly defined in the composition root. `DUMP_NAME = "database.sql"` and `_CONFIG_NAME = "wp-config.php"` are passed to `member_path`, so `domain/archive_format.py` owns only the role prefixes. ### F-06 — LOW — kind: claim — `src/l3io/wp/backup/adapters/tar.py:17-18`

### F-07 — LOW — kind: correctness — `src/l3io/wp/backup/adapters/store.py:114-123`

**Problem.** `_rename` checks `_occupied(final)` and then calls `Path.replace`. A file created at the final name between the two calls is silently overwritten. The story prescribes "refusing … if the final name now exists — `os.replace`", and the Site Lock is E002-S02-008, so the exposure is narrow: two concurrent runs with the same `--archive`.

**Fix.** An atomic no-clobber is available in the stdlib with the same same-directory guarantee: `os.link(staged, final)` (fails with `EEXIST`), then `staged.unlink()`. Map `FileExistsError` to `ArchiveExistsError`. If `os.replace` is kept deliberately, record the residual race in the docstring.

### F-08 — LOW — kind: security — `src/l3io/wp/backup/adapters/workspace.py:98-100`

**Problem.** `shutil.rmtree(created, ignore_errors=True)` followed by a WARNING means that a workspace which cannot be removed keeps the plaintext Dump (the whole database) under `$TMPDIR`, while `run_backup` returns `0`. The AC says "removes it with `shutil.rmtree` in a `finally` on success **and** failure", and the Outcome says "removes its workspace". A leftover Dump is reported only as a log line.
