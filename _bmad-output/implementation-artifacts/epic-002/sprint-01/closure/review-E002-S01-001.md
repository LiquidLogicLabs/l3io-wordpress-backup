## Findings

### F-01 — MEDIUM — kind: correctness — `src/l3io/wp/backup/domain/archive_format.py:260`

**Problem.** `manifest_to_json` calls `json.dumps(..., ensure_ascii=False)`. On Linux, a Site file whose name is not valid UTF-8 (common for old Latin-1 uploads) reaches Python as a lone surrogate (`os.fsdecode(b"caf\xe9.jpg")` gives `'caf\udce9.jpg'`). With `ensure_ascii=False` that surrogate goes into the JSON text unescaped, so writing the Manifest as UTF-8 raises `UnicodeEncodeError: surrogates not allowed`. I confirmed this with a snippet. With the default `ensure_ascii=True`, the surrogate is written as `\udce9`, and `json.loads` returns the original string exactly. ADR-0017 freezes the v1 format at first release, so this encoding choice cannot change after release. The golden string is pure ASCII, so the test does not notice either way.

**Fix.** Drop `ensure_ascii=False`, so stdlib `json`'s default escaping is the v1 encoding. Add a round-trip test with a member path from `os.fsdecode(b"site-root/caf\xe9.jpg")` that encodes the serialised text with `.encode("utf-8")`.

### F-02 — MEDIUM — kind: claim — `src/l3io/wp/backup/adapters/database.py:272-277`

**Claim (AD-14, Interface contracts):** "Every exception from `l3io.wp.database` … reaching a public boundary is re-raised as one of these with `raise ... from`."

**Problem.** `WpDatabase.check_dump` catches only `wpdb.DatabaseUnreachableError` and `wpdb.AuthenticationFailedError`. Database's `_dump_plan` (in `transfer.py`) passes a mid-session `pymysql` error through `_as_package_error`, which returns `AccessDeniedError` for `ER_TABLEACCESS_DENIED`/`ER_DBACCESS_DENIED`. That exception, and any other `wpdb.DatabaseError`, escapes the port unwrapped. `dump_to`, beside it, ends with a catch-all `except wpdb.DatabaseError`; `check_dump` has no equivalent.

**Fix.** Give `check_dump` the same tail as `dump_to`: map `AccessDeniedError` to `DatabaseRefusedError(findings=("missing_privilege",))`, map `MissingDependencyError` to `MissingExtraError`, and finish with `except wpdb.DatabaseError` re-raised as a package error. Add a double test that makes `wpdb.check_dump` raise `wpdb.AccessDeniedError` and asserts the error is a `BackupError` whose `__cause__` is set.

### F-03 — MEDIUM — kind: correctness (deviation 8) — `src/l3io/wp/backup/adapters/database.py:187-189`

**Problem.** `_parse` is the shared path for both descriptor constructors, and it now calls `config.resolve()`. Any `wp-config.php` that does not define the credential pair as literals therefore cannot produce a Site Descriptor. That includes a config that defines neither key, which raises `CredentialsAbsentError` and then `CredentialsError`, and a config that pulls credentials from a sourced secrets file. The story says credentials come from `wp-config.php` only "with no Credential Provider given". E002-S01-006 (explicit spec) and Epic 5 (environment, AWS) provide credentials from elsewhere, and on those paths the descriptor, which carries no credential, would still be refused. The same applies to `site_descriptor_from_archive_config` for a restore target. The eager call adds only the missing-key name: `check_dump`'s `_resolve_or_finding` already reports a half pair as a `credentials_unobtainable` blocker before anything runs.

**Fix.** Keep `_parse` credential-free: connection, prefix and URLs only. Move the eager `resolve()` into a separate function, for example `require_wp_config_credentials(source)`, which raises `CredentialsError(missing_key=...)`, and call it only where `wp-config.php` is chosen as the Credential Provider. Move `test_half_a_credential_pair_names_the_key_not_the_value` to that function, and add a test that a config with no `DB_USER`/`DB_PASSWORD` still produces a descriptor.

### F-04 — MEDIUM — kind: scope — `tests/contracts/test_port_types.py:53-72`

**Problem.** The AD-21 guard only looks at functions and property getters in `vars(protocol)`. Two gaps let a violation through:
1. **Data-attribute annotations are not examined.** A Protocol member declared as `stream: bytes` or `body: bytes` has no entry in `vars()`, only in `__annotations__`, so the guard passes it. That is exactly how `StagedArchive.stream` could have been written.
2. **Container types are not examined.** `_is_bytes` recurses only into `Union`, so `list[bytes]`, `tuple[bytes, ...]`, `Sequence[bytes]` and `dict[str, bytes]` all pass, and each of them buffers bytes whole.

The planted test attacks nesting and properties but not either gap.

**Fix.** Also check `typing.get_type_hints(protocol)` (class-level annotations). Recurse through `typing.get_args` for every generic except an explicit streaming allow-list (`IO`, `BinaryIO`, `Iterator`/`Iterable` if chunked iteration is meant to be allowed; state the choice in the docstring). Plant `data: bytes` and `def all(self) -> list[bytes]` in the planted tree and assert both are reported.

### F-05 — MEDIUM — kind: deletion — confidence: medium — `tests/contracts/test_extraction.py:114`, `tests/contracts/test_streaming.py:134`

**Problem.** Both tripwires used to fire on a scope derived from the tree: "any adapter module" and "any port module". They now fire only if a hand-picked function name (`extract_archive` or `write_archive`) appears in a hand-picked file (`adapters/tar.py`). This retarget is what the story prescribes. Even so, the tripwire now detects the event only by a naming coincidence. If E002-S01-003 or E002-S01-010 puts the code in `adapters/archive.py`, names it `extract`/`write`, or binds it as `extract_archive = _impl`, the tripwire stays green while the real code lands with only stdlib-level tests. That is a silent false green. The planted tests attack spellings inside `tar.py`, not the file or name choice. Under the old scope (any adapter) the tripwire would have fired anywhere. So each tripwire still fires on the planned spelling of its event, but not on the event itself.

**Fix.** Key each tripwire on the capability, with scope derived by walking `adapters/`:
- **AD-11:** fail when any adapter module calls `.extract`/`.extractall` or opens a tar for reading. As an AST proxy, use any adapter importing `tarfile` other than through a write-mode `open`.
- **AD-21:** fail when any adapter module imports `tarfile` or `gzip`, or defines a class that structurally provides `ArchiveStoreCommand.stage`.

Plant a violation in a differently named module, for example `adapters/archive.py`, to attack the scope.

### F-06 — LOW — kind: claim — `src/l3io/wp/backup/domain/archive_format.py:268-270`

**Claim (Error handling):** "A Manifest whose `origin.kind` this build does not know: read as `origin=None` **plus a WARNING naming the value**."

**Problem.** `on_unknown` defaults to `None`. A caller that forgets to pass it drops the unknown value silently, and the WARNING never happens. Nothing in this story calls `manifest_from_json` from an adapter, so no test checks that a WARNING is actually logged.

**Fix.** Make `on_unknown` a required keyword argument with no default, so every reader has to choose. Callers that genuinely do not care can pass `lambda *_: None`, which is visible in review.

### F-07 — LOW — kind: correctness — `src/l3io/wp/backup/adapters/database.py:301-307`

**Problem.** `dump_to` maps `wpdb.AccessDeniedError` to `CredentialsError`, whose message is "credentials … unusable". Database raises `AccessDeniedError` when an *authenticated* account lacks a privilege mid-session, so the credentials were accepted. The operator is told to fix the wrong thing.

**Fix.** Map `AccessDeniedError` to `DatabaseRefusedError(findings=("missing_privilege",))`, the same code database uses for the plan-time case, and add a double test.

### F-08 — LOW — kind: correctness — `src/l3io/wp/backup/domain/archive_format.py:382-399`

**Problem.** `_member` accepts any `path` string. When a Manifest is read, an entry such as `{"path": "../../etc/passwd", "role": "dump"}`, or a `site-root/...` path with `role: "config"`, parses without error. Elsewhere this module promises that "inner member names are `member_path`'s role-prefixed names". The verifier (E002-S01-003) will compare the index against the tar, and it will trust a parsed `ManifestMember`.

**Fix.** On read, require `path == role.value` or `path.startswith(role.value + "/")`, and run the remainder through the same checks as `member_path`. Raise `MalformedManifestError` otherwise. Add these two cases to `test_a_malformed_field_is_refused`.

### F-09 — LOW — kind: scope — `tests/contracts/test_archive_format_owner.py:38`

**Problem.** The story describes a grep for `"dump/"`, `"site-root/"` and `"config/"`, but the check matches those role prefixes only at the start of a string constant. `f"{staging}/site-root/{rel}"` and `"./dump/x"` re-spell the format outside its owner and pass. Of the gaps, the module docstring mentions only runtime concatenation.

**Fix.** Match role prefixes as substrings at a path boundary, for example `re.search(r"(^|/)(dump|site-root|config)/", value)`. Plant an f-string with a leading `{root}/` and list it in the expected offenders.

### F-10 — LOW — kind: scope — `tests/adapters/test_descriptor.py:41,190`

**Problem.** `test_a_planted_password_never_reaches_the_manifest` never checks that `PLANTED_PASSWORD` is actually in `tests/data/wp-config.php`. If the fixture's password is changed, the test passes without checking anything.

**Fix.** Add `assert PLANTED_PASSWORD in FIXTURE.read_text(encoding="utf-8")` before the search (and the same in `test_the_live_constructor_reads_the_fixture`).

### F-11 — LOW — kind: testability — `src/l3io/wp/backup/adapters/database.py:251`, `src/l3io/wp/backup/domain/exclusion.py:45`

**Problem.** The docstrings state that `WpDatabase` "implements `DatabaseQuery` and `DatabaseCommand`" and that `IncludeEverything` "satisfies the `ExclusionPolicy` port". Nothing checks either claim. Nothing in `src/` assigns one to the other, so mypy never compares them, and drift, for example a renamed parameter, would surface only in E002-S01-010.

**Fix.** Add typed assignments in a module mypy checks, for example in `adapters/database.py`: `_q: type[DatabaseQuery] = WpDatabase` is not valid, so use a function `def _conforms(db: WpDatabase) -> tuple[DatabaseQuery, DatabaseCommand]: return db, db`. Do the same for `INCLUDE_EVERYTHING` against `ExclusionPolicy`, alongside the port definition outside `domain/`.
