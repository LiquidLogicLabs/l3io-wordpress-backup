## Scope and method

**Seed:** the src diff above and the seven story files in `epic-002/sprint-01/stories/`.

**Widened to, and why:**
- `docs/adr/0009-python-floor-3-11.md` and `docs/adr/0024-one-encrypted-payload-passphrase-only.md`, because H1 and H2 depend on what they decide.
- `pyproject.toml` (`requires-python`) and the dev venv interpreter (3.11.11), for H1.
- The installed dependency `l3io.wp.database` (`.venv/.../l3io/wp/database/identifiers.py`, `transfer.py` grep), because `DB_NAME` and `DB_HOST` cross the trust boundary from `wp-config.php` through it. Only identifier validation was exercised. TLS and the dump subprocess argv were **not** examined (O2).
- The CPython tarfile advisories, by live search (H1).

**Proofs of concept.** Scripts were kept in `/tmp/rt-scripts` and their data in `/tmp`. Each ran with the repo venv's `python -I`. Nothing in the repository was modified apart from this report.
- `forge.py`: a forged v1 Archive (malicious Dump plus a recomputed Manifest digest) verifies as `passed=True, integrity=VERIFIED`. Proves H2.
- `paxbomb.py`: a 388,896-byte gzip Archive drives `verify_archive` from 33 MB to 1,181 MB max RSS. Proves M1.
- `fifo.py`: a file swapped for a FIFO after `collect_site_root` makes `write_archive` block forever. It was killed by an alarm after 5 s. Proves M2.

**Threat model assumed.** The Site Root and `wp-config.php` are writable by the web-server user, who may be compromised (for example, through a plugin). The backup typically runs as root or as a more privileged operator. Archives in backup storage may be writable by others. An Archive handed to `verify` or extract is untrusted (AD-11/AD-23).

## Controls that held (checked, not assumed)

- **Walk races:** the traversal uses `O_NOFOLLOW` and `(dev, ino)` identity on every directory and member. A directory or file swapped for a symlink fails the run.
- **Extraction rules:** extraction refuses hard links, duplicate names, members outside the Manifest index and members below an Archive symlink.
- **Containment re-check:** extraction re-checks containment and runs a header-kind cross-check on v1.
- **Untrusted names:** member names are always `repr()`'d in logs and errors, so untrusted names cannot inject terminal escapes.
- **File modes:** the workspace is `mkdtemp` 0700, and staged and decrypted files are 0600 `O_EXCL`.
- **Exceptions:** non-package exception text is withheld from stderr, and redaction sits last before the renderer for structlog and stdlib records alike.
- **Passphrase:** it is never on argv, is registered before return, and shows only its source in `repr`.

## EXECUTIVE SUMMARY

**Reviewed:** the sprint's 6.1 kLOC Python diff for the backup writer, the Site Root traversal, Archive verification and extraction, the Run Context, the logging and redaction pipeline, credential plumbing and exit codes. The stack is stdlib `tarfile`/`gzip`, structlog and `l3io-wp-database`.

**Overall posture: HIGH.** The traversal and publish paths are carefully hardened against symlink and swap races. The serious risks sit at two trust boundaries the code cannot defend alone: the interpreter's tarfile and the unauthenticated Manifest.

**Most dangerous finding: RT-H1.** The one extraction function's safety depends on a CPython patch level that the declared floor and the dev venv (3.11.11) do not guarantee. A restore run as root over an attacker-writable site can then write outside it.

**Most important recommendation:** add a runtime refusal of unpatched interpreters to `extract_archive`, in the same place it already refuses a missing `data_filter`. Before Epic 3 ships restore, also make restore refuse a plaintext Archive when encryption is expected (RT-H2).
