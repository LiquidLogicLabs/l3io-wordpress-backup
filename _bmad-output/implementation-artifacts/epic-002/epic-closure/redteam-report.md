## Scope and method

**Seeds used:** the cumulative src diff, the 12 sprint stories, ADRs 0014 to 0024, and both sprint red-team reports (to avoid re-raising).

**Widened to, and why:**
- `adapters/database.py` end to end (`site_descriptor_from_archive_config`, `_parse`, `ensure_database`, `drop_database`, `_connection`): the sprint reports covered `wp-config.php` on the live site, not the Archive's config as the source of the database identity.
- `core/verify.py`, `cli/verify.py`, `adapters/tar.py` (`decrypt_payload`, `extract_archive`, `_ExtractFilter`), `domain/archive_format.py` (`ViewMember`, `classify`): to follow what `--authenticate` actually binds.
- `domain/restore.py` (phase order) and `adapters/site_files.py` (`clean`): to see what runs before extraction.
- `cli/__init__.py`, `adapters/workspace.py`, `cli/passphrase.py`, `cli/logging.py`, `adapters/redaction.py`, `adapters/lock.py`, `adapters/store.py`, `adapters/config_writer.py`, `cli/adapter_sets.py`: signals, secrets, logging, lock, publish, config write and the Dry Run / unbound-port composition.
- Dynamic check: one throwaway call to `structlog.dev.ConsoleRenderer` with the repo venv (Python 3.11.15, `os.path.ALLOW_MISSING` present). It refuted a candidate (see "Controls that held"). Nothing in the repository was changed except this report.

**Threat model:** unchanged from the sprint reports. The Site Root and anything the web user can write are attacker-writable. The backup and restore run as a more privileged user. An Archive, or the directory it lives in, may be written by someone else. Archives that are plaintext are unauthenticated by owner decision (ADR-0024, not reopened).

**Not exercised:** no MySQL server was available, so RT-1 is argued from code and the documented behaviour of the client library, not reproduced. The restore driver, the journal adapter and the search-replace adapter do not exist yet (Epic 3 and Epic 7), so their wiring is a recommendation for those epics, not a finding.

| MEDIUM | RT-3 | Extraction has no size, member-count or free-space bound, and it runs after `CLEAN` has already deleted the live files | CHA, ABU, EXT | `RESTORE_PHASE_ORDER` runs `CLEAN` then `EXTRACT` (`domain/restore.py:120-131`). ### Detail for RT-8

`extract_archive(source, destination, view, ...)` receives the `view` made at VERIFY (`adapters/tar.py:1047-1074`) and does not re-read the Manifest of the file it opens, so a replaced plaintext Archive whose member names stay within the old index is extracted unchecked. For a v1 Archive whose names differ, the index check refuses (`ExtractionRefusedError`, "not in the member index"); only same-name content swaps pass.

## Controls that held (checked, not assumed)

- **Console log injection (candidate refuted):** `symlink_outside_site_root` and `special_file_skipped` log attacker-chosen file names and link targets unescaped (`adapters/tar.py:298,339`), and `member_path` allows control characters and newlines. Test: `structlog.dev.ConsoleRenderer` rendered a value holding ESC, BEL and a newline as `path='a\x1b]0;pwn\x07\nINFO fake line'`, so strings are `repr`'d and JSON escapes them. No terminal-escape or log-line forgery. Not a finding.
- **Site Lock:** `O_NOFOLLOW`, 0600, directory 0700, hashed name, record read capped at 64 KiB, release unlinks the record while still holding the lock, in-process re-entry only for the same `run_id` (`adapters/lock.py`). Advisory and per-user (sprint 02 RT-4, RT-9).
- **Publish:** staged file by `mkstemp` (0600), verified before rename, discarded on any failure; no-clobber check (race is sprint 01 RT-L1) (`adapters/store.py`).
- **Extraction filter:** hard links refused, duplicate names refused, names outside the index refused, members below an Archive symlink refused, header kind cross-checked for v1, exclusion also checked after resolve, and the filter's directory fix-up second call handled (`adapters/tar.py:932-1037`). Capability gate on `os.path.ALLOW_MISSING` is present (owner decision, not reopened).
- **Exceptions and secrets in output:** only `BackupError` text is printed; others are named by class (`cli/exit.py`). Redaction runs last before the renderer, covers repr and JSON spellings, and every live registry (`adapters/redaction.py`). The passphrase and administrator password are registered before use (`cli/passphrase.py`, `adapters/database.py:_explicit`). `PassphraseCipher.__repr__` and `ResolvedPassphrase.__repr__` hide the value.
- **Journal values:** `DB_PASSWORD` cannot enter a `JournalHeader`; the mappings are read-only after validation (`domain/journal.py`).
- **Unbound ports fail closed:** `UnboundAdapterError` on every method; no silent no-op in a real Run (`cli/adapter_sets.py`).
- **Config write:** owner and mode preserved or refuse, read-back check, temp file removed on failure (`adapters/config_writer.py:replace_file`).

## EXECUTIVE SUMMARY

**Reviewed:** epic E002 as a whole: the `l3io-wordpress-backup` Python 3.11 package after both sprints (backup writer, verify and authenticate, tar probe and the single extraction function, Site Lock, Run Context and journal values, redaction and passphrase chain, CLI composition and Dry Run, database and config restore adapters), 58 source files and ADRs 0014 to 0024.

**Overall posture: HIGH, carried by the two open sprint HIGH findings.** This pass added no CRITICAL or HIGH, four MEDIUM, four LOW and four OBSERVATION. The code is careful at its local boundaries: the walk, publish, lock, extraction filter and redaction all held under review. The new risk sits **between** the pieces, where one component trusts a value another produced: the Archive's config choosing the database server (RT-1), the unauthenticated Manifest steering authenticated payload (RT-2), a payload extracted with no bound after the site was cleaned (RT-3), and the key left in the environment of children (RT-4).

**Most dangerous finding: RT-1.** A forged or tampered Archive can send the database administrator password to a server of its choice, or aim a drop at another site's database, because restore to a bare target takes its database identity from the Archive. It rests on the plaintext Archive being forgeable (an accepted, documented trade-off), so the fix is to stop the Archive deciding.

**Most important recommendation:** before Epic 3 wires restore, make the restore driver take the database host, name and user from the operator or the target, refuse an Archive-supplied value without confirmation, add an expansion and free-space preflight ahead of `CLEAN`, and bind the Manifest into the encrypted payload when E004 adds backup encryption.
