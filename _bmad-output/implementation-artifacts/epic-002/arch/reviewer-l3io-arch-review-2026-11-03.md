# E002 pre-build re-check — l3io-arch-review

Executive summary: the owner decisions (ADR-0024 payload layout, ADR-0020–0023, the ADR-0017 symlink amendment, `BackupError.snapshot_path`, `performed`, config v0.1.3) are applied consistently across the 10 edited stories, with two exceptions that would cost rework. First, ADR-0024 moved the hard-link refusal off Verification. The mechanism the stories now name, `tarfile`'s `data` filter, does not refuse a hard link inside the destination. Second, `performed` is defined as `StagedArchive.publish()`'s return value, but the port that owns `publish()` still declares `-> None`. No cross-epic leak: every `depends_on` in `state/planned/epic-002/` stays inside E002, and every E003/E004/E005/E008 mention is a forward reference or a test double. Sprint order holds: `PayloadCipher`, `decrypt_payload`, `INCLUDE_EVERYTHING`, `Redactor` and `PassphraseRequiredError` all land in sprint 01 with doubles. `resolve`, `save_copy`, `replace_file`, `ConfigPolicy` and `phase_undo` land in sprint 02, behind S02-011 → S02-012 → S02-009. ## Findings

MAJOR: [AD-11 / ADR-0017 "hard links anywhere" / standards-core design-by-contract] E002-S01-003:67 says a hard link "in any position" still refuses the Archive, and that "the decision is taken on the exception `data_filter` raised". E002-S01-003:85 says "Inside the payload, a hard link … is refused at extraction by the `data` filter". `tarfile.data_filter` refuses only links whose target is absolute or outside the destination. A hard link to a path inside the destination passes. Before ADR-0024, Verification caught every `HARDLINK` member (`UNSUPPORTED_MEMBER_TYPE`). Under ADR-0024 the inner tar is no longer verified, so nothing enforces the rule ADR-0017's 2026-10-29 amendment keeps "unchanged". A crafted payload with an in-destination hard link, for example one pointing at the kept `wp-config.php`, followed by a file member written through it, would extract. Remediation: in the filter callable, refuse `TarInfo.islnk()` explicitly before or after delegating to `data_filter`. This is a type check, not a second containment filter. Correct lines :67 and :85. Add a planted in-destination hard link inside the payload to `tests/contracts/test_extraction.py` (E002-S01-003:125, which today plants only an *escaping* hard link, so the guard's scope is untested).
MAJOR: [contract consistency — two signatures for one method] E002-S01-001:77 declares `StagedArchive.publish() -> None`. E002-S01-004:64, in sprint 01, defines `BackupResult.performed` as "the value `StagedArchive.publish()` returns". E002-S02-007:57 has the no-op return `False` and says "the real one returns `True`". E002-S01-010:66, the real `LocalArchiveStore.publish()`, states no return value. A sprint-01 dev on S01-004 must silently change a port owned by S01-001, or derive `performed` some other way. Remediation: change E002-S01-001:77 to `.publish() -> bool` ("`True` when the Archive was published"), and have E002-S01-010:66 state that `LocalArchiveStore.publish()` returns `True` after the `os.replace`.
MINOR: [type design] E002-S01-001:71 makes `Manifest.payload: ManifestPayload` and `encrypted` required. E002-S01-010:64 has `manifest_builder` return a `Manifest` before the payload exists, which the writer then patches with `dataclasses.replace`. E002-S02-007:57's `NoopArchiveWriter` returns a Manifest "built from an empty index" with no payload. Both callers must invent a placeholder `ManifestPayload`. Remediation: either have the builder take `(members, payload, encrypted)`, or state the placeholder (e.g. `ManifestPayload(name=PAYLOAD_MEMBER, size=0, sha256="")`) once in E002-S01-001.
MINOR: [AD-11 untrusted input] E002-S01-003:61's keyless v1 rules check that the payload the Manifest names is present, with its size and checksum. They do not check that `payload.name` is one of `PAYLOAD_MEMBER`/`ENCRYPTED_PAYLOAD_MEMBER` and agrees with `encrypted`. A Manifest saying `encrypted: false` over an `.age` payload passes Verification and fails only at extraction. Remediation: add "`payload.name` equals the constant for `encrypted`, else `UNREADABLE`" to the v1 rules and to the `test_verify.py` case table.
MINOR: [observability / AD-1 phase records] E002-S01-010:69 maps `ENCRYPT`/`WRITE_ARCHIVE` to one `write_archive` call run "inside `phase(step)`". Under ADR-0024 the work is: write the inner payload, then encrypt it, then copy it into the outer tar (E002-S01-010:64). The story does not say which phase brackets the inner-payload write, or where the `ENCRYPT` record is emitted from inside the call. E002-S02-007:54 then expects `TarArchiveWriter` to emit both. Remediation: state in E002-S01-010:64 that `write_archive` emits `ENCRYPT` around step (2) and `WRITE_ARCHIVE` around steps (1) and (3), or accept a `phase` callback.
MINOR: [superseded text left in place] E002-S01-010:26–27 still state the pre-ADR-0024 layout ("a gzipped tar whose first member is `manifest.json`, followed by the `config` member…", "every file member's checksum"). The note at :32 marks them superseded, but QA reads the AC lines. Remediation: rewrite the two AC lines to the outer-tar/payload layout and drop the note.
MINOR: [superseded text left in place] E002-S01-003:42, a non-goal, still says out-of-destination symlinks are something "`tarfile`'s `data` filter refuses at extraction" and that the decision is Epic 3's. E002-S01-003:67 now decides it here (skip and warn). Remediation: replace :42 with a pointer to :67 and the ADR-0017 2026-10-28 amendment.
MINOR: [dependency-baseline drift] The owner pinned database v0.2.1 and config v0.1.3 from TestPyPI (`pyproject.toml:76–79`, `>=0.2.1,<0.3` / `>=0.1.3,<0.2`). The stories still name database **v0.2.0** with extra `>=0.2.0,<0.3` (E002-S01-001:59, :145; E002-S02-009:51, :106; E002-S02-012:113, among others), config v0.1.1 (E002-S01-001:146) and config v0.1.2 (E002-S02-009:106; E002-S02-012:113). The signatures are unaffected, because v0.2.1 has the same `src/` as v0.2.0. But a dev aligning `pyproject.toml` to the story baseline would pin a version that is not on TestPyPI. Remediation: change the baseline paragraph E002-S01-001:59 to "database v0.2.1 (same source as v0.2.0), extra `>=0.2.1,<0.3`", and make the two "v0.1.2" lines "v0.1.3".
MINOR: [contract gap] E002-S01-004:57 has `join_or_open` forward exactly `tracer`, `secrets` and `command_args` to `open_run`. E002-S02-007:59 adds `dry_run` to `open_run` and has `drive_backup` select by `request.dry_run`, but does not add `dry_run` to `join_or_open`. Remediation: E002-S02-007:59 adds `dry_run: bool = False` to `join_or_open` and its forwarding list.
MINOR: [clarity] E002-S01-004:65 reduces both `run_backup` and `run_verify` to "argument translation (… the passphrase and cipher resolved into that registry)". Verification is keyless, `VerifyRequest` carries no cipher (same line), and `--encrypt-with-passphrase` is backup-only (E002-S02-011:68). Remediation: say `run_verify` creates the registry and resolves no passphrase.
MINOR: [operator-facing naming] Under ADR-0024 the outer Archive is an **uncompressed** tar (E002-S01-001:67), but `default_archive_name` still yields `wpbackup2-<db>-<ts>.tar.gz` (E002-S01-001:73), and the committed fixture is `tests/fixtures/archives/v1/minimal.tar.gz` (E002-S01-003:127). Detection ignores extensions, so behaviour is correct, but `tar xzf` on a default-named v1 Archive fails. Remediation: record the choice. Either keep the frozen legacy name and say in the operator docs that the outer tar is plain, or name the fixture `minimal.tar`. This is not a reopening of ADR-0024.
