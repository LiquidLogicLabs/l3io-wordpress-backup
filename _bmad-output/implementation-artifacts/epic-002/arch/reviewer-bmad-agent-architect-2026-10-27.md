## Findings

BLOCKER: Sprint 01 cannot close green as written, because sprint-01 stories require artifacts that only sprint 02 delivers (AG-28 has come back in a new form). Five cases. (1) E002-S01-005 §Testability `tests/unit/cli/test_exit_mapping.py` requires "one end-to-end CLI case per `ExitCode` member except `OK` … a member with no reachable case fails the test". `LOCKED` is reachable only through `SiteLockedError`, and E002-S02-008 §Testability says itself that it supplies that case. (2) E002-S01-005 §Interface contracts maps `SiteLockedError` (S02-008) and `PreflightFailedError` (S02-007) as if they already exist. (3) E002-S01-004 §Interface contracts (2026-10-27) has `drive_backup` select `real_adapters(...)`/`dry_run_adapters(...)` by `request.dry_run`, and both constructors are S02-007's. (4) E002-S01-004 §Testability `test_backup_entry.py` asserts "acquires no lock … (E002-S02-008)". (5) E002-S01-004 §Testability `test_tracing_hooks.py` asserts the span is "entered before the lock (a recording `SiteLock` …)" and that `set_outcome` runs "on lock refusal". Remedy: mark each of these as delivered by the sprint-02 story that owns the type (S02-007 adds the dry-run selection and its test; S02-008 adds the `LOCKED` case, the lock-order assertions and the mapping), or move `SiteLockedError`/`PreflightFailedError` into S01-001's `domain/errors.py` list.
MAJOR: Two stories own `AdapterSet`, and its construction order contradicts the Run Context. E002-S01-004 §Interface contracts types `RunContext.adapters: AdapterSet` (frozen) and `open_run(*, adapters: AdapterSet, …)`. E002-S02-007 §Interface contracts says S02-007 defines `AdapterSet` and its only two constructors. No sprint-01 story defines the type that sprint 01's Run Context carries. Separately, `drive_backup`'s mandated order in S01-004 is: `join_or_open(ctx, adapters=..., site_root=…)` and the lock, then `locate_wp_config`, then the descriptor, then the WordPress source, then `real_adapters(...)`. The adapter set is therefore passed to `open_run` before it can be built: it needs the credential source, and S02-008 requires the lock to be taken before credentials. Remedy: name S01-004 as the owner of a minimal `AdapterSet`, which S02-007 then extends, and remove `adapters` from `open_run`/`RunContext` construction (bind it afterwards, e.g. `dataclasses.replace` or a separate field set by the driver).
MAJOR: The intra-sprint dependency graph contains a cycle and is missing edges. E002-S01-006 (state `depends_on: [S01-001]`, scheduled before S01-004 and S01-005) defines `PassphraseUnavailableError(UsageError)` and makes a lone admin half a `UsageError`, and its `test_credentials.py` reads "the accepted-and-explained set, E002-S01-005". `UsageError` and that set are both S01-005's, and S01-005 `depends_on` S01-006. Missing edges: S01-004 `drive_verify` calls S01-003's `verify_archive`; S01-005 maps S01-003's `VerificationFailedError`/`UnrecognisedArchiveError`; S01-006's `credential_sentinel` runs "verify". Remedy: move `UsageError` into S01-001's error list, and add the S01-003 edges to S01-004, S01-005 and S01-006.
MAJOR: Every E002 story cites a stale `l3io-wordpress-database` version. `pyproject.toml` now pins `>=0.2.0,<0.3` (rev `48a7da9`, commit 49e99de), while the stories say "verified at v0.1.0" and give line numbers. Locations: S01-001 §Interface contracts (`transfer.py` L476, `WpConfigFile` v0.1.0 API) and §Existing-library; S01-001 2026-10-27 addition ("current pin (`47384ba`)"); S01-004 (CLI flags "match v0.1.0"); S01-005 (`cli.Exit` "verified at tag v0.1.0"); S01-006 (AC2 and §Existing-library); S02-007 (`check_dump` at v0.1.0); S02-009 (AC and every signature with its line number). S01-006 also designs a live code path and test around the old version: "Requesting passphrase encryption on `l3io-wordpress-database` < 0.2.0 is refused … `PassphraseEncryptionUnavailableError`", and "on database 0.1.0 that Run is refused — the refusal path is what is asserted clean until 0.2.0". At the current pin that branch is unreachable, so the test asserts nothing. Remedy: re-verify the signatures against v0.2.0, then restate or remove the `< 0.2.0` refusal and the passphrase-variant test.
MAJOR: E002-S02-009 contradicts itself on the config-writer mode test. §Interface contracts says `l3io-wordpress-config` v0.1.1 (`4c842ca`) fixes mode and fsync and is pinned `>=0.1.1,<0.2` (confirmed in `pyproject.toml`). §Testability marks the `0640` mode test and the fsync spy `xfail(strict=True, reason="… v0.1.0 does not preserve mode; fixed in <release>")`. At the pinned release both XPASS, so strict mode fails CI. Remedy: make them ordinary, unmarked tests. This is the NFR-3 release gate, so it must be a real assertion.
MAJOR: Append-only amendments leave earlier canonical signatures in place without marking them superseded, so a dev reading from the top builds the wrong shape first. (a) S01-001 `write_archive(out, manifest, members)` is later `write_archive(out, manifest_builder, members, *, cipher)`. (b) S01-001 `site_descriptor_from_wp_config(site_root)` is later `(site_root, *, config_file)`. (c) S01-002 `build_backup_plan(site, scope: BackupScope, target)` against S01-001's required keyword-only `encrypted` and S02-007's `required_tools`. (d) S01-003 `extract_archive(source, destination, view, *, roles)` is later extended with `exclude`, and `source` is never typed. (e) S01-001 `DatabaseQuery.check_dump(site) -> DumpReadiness` is "this type" `Readiness` in S02-007, but nothing renames it, and S01-001's `dump_to(site: SiteDescriptor, …)` sits beside S02-007's `DatabaseLocation`-keyed methods. (f) S01-005 describes the `match` mapping in full before the later "class attribute is chosen" decision. (g) S01-003 §Error handling still says a "v0 Archive missing `wp-root/` or `database.sql`: fail `MEMBER_MISSING`" above the amendment that passes files-only v0. Remedy: fold each amendment into the original bullet and keep one signature per symbol.
MAJOR: The exit code for three refusals is ambiguous after the class-attribute decision. E002-S01-005's first mapping sends `UnsupportedStorageSchemeError`, "existing final Archive name" and `RunContextActiveError` to `REFUSED`. Under the chosen class-attribute mechanism (same story, later bullet), only `RefusedError` subclasses get `REFUSED`, and S01-001 defines `UnsupportedStorageSchemeError(BackupError)` and `ArchiveWriteError(reason="exists")`, while S01-004 defines `RunContextActiveError(BackupError)`. All three would exit `FAILED`. `ArchiveWriteError` also covers `ENOSPC`, so a class attribute cannot distinguish the two cases. Remedy: make the three refusals `RefusedError` subclasses, with a distinct `ArchiveExistsError(RefusedError)`, in S01-001 and S01-004.
MAJOR: The redaction mechanism violates the layer rules. E002-S01-006 §Interface contracts says "`BackupError.__str__` passes its message through the Run's `redact` when one is active". `BackupError` lives in `domain/errors.py` (S01-001), which may not import `adapters/redaction.py`, and the active Run is a `ContextVar` in `cli/context.py`. Both imports are forbidden by AD-1 and the import-linter contracts. A dev will either break the layers or invent an unreviewed hook. Remedy: redact at the boundary (`cli/exit.py` rendering, and the `redact_event` processor, which already covers `exc_info`), or specify a domain-side hook installed by the composition root.
MAJOR: The supported format set has no defined source at runtime. E002-S01-003 says the supported set is "the set of fixture Archives committed under `tests/fixtures/archives/`", and that `UNSUPPORTED_VERSION` fires for "a `format_version` with no fixture in the supported set". The classifier ships in the wheel and cannot read `tests/`. The story never states what the runtime code compares against. Remedy: `SUPPORTED_FORMAT_VERSIONS: Final` in `domain/archive_format.py`, plus a contract test asserting it equals the fixture-derived set (AD-6 then holds mechanically).
MAJOR: The v1 Manifest member index leaves directories, empty directories, symlinks and non-content members undefined. E002-S01-001 stores symlinks as link members and walks a tree, but `ManifestMember(path, role, size, sha256, encrypted)` does not say whether directory entries, symlinks (size or hash of what?), file mode or mtime are recorded. E002-S01-003's `UNDECLARED_MEMBER`/`MEMBER_MISSING` checks do not exempt `manifest.json` or directory entries. Either every tar directory entry fails verification, or empty directories (e.g. `wp-content/uploads/`) are silently dropped. FORMAT_VERSION 1 is append-only, so this has to be fixed before the first Archive is written. Remedy: add a `kind: file|dir|symlink` (and `link_target`) to `ManifestMember`, define the hash rule for each kind, state that mode and mtime are carried by the tar header and not checksummed, and exempt `manifest.json` from the index explicitly.
MAJOR: E002-S02-007 cannot complete `real_adapters` before E002-S02-009 lands. S02-007 extends `DatabaseQuery`/`DatabaseCommand` and adds `SiteFiles*`/`Config*` Protocols, and requires `real_adapters(...)` to "fill every field" and every Protocol to be `@runtime_checkable`-satisfied. The real implementations are S02-009's, which S02-007 still calls "the proposed story … `elaboration-proposed-stories.md`". As written, S02-007's mypy and `isinstance` checks fail unless the dev invents placeholders. Remedy: S02-007 binds `Unbound*` placeholders, as it already does for `UnboundSearchReplace`, and S02-009 replaces them; also update the pointer to name E002-S02-009.
MAJOR: The contracts Epic 3 depends on are incomplete: there is no Run Journal or staging port. E003-S02-005 §Interface contracts specifies `RunJournalQuery.incomplete(...)` and `RunJournalCommand.begin_run/phase_started/phase_completed/finish_run`, "split ports (`*Query`/`*Command`, E002-S02-007), with no-op command twins" (`NoopRunJournal`). No E002 story declares `ports/journal.py` (or a staging port) or the `JournalHeader`/`JournalRecord` domain types. `ports/*` is Epic 2-exclusive, and S02-007's `test_port_split.py` requires every `*Command` to have its twin in `adapters/noop.py`. Epic 3 must therefore either edit Epic 2's `ports/` and `adapters/noop.py`, or define Protocols outside `ports/` that the port-split test cannot see. Remedy: add the journal port, its domain record types and `NoopRunJournal` to S02-007, or record an ownership exception in `epics.md`. A smaller seam drift belongs with this one: E003-S02-005 calls `load_dump(Connection(...), wordpress, source, replace=None, identities=...)` against S02-007's `load_dump(location, source)`, which deliberately has no `replace` and no credential parameter.
MAJOR: E002-S01-001 is too large for one dev loop. It creates about 17 modules: `domain/{site,archive_format,storage_target,errors,backup_scope,exclusion}`, `core/backup`, `ports/{archive,database,crypto,exclusion}`, `adapters/{database,tar,store,workspace}` and `cli/backup`, plus the parser.
