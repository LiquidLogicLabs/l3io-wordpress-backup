### E006 closure owner decisions (added 2026-11-07, relayed by the orchestrator)

- *(owner decision, 2026-11-07; E006 closure decision 2, option a)* **A warning sink for the library.** `api.backup()`, `api.restore()` and `api.verify()` gain `on_warning: Callable[[RunWarning], None] | None = None`. `RunWarning` is a new frozen, typed value exported from `api/` (named so it does not shadow the builtin `Warning`), with `code` (the WARNING event name: `archive_unauthenticated`, `safety_snapshot_unencrypted`, the snapshot-location notice and every other operator notice the CLI writes to stderr), `message` and structured fields such as paths; it never carries a secret. Given a callback, each notice goes to it instead of stderr; with `None`, stderr output is unchanged. The structured WARNING log records stay in both cases, and the CLI keeps writing to stderr. Tests: every notice the API path can produce reaches the callback (the set derived from the code); nothing reaches stderr with a callback; stderr is unchanged without one; an exception raised by the callback propagates (documented); a guard that every stderr write on the API path goes through the sink. `docs/api.md` gains the name and the parameter.
- *(owner decision, 2026-11-07; E006 closure decision 3, option a)* **`api.backup(target=...)` is required.** No default: a call without it is a `TypeError` at call time, and the type checker sees it as required. The CLI keeps its frozen default (AD-22) and passes its resolved target explicitly into the shared driver. Tests: a call without `target` fails before any effect; the CLI default is unchanged; `inspect.signature` shows it required. Every caller relying on the default is updated (found by search). `docs/api.md`'s `backup` section and its pre-1.0 instability note say so.
- *(owner decision, 2026-11-07; E006 closure decision 4, option a)* **An opaque `Secret`.** A small `Secret` value defined once in `domain/` (pure) and re-exported from `api/`: `repr`/`str` give `Secret('***')`; `.reveal()` returns the value; it is not equal to, nor hashable as, its plain string (two `Secret`s compare in constant time with `hmac.compare_digest`); pickling it refuses or pickles a redacted placeholder (stated and tested); about 30 lines, no pydantic. `api.backup/restore/verify(passphrase=...)`, `ExplicitCredentialSpec.password` and `RelocationFlags.new_db_password` accept `Secret | str`; a `str` is wrapped on entry, the value stays a `Secret` until it is handed to `l3io-wordpress-database` or `PassphraseCipher`, where `.reveal()` is called, and it is registered with the `SecretRegistry` as now; the CLI wraps what it reads. Tests: every public credential field and parameter (derived from type hints) accepts `Secret`; `repr` of every public value object holding one shows no plaintext; `.reveal()` is called only in an allow-listed set of adapter modules (AST guard, planted violation); the existing redaction and leak tests pass. `docs/api.md` gets a `Secret` section.
- *(owner decision, 2026-11-07; E006 closure decision 5, option a)* **No public `context=`.** The parameter is removed from `api.backup()`, `api.restore()` and `api.verify()`; the CLI and the drivers' internal `ctx=` are unchanged.
