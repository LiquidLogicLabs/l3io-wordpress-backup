**Implements:** FR-14 (CLI selectability), FR-27 (diagnostic subcommand), FR-4/FR-5 (binding only), AD-9, AD-13, AD-26.

As an operator,
I want the credential providers, tool checks and encryption that later epics deliver to work from the same commands I already run,
So that `backup`, `restore` and `doctor` behave as documented without any root assembling them differently.

**Acceptance Criteria:**

**Given** Epics 4 and 5 have landed
**When** `wpbackup2 backup`, `restore`, `verify` or `doctor` runs
**Then** credentials come from Epic 5's chains in the order `domain/credentials.py` declares, for the WordPress account and the administrator alike
**And** every external binary the plan needs is checked by Epic 5's `BinaryPreflight` before the first command adapter
**And** `wpbackup2 doctor` prints the FR-27 diagnosis and exits `OK` or `NOT_READY`
**And** no flag that now works is still refused as not implemented

A reviewer can tell it happened by running each previously accepted-and-explained flag and seeing it take effect, and by `wpbackup2 doctor --json` on a host missing `age` reporting `ready: false` with exit 7.

## Technical acceptance criteria

### Interface contracts

- **`cli/credentials.py` bodies (E002-S01-006's seam).** `wordpress_source(...)` delegates to `adapters/credential_providers.wordpress_credentials(explicit=..., wp_config=..., aws_secret_id=..., aws_region=...)` and `admin_source(...)` to `admin_credentials(...)`, both taking their step order from `domain/credentials.py`'s tuples; the signatures of the two `cli/credentials` functions do not change. Requires E005-S01-001's `wordpress_credentials` to accept the AWS pair (E005 follow-up in the round-2 gap map).
- **`AdminCredentialsRequiredError`'s message** names `--admin-username`/`--admin-password`, `--admin-credentials-aws-secret-id`, and `L3IO_WP_BACKUP_ADMIN_USER`/`L3IO_WP_BACKUP_ADMIN_PASSWORD`, reading the variable names from Epic 5's constants (no second literal).
- **`RootPreflight` (`cli/context.py`)** wraps E005-S01-002's `BinaryPreflight(environ=os.environ)` and is what `real_adapters`/`dry_run_adapters` bind as `AdapterSet.preflight` (replacing the `check_dump`-only binding of E002-S02-007): its `check(requirements)` first raises `PreflightFailedError(tool="platform", ...)` when `unsupported_platform()` returns a reason, then delegates — it checks exactly the plan's `required_tools`. *(Decided 2026-10-28.)* The passphrase backend reaches it through the plan: each root passes `extra_tools=cipher.required_tools()` (E004-S01-003) into `BackupRequest`/`RestoreRequest`, which the plan builders append (E002-S02-007, E003-S01-001); `RootPreflight` never infers the cipher's mode. Every root — `cli/backup.py`, `cli/verify.py`, Epic 3's `cli/restore.py`, Epic 6's `api/` — gets it through `real_adapters` and adds nothing.
- **`cli/doctor.py::run_doctor(args) -> int`** builds `diagnose(preflight=RootPreflight(...), environ=os.environ, target=<--archive parsed>, database=<DatabaseQuery.check_dump when --wp-dir is given>)` and renders `Diagnosis` as text on a TTY, `to_dict()` as JSON otherwise or with `--json`; returns `OK` when `ready`, else `NOT_READY`. It opens a Run without a Site Lock (it changes nothing).
- **Epic 4 bindings.** *(Decided 2026-10-27.)* The cipher and the exclusion set are per-call arguments — `BackupRequest.cipher`/`.exclusion` and `RestoreRequest.cipher`, reaching `backup(...)` — never `AdapterSet` fields and never `real_adapters` arguments. This story binds them in `cli/`, using the registry each root created before the Run (E002-S01-004) and Epic 4's `adapters/crypto.build_payload_cipher` (E004-S01-003) *(ADR-0024; Gate E004 AG-6/AG-9, 2026-10-30)*: `run_backup` resolves the passphrase only with `--encrypt-with-passphrase` and calls `build_payload_cipher(passphrase=..., required=args.encrypt_with_passphrase, secrets=registry)`, so the flag with no passphrase resolved exits `REFUSED` (`PassphraseRequiredError`) rather than writing plaintext; `run_restore` resolves it on every restore and passes `required=False`; `run_verify` builds no cipher, because verification is keyless. `run_backup` builds the exclusion set from `--exclude`/`--no-default-excludes` with `ExclusionSet.from_patterns(...)`, wrapped in `LoggedExclusionPolicy` (E004-S01-001, Gate E004 AG-12). With no exclusion flag it passes none, and this story changes `cli/backup.py::default_exclusion_policy()` (E002-S01-004) from `INCLUDE_EVERYTHING` to `LoggedExclusionPolicy(ExclusionSet.default())`, so the library and the CLI get the same default from one place.
- The accepted-and-explained declarations for every flag above are removed in the same change. `NOT_YET_IMPLEMENTED` names this story for each of them (E002-S02-011).

*(Resolved 2026-10-28, Shawn: the plan's `required_tools` carries the passphrase-backend requirement — `extra_tools=cipher.required_tools()` from each root, appended by the plan builders.)* Formerly OPEN: with the cipher a per-call argument, `RootPreflight` has no stated way to learn that the Run's cipher is in passphrase mode. It is bound through `real_adapters`, which takes no cipher (AG-31), and `check(requirements)` receives only the plan's tool requirements. Either the plan's `required_tools` gains the passphrase backend requirement when the request's cipher is in passphrase mode, or `real_adapters` takes a passphrase-mode flag. No story has chosen. Until then, the cipher's `check()` refuses a host with no usable passphrase backend before preflight (E004-S01-003), so a real Run is not unprotected; what is missing is the `doctor`/preflight report naming it.

### Error and edge case handling

- Conflicting credential sources: Epic 5's `CredentialSourceConflictError` → `USAGE`, before the lock.
- `--admin-credentials-aws-*`/`--db-credentials-aws-*` without the `aws` extra: `MissingExtraError(extra="aws")` → `NOT_READY`, raised when the chain is built, not at import (AD-8).
- Windows: `PreflightFailedError(tool="platform")` → `NOT_READY` before any other check, files-only Runs included.
- `doctor` with an unreachable database: the diagnosis records database's finding codes and `ready: false`; exit `NOT_READY`, never `UNREACHABLE` (doctor reports, it does not fail on what it reports).

### Testability approach

- **Encrypted restore, end to end** (moved from E004-S01-003, whose restore-side tests stop at `decrypt_payload`, because `drive_restore` is E003's and E003 runs beside E004) *(Gate E004 AG-10, 2026-10-30)*: an Archive written by `run_backup` with `--encrypt-with-passphrase` restores through `run_restore` with the same passphrase, tree and database intact; a wrong passphrase exits 4 (`ArchiveDecryptionError`) with no Safety Snapshot written and the Site unchanged; no passphrase exits `REFUSED` (`PassphraseRequiredError(operation="restore")`) before `VERIFY`.
- The accepted-and-explained test of E002-S01-005 fails until every flag here is bound and undeclared — it is this story's completion check, with scope from the parser.
- `tests/unit/cli/test_root_preflight.py`: platform first; it checks exactly the requirements it is handed, and the passphrase backend's arrive only through the plan's `extra_tools` from `cipher.required_tools()` *(Gate E004 AG-8, 2026-10-30)*; `real_adapters` and `dry_run_adapters` bind the same `RootPreflight`; E002-S02-007's `test_preflight_order.py` passes with it bound.
