## New findings

MINOR: The kill harness (E003-S02-005 L203) kills only after a durable journal write, so the window where an effect has landed and its step has not yet been journaled is never exercised for the loser removal. If the Run is killed after `revoke_grants`, or after `drop_database` but before the `"loser_dropped"` write, the undo row for `"cutover:<last key>"` (L112) says the previous database "is retained", when its grants are already revoked or it is already gone. The advice ("restore the database from Safety Snapshot") is still safe, so nothing is destroyed. Still, ADR-0020's own rule ("every step that changes what undo means must be journaled as a named step") calls for a `"loser_drop_started"` step before `revoke_grants`, with its own row ("`<live>` was being dropped; it may be gone; restore from Safety Snapshot `<path>`").
MINOR: No E003 test covers the AG-2 behaviour at restore level. E003-S01-001 L64–65 and E003-S02-006 L81 promise four things: exit `OK` with skipped links, one WARNING per link, a Dry Run list that "agrees" with the real skip, and a snapshot of such a site that round-trips. Only E002-S01-003's `extract_archive` contract test exists. The Dry Run list also needs a second, hand-written "resolves outside the Site Root" predicate over `ViewMember.link_target`, while the real skip is `tarfile.data_filter`'s decision. Nothing proves that the two agree. Remediation: add a restore-level case with a fixture that has `uploads -> /abs/path` and `a/b -> ../../x` (real and `dry_run_adapters`, asserting the same `skipped_links`), plus a `test_snapshot_reversible.py` case for such a site. Alternatively, derive the Dry Run list by running `tarfile.data_filter` on a synthesized `TarInfo`.
MINOR: In a Dry Run, E003-S01-001 L61 has the executor evaluate `is_orderly_failure` over "the record read back through `ports.journal_query`". Under `NoopRunJournal` that record does not exist, so `incomplete()` returns `None`, and what the predicate receives is unstated. This is harmless today because `finish_run` is a no-op there. The cleaner contract is for the executor to accumulate the entries it journaled in memory and pass those, which also avoids a read-back in the real Run.
MINOR: AG-10's remediation asked for an integration case for a one-level-up (`PARENT`) config. None was added: no E003 test names `PARENT` or a one-level-up config except `test_snapshot_location.py`. Add one to E003-S02-005's `test_restore_inroot_config.py`: a `PARENT` target, restored in `database` and `all`, keeps its file at `../wp-config.php`, gets no in-root copy, and its cutover lands in the parent file.
MINOR: Two pieces of editorial or type residue from the edit. (a) E002-S02-012 L60's `NoopSiteFiles` `extract` still returns `ExtractResult(0, 0)`, but E002-S01-003 L59 now gives `ExtractResult` a third required field, `skipped_links`, so the result should be `ExtractResult(0, 0, ())`. (b) In E003-S01-001 L62, the `RestoreInputs` bullet ends with two sentences about the executor ("It contains no `if dry_run` … `take_snapshot` is a callable …"). They were moved off the `execute_restore` bullet (L61) and now describe the wrong subject.
