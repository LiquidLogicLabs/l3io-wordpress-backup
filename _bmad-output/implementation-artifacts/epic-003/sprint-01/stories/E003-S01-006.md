# E003-S01-006: Drive a restore from the command line


**Implements:** FR-6, FR-7, FR-8, FR-19 (restore path), AD-5, AD-16, AD-17, AD-18.1, AD-19, AD-25, AD-26.

*(Added 2026-10-27 from the route-1 gap pass, proposal P2 in `_bmad-output/planning-artifacts/elaboration-proposed-stories.md`, re-homed from Epic 2 to Epic 3 by Shawn's decision: Epic 3 owns `cli/restore.py` and its one dispatch arm in `cli/__init__.py`; Epic 2 keeps the rest of `cli/`. This keeps the epic graph acyclic — the restore root calls Epic 3's `core/restore` and `adapters/restore_runner`. Depends on E003-S01-001 and on Epic 2's E002-S01-001, E002-S01-003, E002-S01-006 through E002-S02-009. Until it lands, `wpbackup2 restore` stays accepted-and-explained (exit `USAGE`, listed in E002-S02-011's `NOT_YET_IMPLEMENTED`), and the end-to-end criteria of E003-S01-002 through E003-S02-005 run through it.)*


As an operator,
I want `wpbackup2 restore` to resolve what I asked for once and carry it through every phase,
So that the mode I typed is the mode performed and every safety step runs in order.

**Acceptance Criteria:**

**Given** `wpbackup2 restore --wp-dir <Site Root> --archive <Archive>` with any flag combination
**When** it runs
**Then** `(RestoreMode, OverrideSet)` is resolved once from E002-S01-005's table and passed explicitly to every phase
**And** the Site Lock is taken and an incomplete Run Journal is refused before any Site state is read beyond canonicalising the path
**And** the Archive is verified before the Safety Snapshot and before any destructive phase
**And** a target with no `wp-config.php` gets its Site Descriptor from the Archive's config member
**And** a Dry Run binds no-op commands and refuses wherever the real Run would

*(Per the E002 gate reconciliation 2026-10-27: the `(RestoreMode, OverrideSet)` table and `resolve_flags` are E002-S02-011's, not E002-S01-005's.)*

## Business acceptance criteria

### Outcome

`wpbackup2 restore` (and Epic 6's library root, which reuses the same driver function) runs a restore end to end: flags resolved through the AD-25 table; Site Lock; incomplete-journal refusal (or `--resolve-interrupted-run <run_id>`); `PREFLIGHT`; `VERIFY`; the target surveyed through query ports; the plan built; `SNAPSHOT` (encrypted when configured, otherwise said loudly; skipped only by `--no-safety-snapshot`); the remaining phases executed in `RestorePhase` order; the database report printed; one exit code. A reviewer can tell it happened by running each FR-6 row against a fixture site and reading the `restore_mode_resolved`, `planned_action` and `phase_completed` records — one `run_id`, phases in AD-17 order, the requested Mode in the Safety Snapshot's Manifest `origin`.

## Technical acceptance criteria

### Interface contracts

*(Adopted 2026-10-27 from the E002 gate, changes 3, 4, 5, 6, 7 and 8.)*

- **`cli/restore.py::run_restore(args) -> int`** (dispatched from `cli/__init__.py::main`) does only argument translation: `FlagCombination` from the `restore mode` group → E002-S02-011's `resolve_flags` (AD-25); `SnapshotPolicy` from `--no-safety-snapshot`; the administrator `CredentialSpec` from `--admin-username`/`--admin-password` through E002-S01-006's `cli/credentials.admin_spec(...)`; then — *(Decided 2026-10-27.)* — in this order creates one `SecretRegistry()`, resolves the passphrase into it (`resolve_passphrase(..., secrets=registry)`, E002-S01-006) and builds the cipher from the encryption flags with Epic 4's `adapters/crypto.build_member_cipher(..., secrets=registry)` (bound by E008-S01-001; `None` until then); then calls **`drive_restore(request, ctx=None, secrets=registry)`** (signature below), the function the library root also calls. `open_run` adopts that registry (E002-S01-004), so the passphrase is registered before the Run opens and the request's `cipher` exists before the driver is called. Frozen `RestoreRequest(site_root: Path, archive: StorageTarget, mode: RestoreMode, overrides: OverrideSet, snapshot: SnapshotPolicy, snapshot_dir: Path | None, resolve_run_id: str | None, admin: CredentialSpec | None, cipher: MemberCipher | None, dry_run: bool)` — `mode`, `overrides` and `snapshot` have no defaults (AD-5), and no field carries an `l3io.wp.database` type (ADR-0015 amendment). No function below `run_restore` receives `args`.
- **`drive_restore` order (each step before the next; nothing destructive before step 7):**
  1. Canonicalise `site_root` (`Path.resolve(strict=True)`), then `join_or_open(ctx, operation="restore", tracer=tracer, secrets=secrets, command_args=command_args, site_root=canonical, site_lock=FcntlSiteLock())` → `RunHandle(ctx, opened)` (E002-S01-004, E002-S02-008). When the Run is opened here, `open_run` adopts `secrets` and acquires the Site Lock; when it is joined, the outer root holds the lock and the Run keeps the outer root's registry. No adapter set is bound in this step (ADR-0016). Log `restore_mode_resolved` with `restore_mode`, `overrides`, `snapshot_policy`.
  2. **Journal.** When `opened`, the root constructs `adapters/journal.py`'s `(RunJournalQuery, RunJournalCommand)` pair for the canonical Site Root (E003-S02-005) — keyed by that path only, so no other Site state is read — and queries it directly; the same pair is passed to `real_adapters` in step 3. When joined, it uses `ctx.adapters.journal_query`. `incomplete(site_root)`: a record → `IncompleteRunError` unless `resolve_run_id` equals `record.header.run_id`, in which case the journal is resolved (moved to `resolved/`, `resolved_by="cli"`) and the Run **stops** with `OK` after reporting — resolving and restoring are never one command.
  3. **Site Descriptor, credentials and the one bind.** `locate_wp_config(site_root, stated=request.relocation.wp_config)` and `site_descriptor_from_wp_config(site_root, config_file=...)` (E002-S01-001). The administrator source is `cli/credentials.admin_source(request.admin, ...)`; the WordPress source is `cli/credentials.wordpress_source(None, ...)` (the target's `wp-config.php`); the relocated WordPress source, when Epic 7 supplies a spec, is `cli/credentials.wordpress_source(ext.wordpress_spec(), ...)` (E002-S01-006). Then, **only if `opened`**, `ctx.bind_adapters(real_adapters(..., admin_source=..., restore_wordpress_source=..., search_replace=..., journal=(query, command), tracer=tracer))`, wrapped in E002-S02-007's `dry_run_adapters(...)` when `request.dry_run` (E002-S02-012 substitutes `NoopRunJournal` and the other restore no-ops and reuses every query). A joined Run binds nothing and uses the outer root's set. A port no story has supplied stays bound to E002-S02-012's placeholder, which raises `UnboundAdapterError`.
  4. `PREFLIGHT`: the bound `AdapterSet.preflight` checks the plan-independent requirements, plus database `check_*` queries for the parts the Mode restores.
  5. `VERIFY`: E002-S01-003's `verify_archive`; failure → `VerificationFailedError`; the `ArchiveView` is kept for planning. A files-only v0 Archive with a Mode naming the database is refused by the plan (`ArchiveHasNoDumpError`, AD-23 amended) before step 7.
  6. `TargetState` from `SiteFilesQuery` and `DatabaseQuery.survey_target`; `build_restore_plan(site, mode, overrides, view, target, relocation=...)` (Epic 3) — which applies the FR-7 guard.
  7. `execute_restore(plan, ports, take_snapshot, journal)` (Epic 3), where `take_snapshot(scope)` calls E002-S01-004's `backup(site, scope, file:<snapshot path>, ctx=ctx, cipher=request.cipher, exclusion=INCLUDE_EVERYTHING, origin=ManifestOrigin(SAFETY_SNAPSHOT, mode.value, ctx.run_id))` and, when `request.cipher is None`, writes `safety snapshot is NOT encrypted: <path>` to stderr and logs WARNING `safety_snapshot_unencrypted` with `path` (AD-26, decided 2026-10-20).
  8. Print the plan (Dry Run) or the database report and Snapshot path; return `ExitCode.OK` or raise.
- **A target with no `wp-config.php` (decided 2026-10-27, ADR-0016 amendment; formerly OPEN).** After the lock and the journal check, when the target has no config: `probe.read_member(archive, <the Manifest's config member path>, max_bytes=1 MiB)` (E002-S01-003), digest the bytes, write them to a `0600` file in the Run workspace, and build the descriptor with `site_descriptor_from_archive_config(site_root, <that file>)`; then `ctx.bind_adapters(...)`, `PREFLIGHT`, `VERIFY` in AD-17's order. `VERIFY` must report the config member's stored digest equal to the digest of the bytes used, or the Run aborts with `VerificationFailedError` before any destructive phase. A v0 Archive (no Manifest, no checksums) uses `wp-root/wp-config.php` and its `STRUCTURAL_ONLY` verification; the digest comparison is then against a second read of the same member. An Archive with no config member at all still refuses with `InvalidSiteDescriptorError`, nothing changed.
- **Accepted-and-explained entries (E002-S02-011).** This story removes from `cli/parser.py::NOT_YET_IMPLEMENTED` every entry that names E003-S01-006 — the `restore` subcommand and its flags — in the change that binds them. Entries naming Epic 7 (`--new-*`, restore's `--wp-config`) or E008-S01-001 (the encryption and exclusion flags, `--admin-credentials-aws-*`, `--db-credentials-aws-*`, `doctor`) stay until those stories remove them. E002-S02-011's `tests/contracts/test_not_yet_implemented.py` derives its cases from the mapping, so it needs no edit.
- **`RestorePhase` is driven, not re-listed.** The root iterates nothing itself; it passes the plan to the executor. A contract test fails if `cli/restore.py` names any `RestorePhase` member other than through `plan.phases`.
- *(Decided 2026-10-28.)* `RestoreRequest` gains `extra_tools: tuple[ToolRequirement, ...] = ()`, which `drive_restore` passes to `build_restore_plan(..., extra_tools=...)` unchanged. `run_restore` (and Epic 6's `api.restore`) fill it with `cipher.required_tools()` once E008-S01-001 binds Epic 4's cipher; before that it is `()`. This is the only route by which the passphrase backend reaches preflight.

### Error and edge case handling

- Lock held by another Run → `LOCKED`; incomplete journal → `REFUSED` naming run, phase, undo and journal path; `--resolve-interrupted-run` with a different ID → `REFUSED` naming the journal's ID.
- Rejected flag combination → `USAGE` before the lock is taken.
- Verification failure → `VERIFICATION_FAILED` before `SNAPSHOT`; Snapshot failure → `REFUSED` (`SnapshotFailedError`) before `CLEAN`.
- *(Adopted 2026-10-27 from the E002 gate, changes 4–6.)* A Mode touching the database with no administrator credentials → `CREDENTIALS` (`AdminCredentialsRequiredError`, raised by the first restore-half database method before any connection, E002-S02-012) — at the latest in `PREFLIGHT`'s `check_*`, before any destructive phase.
- `drive_restore(..., ctx=None)` while another Run is active → `RunContextActiveError`, a `RefusedError` → `REFUSED` (E002-S01-004), never a second Run ID.
- A port bound to a placeholder (a feature no story has supplied) called in a real Run → `UnboundAdapterError` → `FAILED` (E002-S02-012), naming the port and its supplier — never a bare `RuntimeError`.
- A second `bind_adapters` or a read of `ctx.adapters` before the bind → `AdaptersAlreadyBoundError` / `AdaptersNotBoundError` → `FAILED` (E002-S01-004; a defect).
- Target with neither its own nor an Archive `wp-config.php` → `FAILED` (`InvalidSiteDescriptorError`), nothing changed.
- SIGTERM mid-phase → the journal shows the open phase; the lock is released by the `finally` (E002-S02-008).
