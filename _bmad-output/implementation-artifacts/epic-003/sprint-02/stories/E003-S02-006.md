# E003-S02-006: Drive a restore from the command line


**Implements:** FR-6, FR-7, FR-8, FR-19 (restore path), AD-5, AD-16, AD-17, AD-18.1, AD-19, AD-25, AD-26.

*(Added 2026-10-27 from the route-1 gap pass, proposal P2 in `_bmad-output/planning-artifacts/elaboration-proposed-stories.md`, re-homed from Epic 2 to Epic 3 by Shawn's decision: Epic 3 owns `cli/restore.py` and its one dispatch arm in `cli/__init__.py`; Epic 2 keeps the rest of `cli/`. This keeps the epic graph acyclic — the restore root calls Epic 3's `core/restore` and `adapters/restore_runner`. Depends on every other E003 story — E003-S01-001, E003-S01-002, E003-S02-005, E003-S02-003, E003-S02-004 — and on Epic 2's E002-S01-001, E002-S01-003, E002-S01-006 through E002-S02-009; it is the last story of sprint 02, re-keyed from E003-S01-006 on 2026-10-28. Those stories provide parts and test them through `execute_restore` and their own adapters; this story binds them, and every-mode end-to-end integration runs here *(Gate AG-3, 2026-10-28)*.)*


As an operator,
I want `wpbackup2 restore` to resolve what I asked for once and carry it through every phase,
So that the mode I typed is the mode performed and every safety step runs in order.

**Acceptance Criteria:**

**Given** `wpbackup2 restore --wp-dir <Site Root> --archive <Archive>` with any flag combination
**When** it runs
**Then** `(RestoreMode, OverrideSet)` is resolved once from E002-S01-005's table and passed explicitly to every phase
**And** the Site Lock is taken and an incomplete Run Journal is refused before any Site state is read beyond canonicalising the path
**And** the Archive is verified before the Safety Snapshot and before any destructive phase
**And** a target with no `wp-config.php` gets its Site Descriptor from the Archive's config member
**And** a Dry Run binds no-op commands and refuses wherever the real Run would

*(Per the E002 gate reconciliation 2026-10-27: the `(RestoreMode, OverrideSet)` table and `resolve_flags` are E002-S02-011's, not E002-S01-005's.)*

## Business acceptance criteria

### Outcome

`wpbackup2 restore` (and Epic 6's library root, which reuses the same driver function) runs a restore end to end: flags resolved through the AD-25 table; Site Lock; incomplete-journal refusal (or `--resolve-interrupted-run <run_id>`, after the adapter bind); the Archive probed; the target surveyed through query ports; the plan built; then the executor runs every phase in `RestorePhase` order — `PREFLIGHT`, `VERIFY`, `SNAPSHOT` (encrypted when a passphrase resolved, otherwise said loudly, ADR-0024; skipped only by `--no-safety-snapshot`) and the rest (ADR-0022) *(Gate AG-4, 2026-10-28)*; the database report printed; one exit code. A reviewer can tell it happened by running each FR-6 row against a fixture site and reading the `restore_mode_resolved`, `planned_action` and `phase_completed` records — one `run_id`, phases in AD-17 order, the requested Mode in the Safety Snapshot's Manifest `origin`.

## Technical acceptance criteria

### Interface contracts

*(Adopted 2026-10-27 from the E002 gate, changes 3, 4, 5, 6, 7 and 8.)*

- **`cli/restore.py::run_restore(args) -> int`** (dispatched from `cli/__init__.py::main`) does only argument translation: `FlagCombination` from the `restore mode` group → E002-S02-011's `resolve_flags` (AD-25); `SnapshotPolicy` from `--no-safety-snapshot`; the administrator `CredentialSpec` from `--admin-username`/`--admin-password` through E002-S01-006's `cli/credentials.admin_spec(...)`; then — *(Decided 2026-10-27.)* — in this order creates one `SecretRegistry()`, resolves the passphrase into it on every restore (`resolve_passphrase(..., secrets=registry)`, E002-S01-006) and builds the cipher with Epic 4's `adapters/crypto.build_payload_cipher(passphrase=..., required=False, secrets=registry)` (E004-S01-003; bound by E008-S01-001; `None` until then), so the one passphrase both decrypts an encrypted Archive and encrypts the Safety Snapshot *(ADR-0024; Gate E004 AG-6, 2026-10-30)*; then calls **`drive_restore(request, ctx=None, secrets=registry)`** (signature below), the function the library root also calls. `open_run` adopts that registry (E002-S01-004), so the passphrase is registered before the Run opens and the request's `cipher` exists before the driver is called. Frozen `RestoreRequest(site_root: Path, archive: StorageTarget, mode: RestoreMode, overrides: OverrideSet, snapshot: SnapshotPolicy, snapshot_dir: Path | None, config_policy: ConfigPolicy, resolve_run_id: str | None, admin: CredentialSpec | None, cipher: PayloadCipher | None, dry_run: bool)` — `mode`, `overrides`, `snapshot` and `config_policy` have no defaults (AD-5); `run_restore` maps `--overwrite-wp-config` to `OVERWRITE`, else `KEEP` (ADR-0023) *(Gate AG-16, 2026-10-28)*; no field carries an `l3io.wp.database` type (ADR-0015 amendment). `snapshot_dir` `None` means the per-Site default, which `drive_restore` computes with `platformdirs` (E003-S02-003) and passes to the plan as a path *(Gate AG-6, 2026-10-28)*. No function below `run_restore` receives `args`.
- **`drive_restore` order (each step before the next; nothing destructive before step 8)** *(Gate AG-4, AG-6, AG-7, AG-8 and AG-14, 2026-10-28; ADR-0021, ADR-0022)*. Before step 1, `request.config_policy` `OVERWRITE` with a Mode that restores no files (`database`, `database-clean`) raises `UsageError` (exit 2), nothing read (ADR-0023).
  1. When the Run is opened here, `open_run` adopts `secrets` and acquires the Site Lock; when it is joined, the outer root holds the lock and the Run keeps the outer root's registry. No adapter set is bound in this step (ADR-0016). Log `restore_mode_resolved` with `restore_mode`, `overrides`, `snapshot_policy`.
  2. **Journal query.** When `opened`, the root computes the per-Site state directory (ADR-0021) and constructs `adapters/journal.py`'s `(RunJournalQuery, RunJournalCommand)` pair for it (E003-S02-005) — keyed by the canonical Site Root only, so no other Site state is read — and queries it directly; the same pair is passed to `real_adapters` in step 3. When joined, it uses `ctx.adapters.journal_query`. `incomplete(site_root)`: a record → `IncompleteRunError` unless `resolve_run_id` equals `record.header.run_id`, in which case resolution is performed in step 4. Nothing is resolved here.
  3. **Site Descriptor, credentials and the one bind.** `locate_wp_config(site_root, stated=request.relocation.wp_config)` and `site_descriptor_from_wp_config(site_root, config_file=...)` (E002-S01-001). The administrator source is `cli/credentials.admin_source(request.admin, ...)`; the WordPress source is `cli/credentials.wordpress_source(None, ...)` (the target's `wp-config.php`); the relocated WordPress source, when Epic 7 supplies a spec, is `cli/credentials.wordpress_source(ext.wordpress_spec(), ...)` (E002-S01-006). Then, **only if `opened`**, `ctx.bind_adapters(real_adapters(..., admin_source=..., restore_wordpress_source=..., search_replace=..., journal=(query, command), tracer=tracer))`, wrapped in E002-S02-007's `dry_run_adapters(...)` when `request.dry_run` (E002-S02-012 substitutes `NoopRunJournal` and the other restore no-ops and reuses every query). A joined Run binds nothing and uses the outer root's set. A port no story has supplied stays bound to E002-S02-012's placeholder, which raises `UnboundAdapterError`.
  4. **Resolution (only when step 2 matched).** After the bind, so a cutover-interrupted set has the config ports and the relocated credentials: when the interrupted step is the cutover, the pending keys are completed as E003-S02-005 specifies; then `ctx.adapters.journal_command.resolve(run_id, resolved_by="cli")`. The Run **stops** with `OK` after reporting — resolving and restoring are never one command. In a Dry Run `NoopRunJournal.resolve` writes nothing and the outcome says what would be resolved (ADR-0021).

  7. **Header and inputs.** The frozen `JournalHeader` (E003-S02-005's field values; the Safety Snapshot path computed in advance as `<snapshot_dir>/<UTC yyyymmddThhmmssZ>-<run_id>.tar.gz`, E003-S02-003; `saved_config` under `OVERWRITE`; `phase_undo` from `relocation.undo`), then `RestoreInputs` (E003-S01-001) with the descriptor, the view, the Archive, `ctx.run_id`, the relocation, the header, `request.config_policy`, the located config path and `payload` (`ctx.workspace / "payload.tar.gz"` when `view.encrypted`, else `None`) *(ADR-0024)*.

### Error and edge case handling

- Lock held by another Run → `LOCKED`; incomplete journal → `REFUSED` naming run, phase, undo and journal path; `--resolve-interrupted-run` with a different ID → `REFUSED` naming the journal's ID.
- Rejected flag combination → `USAGE` before the lock is taken.
- Malformed Archive refused at the probe (step 5) → the classifier's error (`VERIFICATION_FAILED`), nothing changed; verification failure in the executor's `VERIFY` → `VERIFICATION_FAILED` before `SNAPSHOT`; Snapshot failure → `REFUSED` (`SnapshotFailedError`) before `CLEAN` *(Gate AG-4, 2026-10-28)*.
- `--overwrite-wp-config` with `--mode db` → `USAGE` before the lock; with an Archive that has no config member → `REFUSED` at plan time (ADR-0023) *(Gate AG-16, 2026-10-28)*. A v0 Archive that carries `wp-root/wp-config.php` has a `config_path`, so the flag works for it *(Gate E004 AG-11, 2026-10-30)*.
