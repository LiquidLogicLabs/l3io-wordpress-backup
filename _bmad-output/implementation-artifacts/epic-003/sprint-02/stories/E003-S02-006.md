**Implements:** FR-6, FR-7, FR-8, FR-19 (restore path), AD-5, AD-16, AD-17, AD-18.1, AD-19, AD-25, AD-26.

Those stories provide parts and test them through `execute_restore` and their own adapters; this story binds them, and every-mode end-to-end integration runs here *(Gate AG-3, 2026-10-28)*.)*


As an operator,
I want `wpbackup2 restore` to resolve what I asked for once and carry it through every phase,
So that the mode I typed is the mode performed and every safety step runs in order.

**Acceptance Criteria:**

**Given** `wpbackup2 restore --wp-dir <Site Root> --archive <Archive>` with any flag combination
**When** it runs
**Then** `(RestoreMode, OverrideSet)` is resolved once from E002-S01-005's table and passed explicitly to every phase
**And** the Site Lock is taken and an incomplete Run Journal is refused before any Site state is read beyond canonicalising the path
**And** the Archive is verified before the Safety Snapshot and before any destructive phase
**And** a target with no `wp-config.php` gets its Site Descriptor from the Archive's config member
**And** a Dry Run binds no-op commands and refuses wherever the real Run would

*(Per the E002 gate reconciliation 2026-10-27: the `(RestoreMode, OverrideSet)` table and `resolve_flags` are E002-S02-011's, not E002-S01-005's.)*

## Business acceptance criteria

### Outcome

`wpbackup2 restore` (and Epic 6's library root, which reuses the same driver function) runs a restore end to end: flags resolved through the AD-25 table; Site Lock; incomplete-journal refusal (or `--resolve-interrupted-run <run_id>`, after the adapter bind); the Archive probed; the target surveyed through query ports; the plan built; then the executor runs every phase in `RestorePhase` order — `PREFLIGHT`, `VERIFY`, `SNAPSHOT` (encrypted when a passphrase resolved, otherwise said loudly, ADR-0024; skipped only by `--no-safety-snapshot`) and the rest (ADR-0022) *(Gate AG-4, 2026-10-28)*; the database report printed; one exit code. A reviewer can tell it happened by running each FR-6 row against a fixture site and reading the `restore_mode_resolved`, `planned_action` and `phase_completed` records — one `run_id`, phases in AD-17 order, the requested Mode in the Safety Snapshot's Manifest `origin`.

### Error and edge case handling

- **An unreadable Site Root is a refusal, not a failure (BL-E003-034; FR-7 says `REFUSED`).** E002's descriptor adapter (`adapters/database.py` descriptor reading, edit granted) raises today the same `InvalidSiteDescriptorError` for a missing and for an unreadable Site Root, so nothing can map the second by type. This story adds `UnreadableSiteRootError(RefusedError)` (in `domain/errors.py`, naming the path and the `OSError` class, never file contents), raised by that adapter when the Site Root exists but cannot be listed or read. FR-7's guard therefore exits `REFUSED` with nothing changed. A missing Site Root keeps its current error. It is never treated as empty: that safety property already holds. Test: a Site Root with mode 000 is refused with exit `REFUSED` as a non-root user, and skipped as root, which ignores the mode. Resolve BL-E003-034 with this story's key. *(Assigned 2026-11-04.)*
- Lock held by another Run → `LOCKED`; incomplete journal → `REFUSED` naming run, phase, undo and journal path; `--resolve-interrupted-run` with a different ID → `REFUSED` naming the journal's ID.
- Rejected flag combination → `USAGE` before the lock is taken.
- Malformed Archive refused at the probe (step 5) → the classifier's error (`VERIFICATION_FAILED`), nothing changed; verification failure in the executor's `VERIFY` → `VERIFICATION_FAILED` before `SNAPSHOT`; Snapshot failure → `REFUSED` (`SnapshotFailedError`) before `CLEAN` *(Gate AG-4, 2026-10-28)*.
- `--overwrite-wp-config` with `--mode db` → `USAGE` before the lock; with an Archive that has no config member → `REFUSED` at plan time (ADR-0023) *(Gate AG-16, 2026-10-28)*. A v0 Archive that carries `wp-root/wp-config.php` has a `config_path`, so the flag works for it *(Gate E004 AG-11, 2026-10-30)*.
- An encrypted Archive with no passphrase resolved → `REFUSED` (`PassphraseRequiredError`) at plan time; a wrong passphrase → `VERIFICATION_FAILED` (8, `PassphraseRejectedError`) and a damaged payload → `VERIFICATION_FAILED` (8, `PayloadDamagedError`), E002's built errors (Shawn, 2026-11-03), during `VERIFY`, or earlier on the no-config path; all before `SNAPSHOT`, nothing changed *(ADR-0024; E003 pre-build re-check, 2026-11-03)*.
- No target `wp-config.php` and `--archive-database` absent, or not equal to the Archive config's host and database → `REFUSED` (`ArchiveIdentityUnconfirmedError`), before any database connection, naming the Archive's host, database and user and never a credential (BL-E002-114) *(E003 pre-build re-check, 2026-11-03)*.
- An administrator connection that must use TLS and cannot negotiate it → `UNREACHABLE` (`DatabaseTlsHandshakeError`); one whose server certificate does not verify → `REFUSED` (`DatabaseTlsVerificationError`); an `--admin-tls` below the policy for the host → `USAGE` (BL-E002-114) *(E003 pre-build re-check, 2026-11-03)*.
- Any failure after `SNAPSHOT` completed → the mapped exit code, with the Safety Snapshot path printed (AG-15).
- *(Adopted 2026-10-27 from the E002 gate, changes 4–6.)* A Mode touching the database with no administrator credentials → `CREDENTIALS` (`AdminCredentialsRequiredError`, raised by the first restore-half database method before any connection, E002-S02-012) — at the latest in step 6's `survey_target`, before any destructive phase.
- `drive_restore(..., ctx=None)` while another Run is active → `RunContextActiveError`, a `RefusedError` → `REFUSED` (E002-S01-004), never a second Run ID.
- A port bound to a placeholder (a feature no story has supplied) called in a real Run → `UnboundAdapterError` → `FAILED` (E002-S02-012), naming the port and its supplier — never a bare `RuntimeError`.
- A second `bind_adapters` or a read of `ctx.adapters` before the bind → `AdaptersAlreadyBoundError` / `AdaptersNotBoundError` → `FAILED` (E002-S01-004; a defect).
- Target with neither its own nor an Archive `wp-config.php` → `FAILED` (`InvalidSiteDescriptorError`), nothing changed.
- SIGTERM mid-phase → the journal shows the open phase and stays blocking (no `finally: finish_run()`, ADR-0021); the lock is released by the `finally` (E002-S02-008).
