## Findings

### F1 — MEDIUM — The completeness test for ADV-5's halves uses a hand-picked prefix list, not the source of truth (rule 4)

- **kind:** guard-scope
- **Location:** `tests/unit/adapters/test_restore_runner.py:682-690`
  (`test_every_command_half_a_destroying_phase_reaches_is_checked`) and `:664-680`. The guarded
  list is `src/l3io/wp/backup/adapters/restore_runner.py:152` (`_DESTROYING_HALVES`).
- **Problem:** The test builds the expected set from `AdapterSet` field names that match
  `startswith(("site_files", "config", "restore_database", "search"))` and do not end in
  `_query`. That prefix tuple is a second hand-kept list. Its scope is whatever those four
  prefixes happen to match.
  - Suppose a later epic adds a destroying command half with another name, such as a
    relocation or `wordpress_*` command. `_DESTROYING_HALVES` and the test's set both miss it,
    and the test stays green. A not-performed snapshot is then accepted while that real half
    destroys.
  - The neighbouring test's docstring says its list is "Derived from `AdapterSet`'s fields that
    `dry_run_adapters` replaces and a destroying phase uses". But it parametrizes over
    `_DESTROYING_HALVES` itself, so it checks the list against itself.
- **Fix:** Derive the expected set from `dry_run_adapters`, the thing that actually separates
  command halves from query halves:
  `{f.name for f in fields(AdapterSet) if type(getattr(dry_run_adapters(real), f.name)).__module__ == noop.__name__}`.
  Subtract an explicit, commented exclusion set of the halves no destroying phase reaches
  (`archive_store_command`, `archive_writer`, `database_command`, `journal_command`), then
  assert the result equals `set(_DESTROYING_HALVES)`. A new command half then fails the test
  until someone decides which side it belongs on. Correct the docstring at `:668-671` to match.

### F2 — MEDIUM — `_DESTROYING` is a hand-kept phase list that no test checks

- **kind:** guard-scope
- **Location:** `src/l3io/wp/backup/adapters/restore_runner.py:142-150`, consumed at `:333`.
- **Problem:** The RT-003 re-survey runs before the first phase in a hand-enumerated frozenset
  of five phases. Nothing ties that set to `RestorePhase` / `RESTORE_PHASE_ORDER`
  (`domain/restore.py:130-141`).
  - Suppose a phase is added after SNAPSHOT (a relocation step, say) and not added to
    `_DESTROYING`. If it comes before CLEAN, it destroys before the re-survey runs.
  - `core/restore.py:663`'s `_FILE_PHASES` is a third, overlapping hand list of the same idea.
- **Fix:** Derive the set:
  `_DESTROYING = frozenset(RESTORE_PHASE_ORDER[RESTORE_PHASE_ORDER.index(RestorePhase.SNAPSHOT) + 1:])`,
  or `frozenset(RestorePhase) - _CHECK_PHASES - {RestorePhase.SNAPSHOT}`. Alternatively, add a
  test asserting that equality, so a new phase must be classified.

### F5 — LOW — The ADV-5 check cannot see the halves the root-bound `load_database` slot uses

- **kind:** security
- **Location:** `src/l3io/wp/backup/adapters/restore_runner.py:621-626` (`_destroys`) and
  `:816-822` (`_load_dump`). `adapters/staging.py:458` reads `ports.adapters` from its own
  partial-bound `ports`.
- **Problem:**
  - `_destroys` inspects only `run.ports.adapters`. LOAD_DUMP calls the root's `load_database`
    slot, which `load_staged` binds with its own `RestorePorts` through `functools.partial`
    (`tests/integration/live_restore.py:472`).
  - Suppose a root passes no-op `ports` to `execute_restore` but a `load_database` bound to real
    ports. Then a not-performed snapshot is accepted and LOAD_DUMP really loads and cuts over.
    That is the inconsistent "Dry-Run binding wired into a real Run" that ADV-5 names. It needs
    two bindings to disagree, hence LOW.
- **Fix:** Pick one:
  - Have `execute_restore` pass `run.ports` to `load_database`, so the slot uses the
    executor's ports. This changes the E003-S01-001 slot signature to
    `(RestoreInputs, RunJournalCommand, RestorePorts)`.
  - Or record in `_destroys`' docstring that the `load_database` slot is outside its scope, and
    have E003-S02-006's root test assert that the slot's ports are `run.ports`.

### F6 — LOW — The opt-out is not guaranteed to say who opted out

- **kind:** claim
- **Location:** `src/l3io/wp/backup/adapters/restore_runner.py:359` (`opted_out_by or "unspecified"`).
  The parameter is declared at `:280` onward.
- **Problem:** The story says "logs `safety_snapshot_skipped` at WARNING with `opted_out_by`
  (the flag or the API argument)" (line 81) and "opting out is explicit and recorded" (line 29).
  `opted_out_by` is keyword-required but accepts `None`. With `SnapshotPolicy.SKIP` the WARNING
  then records `"unspecified"`, so the log no longer names what opted out. The same function
  already treats a missing `snapshot_path` as a programming error (`ValueError`), but not this
  one.
- **Fix:** In `execute_restore`, raise `ValueError` when
  `plan.snapshot is SnapshotPolicy.SKIP and not opted_out_by`, like the `snapshot_path` check
  at `:312-314`. Drop the `"unspecified"` fallback and add a unit case.

### F7 — LOW — The ADV-5 path check compares spellings, not paths, and the story's interface section contradicts the diff

- **kind:** claim / interface
- **Location:** `src/l3io/wp/backup/adapters/restore_runner.py:632`
  (`if str(result.path) != planned:`). The story is `E003-S02-003.md:71`.
- **Problem:**
  1. Path check. `BackupResult.path` comes from
     `PurePosixPath(Path(target.path).absolute())` (`cli/backup.py:513`), which drops `.`
     segments, repeated `/` and a trailing `/`. The header's `snapshot_path` is whatever string
     the root composed. If the root spells it differently (an un-normalised `--snapshot-dir`
     joined by string concatenation), every real snapshot is refused as "not the planned path".
     That fails safe but makes restores unusable. E003-S02-006 writes the root, so the contract
     should be stated here.
  2. Interface section. The story says "Files this story changes: `adapters/restore_runner.py`
     … — nothing in `cli/restore.py`, and nothing in `core/restore.py`". The diff adds
     `SnapshotFailedError`, `TargetChangedError`, `recheck_target`, `SpaceClaim`,
     `check_claims`, `SNAPSHOT_FILESYSTEM` and `RestorePlan.overrides` to `core/restore.py`,
     and `tree_bytes` to `ports/` and `adapters/site_files.py`. The BL-E003-037 paragraph
     justifies this, but the interface section was not updated. It now misstates the change set
     to E003-S02-006, which binds against it.
- **Fix:**
  1. Compare normalised paths: `if result.path != PurePosixPath(planned):`. State in
     `execute_restore`'s docstring that the header path must be absolute and normalised.
  2. Amend the story's interface-contracts bullet, with a dated note citing BL-E003-037, to
     list the `core/restore.py` and `ports/site_files.py` additions and the new
     `execute_restore` keywords `survey_target` and `opted_out_by`, which E003-S02-006 must
     supply.
